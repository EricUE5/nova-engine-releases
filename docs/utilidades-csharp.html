Esta es la versión en C# de utilidades-lua.md: las mismas herramientas, con todos los ejemplos en C#. Si quieres comparar con Lua, la guía de Lua tiene los mismos apartados en el mismo orden.

Herramientas para programar juegos en C# sin repetir código: Gameplay Tags (etiquetas jerárquicas), interfaces (contratos que cumplen varios scripts), eventos, temporizadores con mango y pools de objetos (también de objetos de red).

Todo funciona igual en el editor, en NovaGame.exe y en NovaServer.exe, y tiene su autocompletado y su documentación en el editor de scripts integrado y en VS Code, Visual Studio o Rider (scripts-csharp.md). Lo que en C# se escribe distinto que en Lua está en cada apartado; lo que todavía no hay en C# se dice donde toca y en csharp-paridad.md.

1. Gameplay Tags: etiquetas jerárquicas#

Una etiqueta de juego es un nombre con partes separadas por puntos: Estado.Herido, Objeto.Botin.Oro, Arma.Pistola. Objeto.Botin.Oro es hija de Objeto.Botin, que es hija de Objeto. Preguntar por una etiqueta encaja con ella y con todas sus hijas:

C#
entidad.HasTag("Objeto.Botin");      // true si tiene Objeto.Botin, Objeto.Botin.Oro, Objeto.Botin.Plata...
entidad.HasTagExact("Objeto.Botin"); // solo Objeto.Botin
Tags.Matches("Objeto.Botin.Oro", "Objeto.Botin"); // true

Se compara por partes: Objeto.Bot no encaja con Objeto.Botin.

Son las etiquetas de siempre#

Las etiquetas de juego son las del componente Etiquetas (Tags) que ya usabas con Scene.FindByTag. Una etiqueta sin puntos ("Enemigo") funciona exactamente igual que antes. Lo que cambia:

  • entidad.HasTag("X") también es true si la entidad tiene una hija de X (X.Algo). Con etiquetas sin puntos no cambia nada.
  • Scene.FindByTag y Scene.FindAllByTag siguen siendo exactas (como siempre). Las jerárquicas son Scene.FindWithTag y Scene.FindAllWithTag.
  • Las IA, los decals y la vegetación siguen comparando sus etiquetas exactas.

Declararlas en el proyecto#

En Ventana > Scripts > Etiquetas de juego se ve el árbol de las etiquetas del proyecto. Se guardan en assets/etiquetas.json (va con el juego publicado). Es la misma ventana para Lua y para C#:

  • + Etiqueta añade una en la raíz; + Hija, una dentro de la elegida.
  • Renombrar enseña antes en qué escenas, prefabs y scripts se usa (y cuántas veces). Con Cambiar también sus usos se cambian a la vez en esos ficheros (dentro de comillas en los scripts) y en la escena abierta, con deshacer.
  • Borrar quita la etiqueta y sus hijas del proyecto. Los usos no se tocan: siguen funcionando en los scripts, pero ya no salen en el selector.
  • Cada etiqueta puede llevar un comentario (para qué sirve), que sale al pasar el ratón.

Declararlas no es obligatorio: un script puede usar cualquier nombre válido. Las declaradas salen en el selector del Inspector y viajan más cortas por la red. (El autocompletado de las etiquetas dentro de las comillas mientras escribes, HasTag(", de momento es solo de Lua.)

En el Inspector#

El componente Etiquetas se ve como «chips» (clic para quitar una) y un botón + con el árbol de las del proyecto (con buscador) y una caja para escribir otra. Una etiqueta que no está declarada se ve en amarillo. Todo tiene deshacer (Ctrl+Z).

Campos de etiquetas (TagSet)#

Un campo TagSet es lo que en Lua es un campo Tags(): un conjunto de etiquetas que se edita con chips en el Inspector y se guarda con la escena. Sus preguntas son jerárquicas (Estado.Has("Estado") encaja con Estado.Vivo) y se responden en C#, sin llamar al motor; lo que le cambies se guarda en el campo al terminar la llamada:

C#
using Nova;

public class EstadosConCampos : Script
{
    public TagSet Estado = new("Estado.Vivo");
    [Tooltip("De lo que es inmune (p. ej. Estado.Envenenado)")]
    public TagSet Inmune = new(); // se rellena en el Inspector

    public void Herir(float cantidad)
    {
        if (Estado.HasAny("Estado.Muerto", "Estado.Invulnerable"))
            return;
        Estado.Add("Estado.Herido");
        if (cantidad > 50)
        {
            Estado.Remove("Estado.Vivo", "Estado.Herido");
            Estado.Add("Estado.Muerto");
        }
    }

    public bool Envenenar() => !Inmune.Has("Estado.Envenenado") && Estado.Add("Estado.Envenenado");
}

TagSet: Has, HasExact, HasAny(...), HasAll(...), Add(...) y Remove(...) (true si cambió algo), Clear(), GetAll(), Count y Copy(), con strings.

Contenedores de etiquetas (TagContainer)#

Un TagContainer es el conjunto de etiquetas del motor, con las mismas preguntas: es lo que devuelve e.GetTags() (las etiquetas de la entidad) y se crea suelto con Tags.Container(...) (o Tags.New(...)) dentro de Awake o Start (no en el inicializador del campo: ahí todavía no se puede usar la API). Para un campo del Inspector, TagSet (arriba).

C#
using Nova;

// Estados con etiquetas: un solo sitio con todo lo que le pasa al jugador
public class EstadosDelJugador : Script
{
    [Tooltip("Etiquetas de las que es inmune, separadas por comas (p. ej. Estado.Envenenado)")]
    public string Inmune = "";

    TagContainer _estado;
    TagContainer _inmune;

    void Awake()
    {
        _estado = Tags.Container("Estado.Vivo");
        _inmune = Tags.Container(LuaValue.From(Inmune.Split(',', System.StringSplitOptions.RemoveEmptyEntries | System.StringSplitOptions.TrimEntries)));
    }

    public void Herir(float cantidad)
    {
        if (_estado.HasAny(LuaValue.From(new[] { "Estado.Muerto", "Estado.Invulnerable" })))
            return;
        _estado.Add("Estado.Herido");
        if (cantidad > 50)
        {
            _estado.Remove(LuaValue.From(new[] { "Estado.Vivo", "Estado.Herido" }));
            _estado.Add("Estado.Muerto");
        }
    }

    public void Envenenar()
    {
        if (_inmune.Has("Estado.Envenenado"))
            return; // inmune
        _estado.Add("Estado.Envenenado");
        // Las etiquetas de la entidad (componente Etiquetas) también: se replican si tiene Identidad de red
        Entity.AddTag("Estado.Envenenado");
    }

    public bool PuedeCorrer() => _estado.Has("Estado.Vivo") && !_estado.Has("Estado.Herido");
}

Donde la API acepta «una etiqueta o una lista» (HasAny, HasAll, Add, Remove, Tags.Container), el parámetro es un LuaValue: un string vale tal cual, una lista se pasa con LuaValue.From(new[] { "A", "B" }) (o una List<string>), y otro TagContainer también vale.

TagContainer Qué hace
c.Has(etiqueta) Alguna encaja (jerárquico)
c.HasExact(etiqueta) Tiene exactamente esa
c.HasAny(lista) / c.HasAll(lista) Encaja con alguna / con todas (jerárquico). La lista puede ser una etiqueta, una lista u otro contenedor
c.Add(...) / c.Remove(...) Añade las que falten / quita esas (exactas). true si cambió algo
c.Clear(), c.GetAll(), c.Count(), c.Copy() Vaciar, List<string> con las etiquetas, cuántas, copia suelta

En las entidades#

Entity Qué hace
e.HasTag(t) Tiene t o una hija suya
e.HasTagExact(t) Tiene exactamente t
e.HasAnyTag(lista) / e.HasAllTags(lista) Alguna / todas (jerárquico)
e.AddTag(t) / e.RemoveTag(t) Como siempre
e.GetTags() Sus etiquetas como TagContainer unido a la entidad (e.GetTags().Add("X") cambia la entidad)
e.Tags Sus etiquetas como List<string>; se puede asignar una lista nueva (e.Tags = new List<string> { ... })
Scene.FindAllWithTag(t) / Scene.FindWithTag(t) Las entidades con t o una hija (jerárquico)

Y en la tabla Tags: Tags.Matches(etiqueta, consulta), Tags.IsValid(nombre), Tags.Exists(nombre) (declarada en el proyecto), Tags.Parent(etiqueta) y Tags.All() (las del proyecto).

En red#

Las etiquetas del componente Etiquetas de una entidad con Identidad de red se replican: lo que el servidor añade o quita (con AddTag, RemoveTag, GetTags(), e.Tags = ... o desde C++) llega a todos los clientes. Las del proyecto viajan por su número (#3) y las demás por su nombre; caben unos 256 bytes por entidad (de sobra para decenas de etiquetas del proyecto). Un TagContainer suelto (como _estado del ejemplo) no se replica: si los clientes lo necesitan, usa las etiquetas de la entidad o una tabla replicada (scripts-csharp.md).

2. Interfaces#

Una interfaz es un contrato: una lista de funciones. Varios scripts distintos la cumplen y el que llama no necesita saber cuál es. Sirve para «cualquier cosa que se pueda recoger», «cualquier cosa que reciba daño»...

En C# una interfaz es una interface de C#, con sus tipos: el compilador comprueba que el script tiene todas sus funciones, con los parámetros y lo que devuelven. Es la diferencia más grande con Lua, donde se declara con Interface(...) y el motor avisa al cargar el script.

Declarar e implementar#

La interfaz va en su propio fichero de scripts/ (todos los .cs se compilan juntos, así que la ven todos los scripts sin require). En el mismo fichero va un pequeño registro para encontrarla en una entidad (ver el apartado siguiente):

C#
// scripts/IRecogible.cs: lo que tiene que tener todo lo que se puede recoger
using Nova;
using System.Collections.Generic;

public interface IRecogible
{
    int AlCoger(Entity jugador);
    string Descripcion();
}

// Qué script de cada entidad se puede recoger: lo rellenan los propios scripts (Awake y OnDestroy)
public static class Recogibles
{
    static readonly Dictionary<Entity, IRecogible> s_deLaEntidad = new();

    public static void Registrar(Entity e, IRecogible r) => s_deLaEntidad[e] = r;
    public static void Quitar(Entity e) => s_deLaEntidad.Remove(e);
    public static IRecogible De(Entity e) => e != null && s_deLaEntidad.TryGetValue(e, out IRecogible r) ? r : null;
}

El script dice que la implementa en su declaración (: Script, IRecogible) y se apunta en el registro:

C#
using Nova;

public class BotinOro : Script, IRecogible
{
    public int Valor = 250;

    void Awake() => Recogibles.Registrar(Entity, this);
    void OnDestroy() => Recogibles.Quitar(Entity);

    public int AlCoger(Entity jugador)
    {
        Log.Info(jugador.Name + " recoge oro");
        Destroy();
        return Valor;
    }

    public string Descripcion() => "Lingote de oro (" + Valor + ")";
}

Si al script le falta una función (o la tiene con otros tipos), no compila: al guardar sale el error con el fichero y la línea, en la Consola y en Problemas (error CS0535: 'BotinOro' no implementa el miembro de interfaz 'IRecogible.Descripcion()'), y el juego sigue con la versión anterior de los scripts.

Llamar sin saber qué script es#

C#
using Nova;

// El jugador recoge lo que toca, sea lo que sea (oro, armas, llaves...)
public class RecolectorBotin : Script
{
    public int Total;

    void OnTriggerEnter(Entity otra)
    {
        IRecogible recogible = Recogibles.De(otra);
        if (recogible == null)
            return;
        // Una llamada normal de C#: devuelve lo que devuelva la función del script que sea
        Total += recogible.AlCoger(Entity);
    }

    public void Mirar(Entity otra)
    {
        IRecogible recogible = Recogibles.De(otra);
        if (recogible != null)
            Log.Info("Ves: " + recogible.Descripcion());
    }
}

El registro es C# puro (llamadas con tipos, sin pasar por el motor). Como todo lo static, se vacía al recargar los scripts con el juego en marcha (los objetos que ya existen no vuelven a pasar por Awake): para probarlo después de un cambio, vuelve a pulsar Jugar.

Que el motor (y Lua) la vean: [Interface] e [Implements]#

Con [Interface("Nombre")] encima, una interface de C# es también una interfaz del motor (la de Interface("Nombre", {...}) de Lua, con sus métodos como funciones): los scripts C# que la implementan los encuentran e.Implements, e.GetInterface e Interfaces.Call, desde C# y desde Lua, sin registro:

C#
using Nova;

[Interface("Vendible")]
public interface IVendible
{
    int Precio();
}

public class Joya : Script, IVendible
{
    public int Valor = 900;
    public int Precio() => Valor;
}
C#
// Sin saber qué script es (en Lua: Interfaces.Call(otra, "Vendible", "Precio"))
LuaValue[] precio = Interfaces.Call(otra, "Vendible", "Precio");

Para una interfaz declarada en Lua (return Interface("Recogible", { "AlCoger", "Descripcion" })), el script C# dice que la cumple con [Implements("Recogible")] encima de su clase (como Clase:Implements(...)), y tiene que tener sus funciones como métodos (el motor avisa al cargarlo si le falta alguna).

Con scripts Lua en el mismo proyecto#

Las interfaces del motor (las de Lua, Interface("Recogible", { ... })) también se usan desde C#: un script C# puede preguntar y llamar a los scripts Lua de una entidad que las implementan.

C#
// Una entidad con un script Lua que hace BotinOro:Implements(Recogible)
if (otra.Implements("Recogible"))
{
    LuaValue[] devuelto = Interfaces.Call(otra, "Recogible", "AlCoger", Entity);
    Total += devuelto.Length > 0 ? devuelto[0].AsInt() : 0;
}
Lua C# Qué hace
Interface(nombre?, { funciones }) public interface IRecogible { ... } Declara el contrato (en C#, con tipos y comprobado al compilar). Interface(...) también existe en C#, para declarar una interfaz que cumplan scripts Lua
Clase:Implements(interfaz) class BotinOro : Script, IRecogible (con [Interface] en la interface, o [Implements("Recogible")] en la clase para una de Lua) La clase la cumple (si le falta algo, no compila)
e:Implements(interfaz) e.Implements("Recogible") Algún script de la entidad implementa esa interfaz del motor (Lua, o C# con [Interface]/[Implements])
Interfaces.Call(e, interfaz, "Funcion", ...) Interfaces.Call(e, "Recogible", "Funcion", ...) La función del primer script que la implementa; devuelve un LuaValue[]
Interfaces.CallAll(e, interfaz, "Funcion", ...) Interfaces.CallAll(...) En todos los scripts que la implementan; devuelve cuántos
Interfaces.Get(nombre), interfaz:IsImplementedBy(e) Interfaces.Get("Recogible") (un InterfaceInfo: Name, Functions), info.IsImplementedBy(e) La interfaz del motor registrada con ese nombre

En red funciona como cualquier llamada: si la función que llamas a través de la interfaz es [Server] o [Multicast], viaja por la red como siempre.

3. Eventos en el Inspector y por código#

Un evento es una lista de funciones que se llaman a la vez con Invoke(...). Un campo Event (el Event() de Lua) es además una lista de enlaces que se rellena en el Inspector, sin código («entidad + script + función (+ un argumento)»): quien monta la escena conecta el evento sin tocar el código. La función de un enlace puede ser de un script C# o de uno Lua.

Paso a paso: una puerta que enciende una alarma#

La puerta tiene dos eventos (AlAbrir y AlCerrar) y los lanza al abrirse y al cerrarse. Se declaran sin new: el motor une cada campo a su evento al crear el script.

C#
using Nova;

public class PuertaConEvento : Script
{
    [Tooltip("Lo que pasa al abrirla (rellénalo en el Inspector)")]
    public Event AlAbrir;
    [Hide]
    public Event AlCerrar; // solo por código: no sale en el Inspector
    public bool Abierta;

    public void Abrir(Entity quien)
    {
        if (Abierta)
            return;
        Abierta = true;
        AlAbrir.Invoke(quien); // llama a los enlaces del Inspector y a las suscripciones
    }

    public void Cerrar()
    {
        Abierta = false;
        AlCerrar.Invoke();
    }
}
C#
using Nova;

public class LuzDeAlarma : Script
{
    public void Encender(Entity quien)
    {
        Log.Info("¡Alarma! " + (quien != null ? quien.Name : "alguien") + " ha abierto la puerta");
    }

    public void Parpadear(int veces)
    {
        Log.Info("Parpadea " + veces + " veces");
    }
}
  1. Pon PuertaConEvento en la puerta y LuzDeAlarma en la luz.
  2. En el Inspector de la puerta, el campo Al Abrir es una lista: pulsa +.
  3. En el enlace nuevo, arrastra la luz desde la Jerarquía a Entidad; Script, LuzDeAlarma; Función, Encender (recibe los argumentos de Invoke: aquí, quien). Un segundo enlace a Parpadear con Argumento 3 recibe solo ese valor.
  4. Pulsa Jugar: cuando algo llame a Abrir de la puerta, la luz escribe «¡Alarma!» en la Consola.

Las mismas puertas y luces valen mezcladas con Lua: una puerta Lua (alAbrir = Event()) puede enlazar con Encender de la luz C#, y una puerta C# con una función de un script Lua.

Suscribirse por código#

Connect recibe los argumentos de Invoke como LuaValue[] y devuelve la conexión:

C#
EventConnection conexion = puerta.GetScript<PuertaConEvento>().AlAbrir.Connect(args =>
{
    Log.Info("se abrió");
});
conexion.Disconnect(); // deja de recibirlo

El evento de un script Lua se lee de su campo y se usa igual:

C#
ScriptEvent alAbrir = puerta.GetScript("PuertaConEvento")?.Get("alAbrir").As<ScriptEvent>();
alAbrir?.Connect(args => Log.Info("se abrió la puerta de Lua"));
Event (y ScriptEvent) Qué hace
ev.Invoke(...) Llama a las suscripciones y después a los enlaces del Inspector. Devuelve cuántas funciones se llamaron
ev.Connect(args => ...), ev.Connect((Entity quien) => ...) La función en cada Invoke (args es un LuaValue[]; con el tipo del primer argumento, ese valor). Devuelve una EventConnection con Disconnect() e IsConnected()
ev.Once(args => ...) Como Connect, solo la próxima vez
ev.DisconnectAll() Quita las suscripciones por código (los enlaces del Inspector se quedan)
ev.ListenerCount (ListenerCount() en ScriptEvent) Suscripciones más enlaces
Event.New() Un evento suelto, sin Inspector (dentro de Awake o Start); un campo public Event X; no lo necesita

Una suscripción se quita sola al destruirse quien se suscribió o el dueño del evento: nunca llama a un script que ya no existe. Una excepción dentro de una función suscrita se escribe en la Consola y las demás se siguen llamando.

Si el evento es solo de C# a C# y no te hacen falta los enlaces de Lua ni la desconexión automática, un event de C# (public event System.Action<Entity> AlAbrir;) también vale; acuérdate entonces de quitar las suscripciones en OnDestroy (puerta.AlAbrir -= ...).

Con prefabs#

Los enlaces de los eventos de Lua guardan la entidad por su identificador, como los campos Entity. Dentro de un prefab (la puerta con su luz hija), cada instancia enlaza con su luz: al instanciar, las referencias internas pasan a las entidades nuevas. Lo mismo vale para un campo Entity de C# como Puerta: dentro del prefab apunta a la puerta de esa instancia. Un enlace o un campo a una entidad de la escena (fuera del prefab) se queda apuntando a esa entidad.

En red: dónde se lanza#

Invoke se ejecuta en la máquina que lo llama, como una llamada normal: no envía nada por sí mismo. Lo normal en un juego en red:

  • Lanza el evento en el servidor (que es quien decide si la puerta se abre).
  • Las funciones que tienen que verse en todos (la luz, el sonido) llévalas con [Multicast]: una función [Multicast] llamada desde la suscripción llega a todos y una [Server] llamada desde un cliente viaja al servidor, igual que si la llamaras desde cualquier otro sitio (scripts-csharp.md). Así funciona en anfitrión y cliente y en servidor dedicado.
  • Lo que solo es visual y local (un efecto en la pantalla de un jugador) puede lanzarse en el cliente.

4. Temporizadores con mango#

Timer es un temporizador que se puede parar, seguir, consultar y cancelar desde fuera:

C#
using Nova;

public class VenenoTemporizado : Script
{
    public float Vida = 100;

    Timer _veneno;
    Timer _cura;

    public void Envenenar()
    {
        if (_veneno != null && _veneno.IsActive())
            return;
        // Cada 0,5 s quita 5 de vida; a los 4 s se cura solo
        _veneno = Timer.Every(0.5f, t => Vida -= 5);
        _cura = Timer.After(4, t => _veneno.Cancel());
    }

    public void Pausar(bool pausado)
    {
        foreach (Timer t in new[] { _veneno, _cura })
        {
            if (t == null)
                continue;
            if (pausado) t.Pause(); else t.Resume();
        }
    }

    void OnGUI()
    {
        if (_cura != null && _cura.IsActive())
        {
            GUI.Begin("Veneno", 20, 20);
            GUI.Text($"Curación en {_cura.Remaining():0.0} s");
            GUI.End();
        }
    }
}
Función Qué hace
Timer.After(segundos, t => ..., opciones?) Llama a la función una vez (también Timer.Create, que es el Timer(...) de Lua)
Timer.Every(segundos, t => ..., opciones?) La llama cada tantos segundos
t.Cancel() Lo cancela (true si seguía activo)
t.Pause() / t.Resume() Lo para guardando lo que le falta / sigue desde ahí
t.Remaining() Segundos que faltan para la próxima llamada
t.IsActive() / t.IsPaused() Si va a volver a llamar (en pausa también) / si está en pausa
t.SetTimeScale(x) / t.GetTimeScale() Escala propia: 2 el doble de rápido, 0 congelado

Opciones (TimerOptions): new TimerOptions { Unscaled = true } sigue con el juego en pausa (Time.TimeScale = 0; menús), { TimeScale = 2 } es la escala propia y { Owner = entidad } lo ata a otra entidad (se cancela si se destruye).

  • Se cancela solo al destruirse el script que lo crea. A diferencia de Tasks.*, no se cancela al desactivar el script.
  • La función se llama directamente y recibe el propio Timer (t). Para esperar dentro de una secuencia, mejor un método async con await Wait(segundos) (scripts-csharp.md).
  • SetTimeout, await Wait(...) y Tasks.* no cambian: Timer va sobre el mismo planificador.

5. Pools de objetos#

Crear y destruir entidades cuesta (instanciar el prefab, Awake, cuerpos de físicas...). Un pool las reutiliza: al «destruir» una, se desactiva y se guarda para la siguiente.

C#
using Nova;

// En el prefab de la bala: se reinicia al salir del pool
public class BalaReutilizable : Script
{
    public float Velocidad = 40;

    float _vida;

    void OnPoolGet()
    {
        _vida = 0;
        Physics.SetVelocity(Entity, Transform.Forward * Velocidad);
    }

    void OnPoolRelease()
    {
        // lo que haya que limpiar (sus tareas de Tasks.* y sus tweens se cancelan solos)
    }

    void OnCollisionEnter(Collision c)
    {
        Pool.ReleaseStatic(Entity); // vuelve al pool en lugar de destruirse
    }
}
C#
using Nova;

public class ArmaConPool : Script
{
    [AssetType("Prefab"), Tooltip("Prefab de la bala (con BalaReutilizable y, si quieres, el componente Devolver al pool)")]
    public Asset Bala;

    Pool _pool;

    void Start()
    {
        if (Bala != null)
            _pool = Pool.Create(Bala, new PoolSettings { Initial = 20, Max = 200 });
    }

    void Update(float dt)
    {
        if (_pool != null && Input.WasActionPressed("Disparar"))
        {
            Vec3 canon = Entity.Position + Transform.Forward;
            _pool.Get(canon, Entity.Rotation);
        }
    }
}
  • Pool.Create(prefab, new PoolSettings { Initial = 20, Max = 200 }) crea el pool con 20 ya creadas (desactivadas). Max es cuántas libres guarda como mucho (las demás se destruyen al devolverlas). Es lo mismo que Pool.Create(prefab, 20, new PoolOptions { MaxSize = 200 }).
  • pool.Get(posicion, rotacion) saca una (o crea otra si no queda ninguna), con su cuerpo parado en el sitio nuevo, y llama a OnPoolGet() de sus scripts y de los de sus hijos.
  • pool.Release(e) o Pool.ReleaseStatic(e, segundos?) (la Pool.Release de Lua; en C# lleva Static porque el pool tiene un método Release con los mismos parámetros) llama a OnPoolRelease(), cancela sus tareas y tweens, la desactiva y la guarda. Una devolución con espera solo vale para esa salida: si la bala se devolvió y se volvió a sacar antes, no la devuelve.
  • El componente Devolver al pool (PoolReturn, en «Scripts») devuelve la entidad sola pasados N segundos desde que sale: perfecto para impactos, casquillos y balas perdidas.
  • Más: pool.Prewarm(n), pool.CountActive(), pool.CountInactive(), pool.Clear(), Pool.IsPooled(e) (nativas-juego.md).

En red: pools de objetos de red#

Con un prefab con Identidad de red, el pool es de objetos de red y se crea en el servidor (en un cliente es un error que lo dice):

  • Las entidades se crean una vez con Spawn (en el servidor y en todos los clientes) y después solo se activan y desactivan: el estado activo se replica, así que los clientes las ven aparecer y desaparecer sin crear ni destruir entidades de red.
  • Al sacarla hay un teletransporte de red: los clientes no ven el salto interpolado desde donde se devolvió.
  • OnPoolGet y OnPoolRelease se llaman en el servidor. Si los clientes necesitan reiniciar algo, usa campos [Replicated].
  • Sin red (o jugando solo) funciona como un pool local.

Cuánto se gana#

Lo medido en las pruebas del motor con 1000 balas está en utilidades-lua.md: crear y destruir cuesta unas 33 veces más que sacar y devolver de un pool (≈ 195 ms frente a ≈ 6 ms en local), y un pool de red evita las 2000 altas y bajas de entidades de red en los clientes. Las libres de un pool de red siguen siendo entidades de red (desactivadas) que la red recorre en cada envío: dimensiona los pools de red a lo que de verdad se usa a la vez (con Max), y para balas que solo se ven, usa un pool local en cada máquina (el servidor decide los impactos con rayos). Desde C# cuesta lo mismo: el trabajo lo hace el motor.
