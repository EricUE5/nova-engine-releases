Este documento explica cómo se organizan las escenas de Nova Engine: entidades, jerarquía, el Transform, todos los componentes del motor con sus campos, cómo se usan desde los scripts Lua, el formato JSON de los ficheros .scene y cómo guardar datos propios en las entidades con los campos de un script.

Entidades#

Una escena es una lista de entidades. Cada entidad tiene:

  • Un UUID estable de 64 bits, que es lo que se guarda en los ficheros y lo que usan las referencias entre entidades (en Lua, entidad.id, un texto).
  • Siempre, un nombre (el que se ve en la Jerarquía) y un Transform.
  • Los componentes que le añadas (luces, mallas, cuerpos rígidos, sonidos, scripts...).
  • Un estado activo. Una entidad inactiva, o con un ancestro inactivo, no se dibuja ni ejecuta scripts ni animaciones.

En un script Lua, la entidad del script es self.entity y cualquier otra se busca con Scene.Find("Puerta"), Scene.FindByTag("Enemigo") o un campo Entity() que se elige en el Inspector. Una entidad es un valor Entity con sus datos y funciones:

entidad. Qué es
name, active Nombre y si está activa (se pueden cambiar)
activeInHierarchy Activa ella y todos sus padres
id UUID (texto); Scene.FindById(id) la vuelve a encontrar
parent, children Padre (se puede cambiar) e hijos
position, rotation Posición y rotación en el mundo (se pueden cambiar)
transform Su Transform (local: ver abajo)
GetComponent(n), AddComponent(n), HasComponent(n), RemoveComponent(n) Componentes por su nombre ("PointLight", "RigidBody"...)
GetScript(n), AddScript(n) Sus scripts, Lua o C++ ("Puerta")
SetParent(padre, mantenerMundo?), FindChild(nombre) Cambiar de padre; un descendiente por su nombre o su ruta ("Puerta/Bisagra")
Destroy(segundos?), IsValid() Destruirla con todos sus hijos (al final del frame o con espera); si sigue existiendo

La API completa de la escena (Scene.Create, Scene.Instantiate, Scene.FindAllWithComponent, cambiar de escena...) está en scripts-lua.md.

Jerarquía y Transform#

Las entidades forman un árbol. El Transform de una entidad es local respecto a su padre: la matriz de mundo es padre * local. Tiene position (metros), rotation (un Quat; el Inspector la muestra en grados de Euler) y scale. Desde un script:

  • self.transform.position, rotation y scale son los locales; self.entity.position y rotation (o self.transform.worldPosition y worldRotation), los del mundo.
  • self.transform.forward, right y up son las direcciones de la entidad en el mundo (forward es −Z).
  • Los vectores son valores: self.transform.position.x = 1 no cambia nada. Asigna el vector entero.
Lua
-- Crea una fila de farolas hijas de esta entidad al empezar y apaga la última al pulsar L
local Farolas = Script()

--[Range(1, 20), Int]
Farolas.cantidad = 4
--[Range(0.5, 10)]
Farolas.separacion = 3

function Farolas:Start()
    for i = 1, self.cantidad do
        local farola = Scene.Create("Farola " .. i, self.entity) -- hija de esta entidad
        farola.transform.position = Vec3.new((i - 1) * self.separacion, 2.5, 0) -- local: respecto al padre
        farola:AddTag("Farola")
        local luz = farola:AddComponent("PointLight")
        luz.color = Color.new(1, 0.85, 0.6)
        luz.intensity = 12
        luz.range = 6
    end
end

function Farolas:Update(dt: number)
    if Input.WasKeyPressed("L") then
        local ultima = self.entity:FindChild("Farola " .. self.cantidad)
        if ultima then
            ultima.active = not ultima.active
        end
        Log.Info("Farolas en la escena:", #Scene.FindAllByTag("Farola"))
    end
end

return Farolas

Componentes del motor#

Entre paréntesis, el nombre que muestra el Inspector. Los componentes Name, PrefabInstance y UnknownComponents no aparecen en el menú Añadir componente.

Transform (Transform)#

Campo Tipo Por defecto Notas
position (Posición) Vec3 0, 0, 0 Local respecto al padre
rotation (Rotación) Quat identidad Se edita en grados de Euler
scale (Escala) Vec3 1, 1, 1

En multijugador, la posición y la rotación (y la escala, si se marca) se replican con el componente Transform de red, no con estos campos: ver multijugador.md.

Camera (Cámara)#

La cámara mira hacia su eje -Z local.

Campo Tipo Por defecto Notas
projection (Proyección) opción Perspectiva Perspectiva u Ortográfica
fieldOfView (Campo de visión) número 60 Grados, vertical (10 a 120)
orthographicSize (Tamaño ortográfico) número 5 Media altura visible en modo ortográfico
nearClip (Plano cercano) número 0.1 Metros
farClip (Plano lejano) número 500 Metros. Si queda por delante del cercano, se dibuja con el lejano justo detrás del cercano
primary (Principal) booleano true La cámara que usa el juego. Si ninguna activa lo tiene, se usa la primera cámara activa

La cámara no tiene color de fondo ni postproceso propios: el fondo es el cielo y el postproceso (exposición, bloom, FXAA...) es del componente Entorno.

DirectionalLight (Luz direccional)#

El sol. Ilumina en la dirección -Z de la entidad. Solo se usa la primera luz direccional activa.

Campo Tipo Por defecto Notas
color color 1, 0.96, 0.9 Lineal
intensity (Intensidad) número 3 0 a 50
volumetricIntensity (Intensidad volumétrica) número 1 Cuánto ilumina la niebla con «Luz volumétrica»: rayos de sol (0 = nada)
castShadows (Proyectar sombras) booleano true
shadowDistance (Distancia de sombras) número 60 Metros que cubren las cascadas
shadowCascades (Cascadas) entero 4 1 a 4
shadowResolution (Resolución) opción 2048 256, 512, 1024, 2048 o 4096 texeles de lado por cascada (en WARP, 1024 como mucho)
shadowSoftness (Suavidad) número 1 Radio del filtro PCF en texeles (0 = bordes duros, hasta 6)
shadowBias (Sesgo de sombra) número 0.0005 Evita el "acné" de sombras (en profundidad de la cascada)
shadowNormalBias (Sesgo normal) número 0.02 Desplaza la muestra a lo largo de la normal

PointLight (Luz puntual)#

Campo Tipo Por defecto Notas
color color 1, 1, 1 Lineal
intensity (Intensidad) número 5 0 a 500
range (Alcance) número 8 Metros; la luz llega a 0 en este radio
volumetricIntensity (Intensidad volumétrica) número 1 Cuánto ilumina la niebla con «Luz volumétrica»: el halo de una farola (0 = nada)
castShadows (Proyectar sombras) booleano true La luz no atraviesa los objetos que proyectan sombra
shadowResolution (Resolución) opción 512 Texeles de lado de cada una de las 6 caras del cubo de sombras
shadowBias (Sesgo de sombra) número 1 En texeles del mapa de sombras
shadowNormalBias (Sesgo normal) número 1.5 En texeles, a lo largo de la normal
shadowSoftness (Suavidad) número 1 Radio del filtro PCF en texeles (0 = bordes duros, hasta 6)
shadowNearPlane (Plano cercano) número 0.05 Metros: lo que está más cerca de la luz no proyecta sombra

SpotLight (Foco)#

Apunta hacia el eje -Z de la entidad.

Campo Tipo Por defecto Notas
color color 1, 1, 1 Lineal
intensity (Intensidad) número 10 0 a 500
range (Alcance) número 12 Metros
innerAngle (Ángulo interior) número 20 Grados, mitad del cono, zona con intensidad completa
outerAngle (Ángulo exterior) número 30 Grados, mitad del cono, borde donde la luz llega a 0
volumetricIntensity (Intensidad volumétrica) número 1 Cuánto ilumina la niebla con «Luz volumétrica»: el cono de una linterna (0 = nada)
castShadows, shadowBias, shadowNormalBias, shadowSoftness, shadowNearPlane Como en la luz puntual
shadowResolution (Resolución) opción 1024 Texeles de lado del mapa de sombras del foco

Cómo funcionan las sombras de las luces y qué hacer si se ven rayas o huecos: ver render-y-materiales.md.

Environment (Entorno)#

Cielo, luz ambiente, niebla, postproceso y nubes volumétricas. Solo se usa el primer Entorno activo de la escena. Sus campos se explican uno a uno en render-y-materiales.md y los de la sección Nubes (cloudsEnabled, cloudCoverage...) en nubes.md. La sección Niebla y luz volumétrica (con sus preajustes) está en niebla-volumetrica.md.

FogVolume (Volumen de niebla)#

Niebla local con forma de caja, esfera o elipsoide (con la transformación de la entidad): humo en una habitación, bruma en un valle, niebla sobre un lago. Se ve con la Luz volumétrica del Entorno activa. Sus campos (shape, size, radius, density, color, edgeFalloff, noiseStrength, noiseScale, priority) se explican en niebla-volumetrica.md.

MeshRenderer (Malla)#

Dibuja una malla estática de un modelo glTF o de una primitiva del motor.

Campo Tipo Por defecto Notas
model (Modelo) asset (Model) ninguno Modelo o primitiva integrada (builtin:Cubo, builtin:Esfera...)
mesh (Malla) entero 0 Índice de la malla dentro del modelo; -1 dibuja todas con las transformaciones de sus nodos
materials (Materiales) lista de assets (Material) vacío Sustituye los materiales del modelo, uno por submalla en orden. Los huecos usan el material del modelo
castShadows (Proyecta sombras) booleano true Hace sombra al sol, a las luces puntuales y a los focos
receiveShadows (Recibe sombras) booleano true Si se desactiva, ninguna luz le hace sombra (la luz le llega igual)
visible (Visible) booleano true Desmarcado no se dibuja; la entidad, sus scripts y sus físicas siguen activos
shadowOnly (Solo sombra) booleano false Proyecta su sombra pero no se dibuja ni se puede seleccionar en la vista (con castShadows)
ownerVisibility (Visibilidad en red) opción Todos "Todos", "Solo el propietario" (brazos en primera persona) u "Oculto para el propietario" (su cuerpo: el dueño solo ve la sombra)

En el Inspector, castShadows y shadowOnly son una sola opción, Sombras: Activadas, Desactivadas o Solo sombra (ver render-y-materiales.md).

Primitivas integradas: Cubo (1 m), Esfera (radio 0,5 m), Plano (10 x 10 m), Cilindro, Cápsula y Cono.

SkinnedMeshRenderer (Malla con huesos)#

Malla con piel. Toma la pose del Animator de su propia entidad o del ancestro más cercano que lo tenga (si ese Animator usa el mismo modelo); si no, se dibuja en la pose de reposo. Se coloca con la transformación de la entidad del Animator (o con la suya propia si no hay ninguno), no con la de la entidad hija.

Campo Tipo Por defecto Notas
model (Modelo) asset (Model) ninguno
mesh (Malla) entero 0 Índice de la malla en el modelo
skin (Piel) entero 0 Índice del esqueleto (skin) en el modelo
materials (Materiales) lista de assets (Material) vacío Igual que en Malla
castShadows (Proyecta sombras) booleano true Igual que en Malla
receiveShadows (Recibe sombras) booleano true Igual que en Malla
visible (Visible) booleano true Igual que en Malla
shadowOnly (Solo sombra), ownerVisibility (Visibilidad en red) Igual que en Malla

Animator (Animador)#

Reproduce las animaciones de un modelo. Explicado a fondo en modelos-y-animaciones.md.

Campo Tipo Por defecto Notas
model (Modelo) asset (Model) ninguno De dónde salen el esqueleto y los clips
controller (Controlador) asset (AnimatorController) ninguno Opcional (.controller)
clip (Clip) texto vacío Sin controlador: clip a reproducir (vacío = el primero)
speed (Velocidad) número 1 Multiplicador de velocidad
loop (Bucle) booleano true Sin controlador: repetir el clip
playInEditor (Previsualizar) booleano true Animar también en el editor sin pulsar Play
applyRootMotion (Root motion) booleano false El desplazamiento horizontal del hueso raíz mueve la entidad al jugar
rootMotionBone (Hueso raíz) texto vacío Hueso del root motion (vacío = el primero del esqueleto)

BoneAttachment (Enganche a hueso)#

La entidad sigue un hueso (o un nodo vacío o un socket) del Animador de su antepasado más cercano o de la entidad de Animador. Su Transform es el desplazamiento respecto al hueso. Ver modelos-y-animaciones.md.

Campo Tipo Por defecto Notas
animator (Animador) entidad ninguna Entidad con el Animador (vacío = el antepasado más cercano que lo tenga)
bone (Hueso) texto vacío Hueso, nodo vacío o socket del modelo (el Inspector tiene la lista)
inheritScale (Heredar escala) booleano false Heredar la escala del hueso y del personaje

IK#

Cinemática inversa sobre el Animador de la misma entidad: cadenas de Apuntar (aims: nombre, activo, peso, huesos, eje que apunta, objetivo, posición del objetivo, ángulo máximo) y Extremidades (limbs: nombre, activo, peso, mano o pie, objetivo, posición del objetivo, copiar rotación, pista). Ver modelos-y-animaciones.md.

Script (Scripts)#

Lista de scripts de la entidad: normalmente scripts Lua (scripts/*.luau, ver scripts-lua.md) y, si el proyecto los tiene, también de C++ (scripts-cpp.md). Una entidad puede tener varios. Cada script tiene su casilla de activado y sus campos, que salen en el Inspector y se guardan con la escena. Se añaden arrastrando el fichero desde Contenido a la entidad, con Añadir script o desde otro script (entidad:AddScript("Puerta")).

Leer y cambiar componentes desde un script#

GetComponent devuelve el componente con todos sus campos, con los mismos nombres que estas tablas (los de la primera columna), o nil si la entidad no lo tiene. Lo que cambies jugando tiene efecto al momento:

Lua
local camara = Camera.GetMain()
if camara then
    camara:GetComponent("Camera").fieldOfView = 40       -- zoom
end
local luz = self:GetComponent("PointLight")
if luz then
    luz.intensity = luz.intensity * 0.5                  -- números
    luz.castShadows = false                              -- booleanos
end
local malla = self:GetComponent("MeshRenderer")
if malla then
    malla.visible = false                                -- deja de dibujarse; scripts y físicas siguen
end
local proyeccion = camara and camara:GetComponent("Camera").projection -- las opciones son textos: "Perspectiva"

Los campos de tipo lista (como materials) son una copia: cambiar un elemento no cambia nada; asigna la lista entera. Algunos componentes tienen funciones extra (RigidBody:AddImpulse, Animator:SetFloat, AudioSource:Play, MeshRenderer:SetColor...): ver scripts-lua.md.

Físicas, audio y red#

Estos componentes tienen su propio documento con todos sus campos:

Los campos de estado que escriben las físicas o la red (velocidad del personaje, dueño de la entidad...) se ven en el Inspector como solo lectura y no se guardan.

Interfaz#

La categoría Interfaz del menú Añadir componente tiene los componentes del HUD y los menús: Lienzo (UiCanvas), Escalador del lienzo, Rectángulo (UI) (UiRect, que en los elementos de interfaz sustituye al Transform), Imagen, Texto, Botón, Interruptor, Deslizador, Barra de progreso, Campo de texto, Vista con desplazamiento, Desplegable, Grupo de layout, Elemento de layout, Máscara (recorte), Grupo (alfa), Pantalla y Animación de UI. Se guardan en la escena como los demás (los enums por su texto, por ejemplo "mode": "Pantalla") y se editan visualmente en el panel Interfaz. La tabla con todos sus campos está en interfaz-ui.md.

Efectos#

La categoría Efectos tiene el Sistema de partículas (ParticleSystem): fuego, humo, chispas, explosiones, lluvia... con sus módulos, sus preajustes (menú Entidad > Efectos) y la API de Lua (Play, Stop, Emit, EmitAt, Effects.Spawn). Todo está en particulas.md.

Tags (Etiquetas)#

Una lista de textos ("Enemigo", "Recogible"...) para encontrar entidades sin depender de su nombre. Desde un script: Scene.FindByTag("Enemigo"), Scene.FindAllByTag(...), entidad:HasTag(...), AddTag y RemoveTag (ver scripts-lua.md). Desde la 0.9.24 son etiquetas de juego jerárquicas (Objeto.Botin.Oro): HasTag("Objeto.Botin") encaja también con sus hijas, se eligen en el Inspector con un selector en árbol y se replican si la entidad tiene Identidad de red (ver utilidades-lua.md).

Campo Tipo Por defecto Notas
values (Etiquetas) lista de textos vacío

PrefabInstance (Instancia de prefab)#

Marca la raíz de una instancia de prefab. Tiene un solo campo, prefab (el asset del prefab, solo lectura). Ver prefabs.md.

Name y UnknownComponents#

Name guarda el nombre de la entidad (en los ficheros va en la clave "name" de la entidad). UnknownComponents es interno: conserva los datos de componentes cuyo tipo no está registrado (por ejemplo, un componente de C++ de un proyecto cuya DLL no está cargada) para no perderlos al guardar.

Formato de los ficheros .scene#

Una escena es un fichero JSON con la cabecera "nova": "scene", la versión del formato, el nombre y la lista de entidades. Las entidades van en profundidad (cada padre antes que sus hijos) y conservan el orden entre hermanos. Reglas del formato:

Elemento Cómo se escribe
id, parent UUID en 16 dígitos hexadecimales. Sin parent, la entidad es raíz
active Solo aparece si la entidad está inactiva ("active": false)
components Objeto con una clave por componente: su nombre ("PointLight", "RigidBody"...)
Vec2, Vec3, Vec4 Arrays de 2, 3 o 4 números
Quat Array [x, y, z, w]
Opciones El nombre de la opción (por ejemplo "projection": "Perspectiva")
Asset Objeto {"id": ..., "path": ...} o null. Si el id ya no existe (se perdió el .meta), se busca por path
Entidad El UUID de la entidad como texto, o null
Listas Array
Estructuras Objeto con sus campos

El componente Script tiene su propio formato: una lista de scripts con su nombre (el del fichero para los Lua), sus campos y, si está desactivado, "enabled": false. Los campos que falten toman su valor por defecto. Este es el rotador de game/sample_lua/assets/scenes/Principal.scene:

JSON
"Script": {
  "scripts": [
    {
      "type": "Rotador.luau",
      "fields": {
        "eje": [0, 1, 0],
        "gradosPorSegundo": 60
      }
    }
  ]
}

Al cargar, los campos que no aparecen en el fichero conservan el valor por defecto del tipo, y los que el tipo ya no tiene se ignoran. El lector de JSON admite comentarios de línea (// ...), útil al editar a mano.

Los prefabs (.prefab) usan el mismo formato con "nova": "prefab"; ver prefabs.md.

Datos propios: los campos de un script#

Para guardar datos propios en una entidad (la vida, el equipo, el dinero de una caja fuerte...) no hace falta un componente nuevo: un script Lua con campos hace ese papel. Sus campos salen en el Inspector, se guardan con la escena, entran en los prefabs, en el deshacer y en la edición en equipo, y con --[Replicated] viajan por la red. Todos los atributos y tipos de campo están en scripts-lua.md.

Lua
-- Puntos de vida de cualquier entidad: los demás scripts la usan con entidad:GetScript("Salud")
local Salud = Script()

--[Header("Vida")]
--[Range(0, 1000), Tooltip("Vida actual"), Replicated(onChange = "AlCambiar")]
Salud.vida = 100
--[Range(1, 1000), Display("Vida máxima")]
Salud.maxima = 100
Salud.invencible = false
Salud.equipo = Enum({ "Rojo", "Azul" }, "Rojo")
--[Color, Display("Color de la barra")]
Salud.colorBarra = Vec3.new(0.2, 0.9, 0.3)

--[Header("Al morir")]
--[Tooltip("Prefab que aparece en su lugar (opcional)")]
Salud.restos = Asset("Prefab")

-- En el servidor (o sin red): quita vida y, a cero, deja los restos y destruye la entidad
function Salud:Danar(cantidad: number)
    if self.invencible or not IsServer() then
        return
    end
    self.vida = math.max(0, self.vida - cantidad)
    if self.vida == 0 then
        if self.restos then
            Scene.Instantiate(self.restos, self.entity.position)
        end
        self:Destroy()
    end
end

function Salud:Curar()
    if IsServer() then
        self.vida = self.maxima
    end
end

-- En los clientes, cuando llega un valor nuevo de la vida (con Identidad de red)
function Salud:AlCambiar()
    Log.Info(string.format("%s tiene %d de vida", self.name, self.vida))
end

return Salud

Otro script la usa así:

Lua
local salud = golpe.entity:GetScript("Salud")
if salud then
    salud:Danar(25)
end

Componentes y sistemas en C++#

Los scripts Lua no crean tipos de componente nuevos: un script con campos hace ese papel. Si un proyecto necesita un componente de C++ de verdad (por ejemplo, para un sistema que recorre miles de entidades en cada frame), se declara con NOVA_COMPONENT y NOVA_SYSTEM en la DLL de scripts C++ del proyecto: ver scripts-cpp.md. Los componentes de C++ salen en Añadir componente y se usan desde Lua como los del motor (GetComponent("Salud")). Cómo está hecha la escena por dentro (manejadores, almacenes, reflexión) está en arquitectura.md.
