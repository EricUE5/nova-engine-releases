Herramientas para probar tu juego y ayudarte mientras lo construyes, todas desde Lua:

Herramienta Para qué Dónde
Consola y comandos Trucos y comandos de prueba: tp 0 10 0, god, dinero 500... Tecla º o F1 en el juego, la línea de comandos de la barra de estado del editor y la consola de NovaServer

Las tres ventanas (Variables de consola, Problemas y Visual Logger) están en Ventana > Depuración.

1. Consola y comandos#

Abrir la consola#

  • En el juego (NovaGame y la vista Juego del editor): tecla º (la de la izquierda del 1) o F1. Se escribe un comando y Intro. Mientras escribes salen los comandos y variables que empiezan así, con su ayuda: Tab completa, las flechas eligen sugerencia o recorren el historial y Esc cierra. La salida va con colores: verde lo que salió bien, rojo los errores, azul lo que escribiste.
  • En el editor: la línea Comando de la barra de estado (abajo). Jugando, el comando va a la partida; si no, a la escena abierta (help, cvars). La salida sale en la Consola.
  • En el servidor dedicado: la consola de texto de NovaServer.exe acepta los mismos comandos y variables (además de status, kick, ban...); comandos los lista.

Las teclas se cambian en Ajustes del proyecto > Consola («Teclas que la abren»: º, F1...F12, Insert).

Comandos del motor#

Comando Qué hace Dónde se ejecuta
help [comando] Lista los comandos (o la ayuda de uno) Aquí
cvars [filtro] Lista las variables de consola con su valor Aquí
fps Enseña u oculta los fotogramas por segundo (arriba a la izquierda) Aquí
stat red / stat fps / stat nada Estadísticas de red (como F3), FPS, o quitarlas Aquí
tp x y z [jugador] Teletransporta tu personaje (o el de otro jugador) Servidor · admin · truco
noclip [jugador] [si/no] Marca el noclip del jugador (lo aplica tu juego, ver abajo) Servidor · admin · truco
god [jugador] [si/no] Marca el modo dios del jugador (lo aplica tu juego) Servidor · admin · truco
timescale [escala] Velocidad del tiempo: 1 normal, 0.5 cámara lenta, 0 congelado (hasta 10) Servidor · admin · truco
quit Sale del juego (en el editor, deja de jugar) Aquí
admin <jugador> [si/no] Da o quita permisos de administrador en esta partida Servidor · admin

noclip y god no saben cómo se mueve ni cómo recibe daño tu juego: el motor apunta quién los tiene y avisa a tus scripts. Úsalo así:

Lua
-- En el script que quita vida
function Vida:Herir(cantidad)
    if Console.IsGod(self.dueno) then return end -- modo dios: no le pasa nada
    self.vida -= cantidad
end

-- O al momento, con el evento (jugador, activado)
AddEventHandler("consoleNoclip", function(jugador, activado)
    print("noclip de", jugador, activado)
end)

Tus comandos: RegisterCommand#

Lua
RegisterCommand("dinero", function(jugador, args, linea)
    local cantidad = tonumber(args[1]) or 100
    Dinero.Dar(jugador, cantidad)
    return "Dinero dado: " .. cantidad -- lo que devuelvas sale en la consola de quien lo escribió
end, { server = true, admin = false, help = "Da dinero", usage = "dinero <cantidad>" })
  • La función recibe el jugador que lo escribió (su id; 0 si es la consola del servidor o sin red), las palabras (args; un texto entre comillas va entero: aviso "hola a todos") y la línea entera.
  • Lo que devuelva (un texto o una lista de textos) sale en su consola, también por la red. Dentro del comando, Console.Print(texto, "success" | "warning" | "error") escribe con color. Un error(...) sale en rojo sin romper nada.
  • Opciones (las de antes en español, servidor, ayuda, uso y truco, siguen valiendo con un aviso de obsoleto):
Opción Qué hace
server = true Se ejecuta en el servidor: desde un cliente se pide por la red y la respuesta vuelve. En el anfitrión, jugando solo o en el servidor, ahí mismo
admin = true Solo el anfitrión (o la consola del servidor) y los administradores
cheat = true Es un truco: en el juego publicado solo funciona si el proyecto lo permite
help = "...", usage = "..." Lo que sale en el autocompletado y en help

Regístralo en Awake (o al cargar el script). Si el script se recarga, el comando se sustituye; al parar la partida se quita. Desde un script también puedes ejecutar una línea como si se escribiera: ExecuteCommand("timescale 0.5").

En red: quién ejecuta qué#

  • Un comando de cliente (sin server = true) se ejecuta en la máquina que lo escribe.
  • Uno de servidor se pide al servidor, que mira los permisos, lo ejecuta con jugador = quien lo pidió y le devuelve la salida. Si el cliente no conoce un comando (porque el servidor lo registra solo con if IsServer()), también lo pregunta: el servidor dice si existe.
  • Permisos: los comandos admin = true (y cambiar una variable replicada) solo los pueden el anfitrión y los administradores: los de Ajustes del proyecto > Consola > Administradores (nombre de jugador, IP o steam:<id>), los que se den en la partida con el comando admin <id> o, desde un script del servidor, Console.SetAdmin(jugador, true) (Console.IsAdmin(jugador) lo consulta).
  • Trucos en el juego publicado: en el editor y desde el código fuente siempre funcionan. En el juego publicado, solo si marcas Ajustes del proyecto > Consola > Trucos en el juego publicado. Con Consola en el juego publicado desmarcado, la tecla no abre la consola en el juego publicado (NovaServer sigue aceptando los comandos).

En project.nova es la sección "consola":

JSON
"consola": { "teclas": ["º", "F1"], "trucosPublicado": false, "consolaPublicado": true, "admins": ["Ana", "steam:7656119..."] }

2. Variables de consola (CVars)#

Un número (o un booleano o un texto) del juego que se puede cambiar en vivo desde la consola, sin tocar el código:

Lua
local velZombi = CVar("zombis.velocidad", 2.5, { help = "Velocidad de los zombis", replicated = true, min = 0, max = 10 })

function Zombi:Update(dt)
    local agente = self:GetComponent("NavAgent")
    agente.speed = velZombi:Get()
end

Desde la consola: zombis.velocidad 4 la cambia y zombis.velocidad dice cuánto vale (con su ayuda).

Opción Qué hace
help = "..." Sale en el autocompletado, en cvars y en la ventana
min, max, integer = true Límites (y redondeo) de una numérica
replicated = true La fija el servidor y llega a todos (también a quien entra después). Desde un cliente, cambiarla es como un comando de admin
persist = true Se recuerda en las preferencias de esta máquina (cvars.json en la carpeta de guardado del juego)
cheat = true Cambiarla es un truco (ver arriba)
  • v:Get() da el valor; v:Set(valor) lo cambia (devuelve false si no se pudo, por ejemplo una replicada en un cliente); v:Reset() vuelve al inicial.
  • v:OnChanged(function(nuevo, viejo) ... end) avisa de cada cambio (también del que llega del servidor).
  • El tipo sale del valor inicial: CVar("debug.rayos", false) es un sí/no (debug.rayos si, 1, on...).
  • Declarar otra vez la misma (otro script, o al recargar) devuelve la misma variable con su valor.

La ventana Variables de consola (Ventana > Depuración) las lista con un buscador y deja cambiarlas en vivo mientras juegas (deslizador si tienen mínimo y máximo, casilla los booleanos, texto con Intro).

3. OnValidate: el script que trabaja en el editor#

OnValidate es una función de tu script que el editor llama sin jugar: al cambiar un campo de la entidad en el Inspector y al abrir la escena. Sirve para colocar hijos, ajustar tamaños o avisar de valores malos:

Lua
local ValladeEjemplo = Script()
--[Range(0, 30)]
ValladeEjemplo.postes = 6 --[Int]
ValladeEjemplo.separacion = 2
ValladeEjemplo.poste = Asset("Prefab")

function ValladeEjemplo:OnValidate(motivo)
    -- Lo que generamos la vez anterior fuera, y otra vez con los valores de ahora
    Editor.ClearGenerated(self.entity)
    for i = 1, self.postes do
        local p = self.poste and Scene.Instantiate(self.poste, nil, self.entity) or Scene.Create("Poste " .. i, self.entity)
        p.position = self.entity.position + Vec3.new((i - 1) * self.separacion, 0, 0)
    end
    if self.postes < 2 then
        return "Una valla necesita al menos 2 postes" -- aviso en el panel Problemas
    end
end

return ValladeEjemplo
  • Cuándo se llama: al cambiar un campo de la entidad en el Inspector (al soltar el arrastre o confirmar el valor) y al abrir la escena. El argumento dice por qué: "field", "load" o "validate" (desde el panel Problemas, ver abajo; hasta la 0.9.36, "campo", "cargar" y "validar"). También vale el nombre OnEditorChange.
  • Lo que crea queda guardado en la escena, marcado con el componente Generado por script (su dueño y el script). Editor.ClearGenerated(self.entity) quita lo que generó esa entidad para volver a generarlo; Editor.GetGenerated() lo lista y Editor.IsGenerated(entidad) lo pregunta. Lo nuevo sale con los mismos UUID si se crea igual (mismo dueño, mismo script, mismo orden): regenerar sin cambios no deja la escena con cambios sin guardar ni pisa a nadie en la edición en equipo.
  • Deshacer: todo lo que hace una llamada (lo creado, lo borrado y los campos cambiados) es un paso del historial («OnValidate Valla»): Ctrl+Z lo deshace.
  • Edición en equipo: ese paso llega a los demás como cualquier otro cambio. Al abrir una escena de una sesión de equipo no se llama (lo hace quien tiene la escena; los demás reciben el resultado).
  • Sin bucles: el editor solo lo llama por lo que hace la persona (un campo, abrir la escena), nunca por lo que cambia el propio OnValidate; un while true do end lo corta el tiempo máximo por llamada de los scripts y sale el error.
  • No se ejecuta jugando ni en el juego publicado: el juego usa lo que quedó guardado. Dentro, Editor.IsEditing() es true.
  • Avisos: lo que devuelva (un texto o una lista de textos) y lo de Editor.Warn("...") sale en la Consola y en el panel Problemas, con clic que lleva a la entidad.
  • Corre en una máquina virtual propia que se abre para la llamada: no hay partida (ni red ni Awake), y lo que registre al cargar (RegisterCommand, CVar) no cuenta en el editor.

4. Botones del Inspector#

Un atributo encima de una función pinta un botón en el Inspector, debajo de los campos del script. Al pulsarlo, el editor ejecuta la función sin jugar, con deshacer de todo lo que cambie (un solo paso) y en la edición en equipo:

Lua
local CofreDeEjemplo = Script()
CofreDeEjemplo.monedas = 0 --[Int]

--[Button("Generar botín")]
function CofreDeEjemplo:GenerarBotin()
    Editor.ClearGenerated(self.entity)
    for i = 1, 3 do
        local moneda = Scene.Create("Moneda " .. i, self.entity)
        moneda.position = self.entity.position + Vec3.new(i * 0.5, 0.2, 0)
    end
    self.monedas = 3
end

--[Button("Vaciar")]
function CofreDeEjemplo:Vaciar()
    Editor.ClearGenerated(self.entity)
    self.monedas = 0
end

return CofreDeEjemplo

Los botones salen en el orden del código; sin texto (--[Button]), con el nombre de la función. Jugando están desactivados. Lo que crean va marcado como generado, igual que en OnValidate.

5. Validación de datos (panel Problemas)#

Al guardar la escena, al publicar y al pulsar Comprobar en el panel Problemas (Ventana > Depuración), el editor repasa el proyecto. Un clic en un problema lleva a la entidad (la selecciona y la encuadra), al script (en su línea) o al prefab. Si hay problemas al guardar, sale un aviso con «Ver los problemas». Al publicar van también a las comprobaciones (como avisos).

Regla Qué detecta
requerido Un campo marcado --[Required] (entidad, asset o texto) que está vacío, en la escena o en un prefab
red Un script con campos [Replicated] en una entidad (o un prefab) sin Identidad de red: no se sincronizarían
scriptComoComponente y los demás avisos de los scripts GetComponent("X") con el nombre de un script (es GetScript), componentes y scripts que no existen, Global de un script sin [Global]... Son los mismos que ve el editor de scripts y VS Code
requireDeScript require("X") de un script que va en entidades (Script()): devuelve la clase, no su instancia; usa entidad:GetScript("X") o Global("X")
triggerColision Un colisionador con Is Trigger y un script con OnCollisionEnter/Exit, que nunca llegan a un sensor (usa OnTriggerEnter)
assetRoto Una referencia a un asset que ya no existe (borrado o sin su .meta)
onValidate Lo que devuelve tu OnValidate o avisa con Editor.Warn: así amplías la validación desde Lua
Lua
local Puerta = Script()
--[Required]
Puerta.llave = Entity()        -- vacía: error en el panel Problemas
--[Required]
Puerta.sonido = Asset("Audio")

function Puerta:OnValidate()
    if self.llave and self.llave == self.entity then
        return "La llave de la puerta no puede ser la propia puerta"
    end
end

return Puerta

Para validar, el editor llama también a OnValidate("validate") de cada script y deshace al momento lo que cambie: solo se queda con los avisos.

6. Visual Logger#

Graba la partida para verla después frame a frame:

  1. Ventana > Depuración > Visual Logger y marca Grabar al jugar (o, desde un script, VisualLogger.Start()).
  2. Juega y para.
  3. Mueve la línea de tiempo (o pulsa ▶ para reproducir, con su velocidad, y las flechas para ir frame a frame).

Lo que se ve:

  • En el visor de la escena: las formas de depuración de ese instante (Debug.DrawLine, DrawSphere, DrawBox...), cada entidad en su sitio de entonces (unos ejes; la elegida, más grande) y, con Recorrido, el camino de la entidad elegida durante toda la grabación. Solo sus formas deja solo las que pidió el script de esa entidad.
  • Entidades: las que tienen scripts, IA o un personaje. La elegida es la que selecciones en la Jerarquía (Seguir la selección) o la de la lista.
  • Mensajes: los del registro hasta ese instante; los de print/Log.* de un script van con su entidad y se filtran.
  • Valores: lo que grabes con VLog y, si tiene Agente IA, la tarea que hacía su árbol de comportamiento.
Lua
function Zombi:Update(dt)
    VLog(self.entity, "vida", self.vida)          -- un valor (se ve el último de cada nombre en ese instante)
    VLog(self.entity, "estado", self.estado)
    Debug.DrawLine(self.entity.position, self.objetivo, Color.red) -- se graba con su entidad
    if self.vida < 20 then
        VLog(self.entity, "huyendo")               -- un mensaje de esta entidad
    end
end

VLog no hace nada si no se graba. Se guardan los últimos 10 minutos (a 60 fps) y hasta 1024 entidades. VisualLogger.Stop() deja de grabar y VisualLogger.IsRecording() dice si se graba.
