La guía para programar juegos con Nova Engine en C#: cómo es un script, todos los atributos, cómo se usa la API del motor desde C#, la recarga en caliente, el multijugador con el servidor al mando, async/await, cómo conviven C# y Lua en un mismo proyecto, VS Code y Visual Studio con autocompletado, la publicación, lo que todavía no hay en C# y, al final, lo que cambia respecto a Lua.

C# es el segundo lenguaje de los scripts, a la par que Lua: los dos van en el mismo componente Scripts, sus campos salen en el Inspector, se guardan con la escena, entran en los prefabs, el deshacer y la red, y usan la misma API del motor con los mismos nombres. Puedes mezclarlos en un proyecto (y en una misma entidad) como quieras. Si nunca has abierto el motor, empieza por empezar.md y editor.md; la referencia completa de lo que hace cada función está en scripts-lua.md (los nombres son los mismos, en PascalCase).

Hay un ejemplo completo en C#, el inventario multijugador tipo Rust: ejemplo-inventario-csharp.md.

1. Por qué C# (y cuándo Lua o C++)#

  • Un lenguaje que ya conoce media industria. Si ya sabes C#, no tienes que aprender otro: clases, tipos, List<T>, LINQ, async/await, genéricos...
  • Sin instalar nada. El editor lleva dentro el runtime de .NET y el compilador de C# (Roslyn): guardas el fichero y se compila y se recarga al momento, también con el juego en marcha y sin perder el estado. No hace falta Visual Studio ni el SDK de .NET (solo si quieres el autocompletado en un editor externo, sección 13).
  • Con tipos. El compilador te avisa de los errores al guardar (y el editor de scripts mientras escribes), con fichero y línea; el autocompletado conoce toda la API del motor y tus propias clases.
  • La misma red que Lua. [Replicated], [Server], [Client], [Multicast], [ServerOnly]... con las mismas reglas, comprobaciones y huella de red: un script C# y uno Lua se comportan igual en una partida en red.
  • Junto a Lua. Un script C# puede leer y llamar a uno Lua (y al revés) con GetScript.

2. Tu primer script en cinco minutos#

  1. Abre un proyecto (o crea uno con la plantilla Vacío (C#) de Nova Hub).
  2. En el panel Contenido, entra en scripts/, clic derecho > Nuevo script..., elige C# (las opciones son Lua, C# y C++ (avanzado)) y llámalo PrimerScript. El editor crea scripts/PrimerScript.cs con una plantilla (y Scripts.csproj en la carpeta del proyecto, para VS Code).
  3. Doble clic en el fichero para abrirlo en el editor de scripts y cámbialo por esto:
C#
using Nova;

public class PrimerScript : Script
{
    [Range(-720, 720), Tooltip("Grados por segundo")]
    public float Velocidad = 90;

    void Start()
    {
        Log.Info("Hola desde " + Name);
    }

    void Update(float dt)
    {
        // Gira sobre el eje vertical; con Espacio cambia de sentido
        Transform.Rotate(Vec3.Up, Velocidad * Mathf.Deg2Rad * dt);
        if (Input.WasKeyPressed("Space"))
            Velocidad = -Velocidad;
    }
}
  1. Guarda (Ctrl+S): abajo a la derecha sale «Scripts C# compilados y recargados». Si hay un error, sale el primero en rojo con su línea y el botón Abrir script, y todos en la Consola y en Problemas.
  2. Arrastra el fichero desde Contenido hasta un cubo de la Jerarquía (o al Inspector del cubo).
  3. Pulsa Jugar. El cubo gira y la Consola dice Hola desde Cubo. Cambia Velocidad en el Inspector: el cubo cambia al momento. Con el juego en marcha, cambia el código y guarda: se recarga sin parar el juego y sin perder la velocidad que pusiste.

3. Cómo funciona por dentro#

No hace falta saberlo para programar, pero explica casi todo lo que sigue:

  • El editor compila todos los .cs de scripts/ juntos en un ensamblado (Scripts.dll) con Roslyn, cada vez que guardas uno. Por eso una clase puede usar otra de otro fichero sin require ni nada.
  • Cada clase que hereda de Script y se llama como su fichero (scripts/ia/Enemigo.cs → class Enemigo : Script) es un script: sale en Añadir script y se arrastra a las entidades. Su nombre de tipo es la ruta dentro de scripts/: Enemigo.cs, ia/Enemigo.cs.
  • Para el motor, un script C# es una clase de la misma biblioteca que los scripts Lua: el compilador escribe una «clase sombra» con los mismos campos, atributos y funciones, y cada función llama al método de C#. Por eso el Inspector, el guardado, la red, las comprobaciones de las funciones de red y GetScript son exactamente los de Lua.
  • La API del motor en C# (Input, Scene, Physics, UI, los componentes...) se genera de la misma descripción de la API que usa el autocompletado de Lua (nova.d.luau): cada función de Lua tiene su versión C# con el mismo nombre. Qué tiene versión C# y qué no está, miembro a miembro, en csharp-paridad.md.
  • Las clases que no son scripts (static class Util, class Objeto) también se compilan y las usan los demás.

4. Anatomía de un script#

C#
using Nova;

// 1. La clase: hereda de Script y se llama como el fichero (scripts/Puerta.cs)
public class Puerta : Script
{
    // 2. Campos public: salen en el Inspector y se guardan con la escena. El tipo es el del campo
    [Range(0, 180)]
    public float AnguloAbierta = 90;
    public bool Abierta;
    public string Mensaje = "Pulsa E para abrir";
    public Entity Jugador; // referencia a otra entidad (se elige en el Inspector)

    // 3. Estado interno: lo que no es public no sale en el Inspector ni se guarda
    float _angulo;
    Quat _cerrada;

    const float Velocidad = 120; // grados por segundo

    static float Acercar(float actual, float objetivo, float paso) =>
        actual < objetivo ? System.MathF.Min(objetivo, actual + paso) : System.MathF.Max(objetivo, actual - paso);

    // 4. Funciones del ciclo de vida: por su nombre (las que no uses, no las escribas)
    void Start()
    {
        _cerrada = Transform.Rotation;
    }

    void Update(float dt)
    {
        bool cerca = Jugador != null && Vec3.Distance(Jugador.Position, Entity.Position) < 2;
        if (cerca && Input.WasActionPressed("Accion"))
            Alternar();
        _angulo = Acercar(_angulo, Abierta ? AnguloAbierta : 0, Velocidad * dt);
        Transform.Rotation = Quat.FromAxisAngle(Vec3.Up, _angulo * Mathf.Deg2Rad) * _cerrada;
    }

    // 5. Tus métodos: se llaman como cualquier método de C# (y desde la interfaz o Lua, por su nombre)
    public void Alternar()
    {
        Abierta = !Abierta;
        Log.Info(Name + (Abierta ? " abierta" : " cerrada"));
    }
}

La clase y lo que hereda de Script#

Miembro de Script Qué es (en Lua)
Entity La entidad (self.entity)
Transform Su Transform (self.transform)
Name El nombre de la entidad (self.name; se puede cambiar)
Enabled Si el script está activo (self.enabled; false = no recibe Update)
GetComponent<RigidBody>(), AddComponent<T>(), HasComponent<T>(), RemoveComponent<T>() Componentes de su entidad (self:GetComponent("RigidBody"))
GetScript<Inventario>() Otro script C# de su entidad, con su clase (o null)
GetScript("Vida") Otro script por su nombre (Lua o C#) como LuaScript, para usarlo con dynamic (sección 11)
AddScript<T>(), AddScript("Nombre") Añade un script a su entidad
Destroy(segundos?) Destruye su entidad (self:Destroy())
IsServer(), IsClient(), HasAuthority(), IsOwner(), IsLocalPlayer(), To(jugador) Red (sección 9)
Global<T>(), Instance<T>() El script [Global] o [Instance] de esa clase (Global("X"), Instances.X)
Wait(segundos) Espera sin parar el juego: await Wait(1.5f) (sección 10)
Las funciones globales de la API Spawn, SetTimeout, TriggerEvent, GetPlayers, Loc... se usan sin prefijo dentro de un script
  • Los métodos del ciclo de vida se escriben con su nombre, sin override. Pueden ser private, public o protected. Si no usas el parámetro, puedes quitarlo: void Update() también vale.
  • Lo static es de toda la sesión, no de la partida. En Lua, las variables local del fichero empiezan de cero en cada partida; en C#, un campo static sigue con su valor al parar y volver a jugar (y hasta que se recargan los scripts). Para datos de una partida usa campos de la instancia, o vacía los static en OnDestroy.
  • No uses la API en el constructor ni en los inicializadores de los campos (public Entity Jefe = Scene.Find("Jefe");): cuando se crea el objeto todavía no está en la escena. Es un error claro («La API del motor solo se puede usar dentro de las funciones del script»). Hazlo en Awake o Start.
  • Una clase de script por fichero (la que se llama como él). Otras clases en el mismo fichero (ayudas, enums, datos) valen, pero no se pueden añadir a una entidad: el compilador avisa.

Ciclo de vida#

Los mismos que en Lua y en el mismo orden:

Método Cuándo
Awake() Al crearse la instancia (al empezar la partida, al aparecer la entidad, o dentro de Scene.Instantiate y Spawn)
Start() Justo antes de su primer Update
Update(float dt) Cada frame (dt en segundos)
FixedUpdate(float dt) Cada paso fijo de las físicas (60 por segundo)
LateUpdate(float dt) Cada frame, después de todos los Update (cámaras)
OnDestroy() Al destruirse la entidad o el script, o al parar el juego
OnCollisionEnter(Collision c), OnCollisionExit(Collision c) Choques: c.Other, c.Point, c.Normal, c.Impulse, c.RelativeSpeed
OnTriggerEnter(Entity otra), OnTriggerExit(Entity otra) Algo entra o sale de un sensor (Collider con isTrigger)
OnNetworkSpawn() La red ya creó la entidad (en el servidor: ya tiene dueño)
OnReplicated() En los clientes, una vez por actualización de la red que cambió algún campo o tabla replicada
OnAnimationEvent(string nombre) Un evento de una animación
OnGUI() Cada frame, para dibujar con GUI.*
OnPoolGet(), OnPoolRelease(), OnAnimationFinished(string clip), OnInteract(int jugador), OnInteractFocus(), OnBreak(float nivel, Vec3 punto), OnRagdollActivated(), OnCollisionEnter2D(Collision2D c), OnTriggerEnter2D(Entity otra), OnJump(string tipo), OnSceneLoaded(), OnPlayerLoaded(int jugador), OnValidate(string motivo)... Todas las de la tabla de scripts-lua.md, con el mismo nombre y sus parámetros con tipo
C#
using Nova;

public class CicloDeVida : Script
{
    public int Golpes;

    void Awake() { Log.Info("Awake de " + Name); }
    void Start() { Log.Info("Start"); }
    void FixedUpdate(float dt) { }
    void LateUpdate(float dt) { }
    void OnDestroy() { Log.Info("Adiós, " + Name); }

    void OnCollisionEnter(Collision c)
    {
        if (c.RelativeSpeed > 3) Golpes++;
        if (c.Other != null) Log.Info("Choque con " + c.Other.Name + " en " + c.Point);
    }

    void OnTriggerEnter(Entity otra)
    {
        if (otra.HasTag("Jugador")) Log.Info(otra.Name + " ha entrado");
    }

    void OnAnimationEvent(string nombre)
    {
        if (nombre == "Paso") Audio.PlayOneShot("sonidos/paso.wav", Entity.Position);
    }

    void OnInteract(int jugador)
    {
        Log.Info("Lo ha usado " + GetPlayerName(jugador));
    }
}

5. Atributos#

Los mismos que los de Lua (--[Range(0, 100)]), como atributos de C#: el compilador los traduce, así que hacen exactamente lo mismo.

C# Lua Sobre Qué hace
[Global] --[Global] clase Script global: una instancia por partida, sin entidad del mapa (sección 9)
[Instance] --[Instance] clase Script único de la escena: desde cualquier otro, Instance<T>()
[Header("Texto")] Header campo Título de sección en el Inspector
[Space] Space campo Un hueco antes del campo
[Range(min, max)] Range campo Límites al editarlo (y red más compacta si está replicado)
[Slider], [Slider(min, max)] Slider campo Deslizador
[Step(x)] Step campo Paso al arrastrar
[Tooltip("Texto")] Tooltip campo Ayuda al pasar el ratón
[Display("Nombre")] Display campo Nombre en el Inspector (por defecto, el del campo: VelocidadMaxima → «Velocidad Maxima»)
[Hide] (o [HideInInspector]) Hide campo No sale en el Inspector (sí se guarda)
[ReadOnly] ReadOnly campo Se ve pero no se edita
[Multiline] Multiline string Caja de texto de varias líneas
[NoSave] NoSave campo No se guarda con la escena (vuelve a su valor por defecto)
[Angle] Angle número En radianes; el Inspector lo enseña en grados
[ColorField] Color Vec3 Selector de color (un campo Color ya lo es)
[HDR] HDR color Color con intensidad mayor que 1
un campo int (o long, short, byte, uint) Int número Número entero
un enum de C# Enum({...}) campo Desplegable con sus valores
[AssetType("Prefab")] Asset("Prefab") Asset Tipo de asset del campo: "Prefab", "Audio", "Material", "Model", "Texture", "Scene", "AnimatorController"... (sin él, "Prefab")
[Required] Required campo Obligatorio: vacío, sale como error en Problemas
[NonSerializedField] (o [System.NonSerialized]) empezar por _ campo public No es un campo del motor aunque sea public
[EditorOnly] EditorOnly campo o método Solo en el editor (en el juego publicado el método no hace nada y el campo no va)
[Replicated] Replicated campo public Lo cambia el servidor y llega a los clientes. OnChange = nameof(Metodo), Condition = "All" / "OwnerOnly" / "SkipOwner" (y "Observers" en tablas)
[Server] Server método Llamada al servidor. Rate = 5 (por segundo y jugador), Reliable = false, AnyCaller = true, OwnerOnly = true, Validate = nameof(F), KickAfter = 3
[Client] Client método Del servidor al dueño (o a un jugador con To(jugador)). Reliable = false
[Multicast] Multicast método Del servidor a todos (y a él mismo). Reliable = false
[ServerOnly] ServerOnly método Solo se ejecuta en el servidor o el anfitrión. Silent = true, Warn = true
[ClientOnly] ClientOnly método Solo donde hay pantalla. Silent, Warn
[OwnerOnly] OwnerOnly método Solo en la máquina del dueño de la entidad. Silent, Warn
[Cooldown(1.5)] Cooldown método No se repite antes de esos segundos. Warn = true
[ArgRange("cantidad", 1, 99)] ArgRange método [Server] Rechaza la llamada si ese argumento se sale del rango
[MaxLength("texto", 32)] MaxLength método [Server] Rechaza la llamada si ese texto es más largo
[Button("Texto")] Button método Botón en el Inspector que lo ejecuta en el editor sin jugar, con deshacer

using Nova;

public class TodosLosAtributos : Script
{
    public enum Modo { Quieta, Vigilar, Disparar }

    [Header("Movimiento")]

    [HDR]
    public Color Brillo = new Color(4, 2, 1, 1);

    [Header("Referencias")]

    [AssetType("Prefab")]
    public Asset Bala;
    [AssetType("Audio")]
    public Asset Sonido;

        Vidas = 3;

Un atributo que no tiene sentido donde está ([Range] en un string, [ArgRange] sin [Server]) es un aviso en la Consola, igual que en Lua. Los nombres de los atributos son los de C#: si escribes uno que no existe ([Rnage]), es un error de compilación con su línea.

6. Campos en el Inspector#

Un campo es un campo public de la instancia (no static, ni const, ni readonly). El orden del Inspector es el del código. Los tipos que pueden ser campos:

Tipo de C# En el Inspector En Lua
float, double número decimal number
int, long, short, byte, uint número entero (--[Int]) number
bool casilla boolean
string texto string
un enum desplegable con sus nombres string (Enum({...}))
Vec2, Vec3, Vec4 vector Vec2, Vec3, Vec4
Quat rotación Quat
Color color RGBA Color
Entity referencia a una entidad de la escena (null por defecto) Entity()
Asset referencia a un asset (con [AssetType("...")]) Asset("...")
ReplicatedTable no sale: es una tabla replicada (con [Replicated], sección 9) --[Replicated] X.t = {}
  • El valor por defecto es el de su inicializador (public float Velocidad = 5;); el motor crea un objeto de la clase para leerlos al compilar.
  • Entity y Asset son null hasta que eliges algo en el Inspector: compruébalo antes de usarlos (if (Objetivo != null)).
  • Un public de otro tipo (List<int>, una clase tuya, un Dictionary) no es un campo: el compilador avisa «un campo de tipo List1 no puede salir en el Inspector ni replicarse». Hazlo private(o ponle[NonSerializedField]`).
  • Nombres reservados que no pueden ser campos: entity, transform, name, enabled.
  • Si borras o renombras un campo, los valores guardados de los demás se conservan (por nombre).

7. La API del motor en C##

La API es la misma que la de Lua, generada de ella. La referencia de cada función (qué hace, qué devuelve, ejemplos) está en scripts-lua.md y en la Referencia de Lua; en C# se escribe así:

Lua C# Regla
Input.GetAxis("MoverX") Input.GetAxis("MoverX") Las tablas globales son clases estáticas con el mismo nombre
entidad.position, cuerpo.mass entidad.Position, cuerpo.Mass Los campos y propiedades, en PascalCase
entidad:GetComponent("RigidBody") entidad.GetComponent<RigidBody>() Los componentes, con su clase (también GetComponent("RigidBody"), que da un LuaValue)
self.transform, self.entity, self.name Transform, Entity, Name Lo de self, como miembros de Script
Time.deltaTime, Time.time Time.DeltaTime, Time.Elapsed (un miembro no puede llamarse Time dentro de la clase Time)
Spawn(prefab, pos), SetTimeout(500, f) Spawn(prefab, pos), SetTimeout(500, () => ...) Las funciones globales, sin prefijo dentro de un script (fuera, Globals.Spawn)
source Globals.Source (int?) El jugador que llamó a la [Server] o envió el evento
UI("HUD/Vida"), UI() UI.Get("HUD/Vida"), UI.Get() Lo que en Lua se llama como función, en C# es .Get(...) (también DataTable.Get(nombre))
Tags({ ... }), Event(), Timer(...), Curve(...), Pool(...) Tags.Create(...), Event.Create(), Timer.Create(...)... Lo que en Lua se llama como tabla, .Create(...)
Task.Delay(1, f) Tasks.Delay(1, () => ...) Task se llama Tasks (para no chocar con System.Threading.Tasks.Task)
Vec3.new(1, 2, 3), Vec3.up, Color.red new Vec3(1, 2, 3), Vec3.Up, Color.Red Los tipos matemáticos son structs de C#, con sus operadores
números float (y int para los enteros: jugadores, índices, capas, contadores) Un int vale donde va un float

Donde la función admite varias cosas (un número o unas opciones), el parámetro es un LuaValue y se le pasa cualquiera de ellas tal cual
{RaycastHit}, {string} List<RaycastHit>, List<string> Las listas que devuelve el motor, List<T>

un valor sin tipo (any) LuaValue Se convierte con .AsFloat(), .AsString(), .As<T>()...

Cuando un nombre se repite. Algunas tablas globales se llaman como un componente o un tipo que tiene un método del mismo nombre y con los mismos parámetros (River.FlowAt de la tabla global y rio.FlowAt del componente). En C#, la de la tabla global lleva Static detrás: River.FlowAtStatic(pos), River.SurfaceAtStatic(pos), Light2D.FlickerStatic(...), Mat4.TranslationStatic(v). El autocompletado enseña las dos.

C#
using Nova;
using System.Collections.Generic;

public class Torreta : Script
{
    public enum Modo { Quieta, Vigilar, Disparar }

    [Tooltip("A quién apunta (arrástralo desde la Jerarquía)")]
    public Entity Objetivo;
    [AssetType("Prefab"), Tooltip("Prefab de la bala")]
    public Asset Bala;
    [AssetType("Audio")]
    public Asset Sonido;
    public Modo Estado = Modo.Vigilar;
    public Color ColorLaser = new Color(1, 0.2f, 0.2f, 1);
    [Range(0.1, 10)]
    public float Cadencia = 2;

    float _espera;

    void Update(float dt)
    {
        if (Estado == Modo.Quieta || Objetivo == null) return;
        Transform.LookAt(Objetivo);
        _espera -= dt;
        if (Estado != Modo.Disparar || _espera > 0 || Bala == null) return;
        _espera = 1 / Cadencia;
        Vec3 delante = Transform.Forward;
        Entity bala = Scene.Instantiate(Bala, Entity.Position + delante);
        bala?.GetComponent<RigidBody>()?.AddImpulse(delante * 20);
        if (Sonido != null)
            Audio.PlayOneShot(Sonido, Entity.Position, new OneShotOptions { Volume = 0.6f, Bus = AudioBus.Sfx });

        // Un rayo: ¿hay algo entre la torreta y el objetivo?
        RaycastHit golpe = Physics.Raycast(Entity.Position, delante, 50, new PhysicsQuery { Ignore = Entity });
        if (golpe != null && golpe.Entity != Objetivo)
            Log.Warn("Hay algo en medio: " + golpe.Entity?.Name);

        // Listas y tablas
        List<Entity> enemigos = Scene.FindAllByTag("Enemigo");
        Log.Info("Enemigos: " + enemigos.Count);
    }
}

Matemáticas. Vec2, Vec3, Vec4, Quat y Color son structs con operadores (+, -, *, /, ==) y las mismas funciones que en Lua (Vec3.Dot, Vec3.Lerp, v.Length(), Vec3.Distance, Quat.Euler, Quat.LookRotation, q * v...). Las básicas se calculan en C#; las de ángulos (Quat.Euler, Vec3.Slerp, Vec3.Angle...) llaman a las del motor, así que dan exactamente lo mismo que en Lua. Mathf tiene Lerp, Clamp, Deg2Rad, SmoothDamp...; y las de .NET (System.MathF) también valen.

Números aleatorios. Random tiene las mismas funciones que en Lua (Random.Number(1, 10), Random.Integer, Random.Bool, Random.Pick, Random.InsideUnitSphere...); con semilla, RandomGenerator dado = Random.New(42); y dado.Integer(1, 6).

8. Errores y recarga en caliente#

Al guardar un .cs el editor compila todos los scripts C# (la primera vez tarda un par de segundos; después, muy poco) y:

  1. Si compila, recarga: «Scripts C# compilados y recargados». Los objetos que ya existen pasan a la clase nueva conservando su estado: los campos public (los del motor) y también el estado privado de tipos sencillos (números, textos, bool, vectores, Entity, List<int>, Dictionary<string, float>... de .NET y del motor) y las referencias a otros scripts C#. Lo demás (objetos de tus propias clases) vuelve a su valor inicial. No se vuelven a llamar Awake ni Start.
  2. Si no compila, se sigue con la versión anterior y los errores salen en la Consola (todos) y en Problemas (el primero de cada fichero), con fichero, línea y columna; el aviso de abajo a la derecha enseña el primero con el botón Abrir script. Pulsa el error para abrir el script en esa línea:
ERROR C#: scripts/Roto.cs:5:29: error CS0103: El nombre 'noExiste' no existe en el contexto actual
  1. Si los campos cambian, el Inspector se actualiza y los valores de las entidades se conservan por nombre.
  2. Las versiones viejas de los scripts se descargan de la memoria (no se acumulan por muchas veces que guardes).

Excepciones. Una excepción en un script sale en la Consola con el fichero y la línea del .cs, la función del motor que la llamó, la entidad y la pila de C#:

ERROR C#: scripts/Lanza.cs:11: NullReferenceException: Object reference not set to an instance of an object. (Update de Lanza.cs en 'Lanza')
  en Lanza.Update(Single dt) en scripts/Lanza.cs:line 11

El mismo error no se repite cada frame (uno y después un resumen cada 5 segundos) y el script sigue recibiendo llamadas: una excepción nunca cierra el editor ni el juego. Los mensajes de las excepciones de .NET salen en inglés.

Sin .NET. Si falta el runtime de .NET (una instalación rota), los scripts C# no se cargan, la Consola lo dice y el resto del proyecto (y los scripts Lua) siguen funcionando. Reinstalar Nova Engine lo arregla.

Editor > Recargar scripts (Ctrl+R) también vuelve a compilar y cargar los .cs.

9. Multijugador#

Todo lo de scripts-lua.md vale igual en C# (el servidor manda, un fichero para los dos lados, IsServer()/IsClient()/IsOwner()/IsLocalPlayer(), [Global], los límites y la validación...). Lo que cambia es cómo se escribe.

Las funciones de red se llaman como cualquier método. Sumar(5) en un método [Server] hace lo mismo que self:Sumar(5) en Lua: si quien llama está en el servidor, se ejecuta ahí; si es el dueño en un cliente, viaja al servidor; si no puede llamarla, es una excepción (LuaException) con el mismo mensaje que en Lua («[Server] Sumar solo la puede llamar el dueño de 'Jugador'»). Los parámetros llevan el tipo de C# (int viaja como entero, float y double como número, string, bool, Vec3, Quat, Color, Entity, Asset, enum como texto) y se comprueban igual que las anotaciones de Lua.

C#
using Nova;

public class Barril : Script
{
    [Replicated(OnChange = nameof(AlCambiarVida)), Range(0, 100)]
    public int Vida = 100;
    [Replicated(Condition = "OwnerOnly")]
    public string Secreto = ""; // solo lo recibe el dueño

    // En el servidor: lo llama otro script cuando le disparan
    public void Danar(int cantidad)
    {
        if (!IsServer()) return;
        Vida = System.Math.Max(0, Vida - cantidad);
        if (Vida == 0) Destroy(); // con Identidad de red, se destruye en todas las máquinas
    }

    // En los clientes, cada vez que llega un valor nuevo de Vida
    void AlCambiarVida()
    {
        Log.Info(Name + " tiene " + Vida + " de vida");
    }
}
C#
using Nova;

// El cofre del tesoro de la partida, como script [Global]: cualquier jugador puede pedir abrirlo (tecla F) y solo el
// primero se lleva el premio. El servidor decide; los demás reciben el resultado.
[Global]
public class Cofre : Script
{
    [Replicated] public bool Abierto;
    [Replicated] public string Quien = "";

    // Cliente -> servidor (en un [Global] la puede llamar cualquier jugador; Globals.Source dice quién)
    [Server(Rate = 2)]
    void Abrir()
    {
        int jugador = Globals.Source ?? 0;
        if (Abierto)
        {
            To(jugador).Call(nameof(Aviso), "Llegas tarde: ya está abierto");
            return;
        }
        Abierto = true;
        Quien = GetPlayerName(jugador) ?? "?";
        Efecto(new Vec3(0, 1, 0));
        To(jugador).Call(nameof(Aviso), "¡Has encontrado 100 monedas!");
    }

    // Servidor -> todos: sonido y partículas en cada máquina
    [Multicast(Reliable = false)]
    void Efecto(Vec3 donde)
    {
        Log.Info("¡Clac! El cofre se abre en", donde);
    }

    // Servidor -> un jugador: To(id).Call(nameof(Aviso), ...)
    [Client]
    void Aviso(string texto)
    {
        Log.Info("Aviso:", texto);
    }

    void Update(float dt)
    {
        if (IsClient() && Input.WasKeyPressed("F"))
            Abrir();
    }
}
  • To(jugador) es self:To(jugador): To(id).Call(nameof(Aviso), "texto") llama a la función [Client] en la máquina de ese jugador. Sin To, Aviso("texto") va al dueño de la entidad.
  • Globals.Source es source: el jugador que llamó a la [Server] (o que envió el evento), null fuera de ellas. Cópialo a una variable si lo necesitas después de un await.
  • Las funciones de red no devuelven valores (como en Lua): para una respuesta, el servidor llama a un [Client].
  • [ServerOnly], [ClientOnly], [OwnerOnly], [EditorOnly] y [Cooldown] funcionan igual que en Lua (9.14): donde no toca, la llamada no hace nada y devuelve el valor por defecto (0, null, false).
  • OnChange se llama en los clientes (no en el servidor ni en el anfitrión): si hace falta, llámalo tú después de cambiar el campo.
C#
using Nova;

public class InventarioRed : Script

Tablas replicadas. Un campo ReplicatedTable con [Replicated] es la tabla replicada de Lua (--[Replicated] X.t = {}): el motor la crea (no hace falta new), el servidor la cambia por claves y solo viajan las que cambian, con los mismos límites y condiciones ("Observers" incluida, con SetObservers).

C#
using Nova;
using System.Collections.Generic;

public class Tablero : Script
{
    [Replicated(OnChange = nameof(AlCambiarCasillas))]
    public ReplicatedTable Casillas;
    [Replicated(Condition = "Observers")]
    public ReplicatedTable Cartas; // solo lo reciben los jugadores de SetObservers

    // En el servidor
    public void Marcar(int casilla, string jugador)
    {
        if (!IsServer()) return;
        Casillas[casilla] = jugador; // solo viaja esta clave
        Cartas["mano"] = LuaValue.From(new List<string> { "as", "rey" });
        SetObservers(new List<int> { Network.GetOwner(Entity) });
    }

    // En los clientes
    void AlCambiarCasillas()
    {
        foreach (KeyValuePair<LuaValue, LuaValue> kv in Casillas)
            Log.Info(kv.Key + " = " + kv.Value);
    }

    void OnReplicated()
    {
        Log.Info("Casillas: " + Casillas.Count + " (seguidas desde la 1: " + Casillas.Length + ")");
    }
}

10. async y await#

En Lua se espera con Wait(ms) dentro de CreateThread. En C#, con await Wait(segundos) en un método async:

C#
using Nova;

public class Semaforo : Script
{
    public string Luz = "Verde";

    async void Start()
    {
        while (true)
        {
            Luz = "Verde";
            await Wait(5);
            Luz = "Ámbar";
            await Wait(1.5f);
            Luz = "Rojo";
            await Wait(5);
        }
    }
}
  • Wait cuenta tiempo de juego (se para en pausa y con Time.TimeScale).
  • Lo que va después de un await sigue en el hilo principal, en un frame siguiente, con su script como siempre (sus campos al día y la API disponible).
  • Si el script o su entidad se destruyen (o se para el juego), lo que estaba esperando no sigue.
  • SetTimeout(ms, () => ...) y Tasks.Delay(segundos, () => ...) también valen, como en Lua.
  • await Task.Delay(ms) de .NET también vuelve al hilo principal con su script, pero cuenta tiempo real (no se para en pausa ni con Time.TimeScale): para el juego, mejor Wait. Task.Run (y ConfigureAwait(false)) siguen en otro hilo, donde no se puede usar la API del motor (es un error claro): sirve para cálculos que no tocan la escena.
  • CreateThread(() => ...) existe, pero dentro no se puede usar el Wait de Lua (y Task.Wait de Lua, Tasks.Wait en C#, no está): para esperar, async y await Wait(segundos).

11. Lua y C# en el mismo proyecto#

Los dos lenguajes conviven: una entidad puede llevar scripts Lua y C#, y cada uno usa al otro con GetScript.

Desde C#, un script Lua es un LuaScript: con dynamic se usa como en Lua (sus campos y sus funciones por nombre), o con Get, Set y Call:

C#
using Nova;

public class Lector : Script
{
    void Update(float dt)
    {
        dynamic vida = GetScript("Vida"); // scripts/Vida.luau
        if (vida == null) return;
        vida.salud -= 10;                  // campo de Lua (los números llegan como double)
        double queda = vida.Curar(5);      // función de Lua: vida:Curar(5)

        LuaScript mismo = GetScript("Vida");
        float salud = mismo.Get("salud").AsFloat();
        mismo.Set("salud", salud + 1);
        mismo.Call("Curar", 1);
    }
}

Desde Lua, un script C# es como cualquier otro: self:GetScript("Contador") da su instancia, con sus campos public (con el nombre de C#) y sus métodos. Con este script C#:

C#
using Nova;

public class Contador : Script
{
    public int Count;

    void Update(float dt) { Count++; }

    public int Double(int x) => x * 2;
}

uno Lua de la misma entidad lo lee y lo llama así:

Lua
local PuenteCs = Script()
PuenteCs.leido = 0 --[Int]
PuenteCs.doble = 0 --[Int]

function PuenteCs:Update(dt: number)
    local c = self:GetScript("Contador") -- scripts/Contador.cs
    if c then
        self.leido = c.Count -- campo public de C#
        self.doble = c:Double(21) -- método public de C#
    end
end

return PuenteCs

Entre scripts C#, con su clase: GetScript<Contador>() (o Global<T>(), Instance<T>()). Lo que escribes en los campos de otro script C# lo ven Lua, el Inspector y la red en cuanto termina la función que se está ejecutando.

12. El editor de scripts integrado#

Nuevo script... (en Contenido, clic derecho, y en Añadir script del Inspector) pregunta el lenguaje: Lua, C# o C++ (avanzado). El de C# sale con la plantilla de una clase Script con Start y Update.

Los .cs se abren en el editor de scripts del motor (doble clic en Contenido, o desde un error) con lo mismo que los .luau (editor-scripts.md): números de línea, buscar y reemplazar, varias pestañas y guardar con Ctrl+S. Para C#, además:

  • Colores de C# y plegado por llaves y por #region.
  • Autocompletado (con Roslyn, el compilador de C#) de la API del motor y de tus propias clases y sus miembros, de las palabras clave y de los atributos. Dentro de la clase, los métodos del ciclo de vida (Update, OnTriggerEnter...) salen como fragmentos con su firma.
  • Ayuda de los parámetros al escribir ( y ,: la firma, el parámetro que toca y su documentación.
  • Ayuda al pasar el ratón: la documentación en español de cada función (la misma que la de Lua).
  • Errores mientras escribes: los del compilador, subrayados en su sitio, sin guardar.
  • Ir a la definición, buscar referencias, renombrar y el esquema del fichero (sus clases, campos y métodos).
  • Cada vez que guardas se compila y se recarga (sección 8).

Los puntos de parada y el depurador paso a paso son solo de Lua: en un .cs, el editor lo dice en la barra de estado.

13. VS Code, Visual Studio y Rider#

Cuando el proyecto tiene scripts .cs, el editor escribe en su carpeta un Scripts.csproj (y una carpeta oculta .csharp/ para lo que se genera al compilarlo) que incluye scripts/**/*.cs y referencia el Nova.Runtime.dll de tu instalación del motor (con su documentación en español). Ábrelo (o la carpeta del proyecto) en VS Code con la extensión C# Dev Kit, en Visual Studio o en Rider y tendrás el autocompletado, los errores y la ayuda de toda la API.

  • Para eso sí hace falta el SDK de .NET 10 en tu PC (es lo que usan esos editores para entender un .csproj). Para jugar, compilar y publicar con Nova no hace falta: el motor lleva el suyo.
  • El .csproj es solo para los editores externos: el que compila los scripts es Nova al guardar. Si compilas con dotnet build, lo de .csharp/ es tuyo (no se usa).
  • Si mueves el motor de carpeta, el editor rehace el .csproj al abrir el proyecto.
  • Para C# en VS Code, la extensión C# Dev Kit de Microsoft da el autocompletado. La extensión de Nova Engine (scripts-lua.md) añade la orden «Nova: Nuevo script C#» y fragmentos para C#: novascript (un script entero), Update, server, client, multicast, replicado, tablareplicada y esperar (await Wait(...)).

14. Publicar#

Al publicar (publicar-juego.md), si el proyecto tiene scripts C#, el juego lleva además:

  • data/scripts/Jugador.csc: la clase sombra de cada script en bytecode, como el .luauc de los de Lua — sin el código fuente;
  • csharp/, junto al ejecutable: Nova.Runtime.dll y tus scripts compilados en modo Release (Scripts.dll), su Scripts.pdb (para que las excepciones digan fichero y línea) y Scripts.json;
  • dotnet/, junto al ejecutable: el runtime de .NET 10 (unos 70 MB). Un juego sin scripts C# no lo lleva.

NovaGame.exe y NovaServer.exe los cargan sin compilar nada (no llevan el compilador). Si un .cs no compila, publicar se para y dice cuál y en qué línea.

15. Lo que todavía no hay en C##

La lista completa, miembro a miembro, está en csharp-paridad.md (se comprueba sola al compilar el motor). Lo que hay que saber:

  • Datos de juego como campos: Struct({...}), List(...), Dict(...) y los atributos --[List(...)] y --[Dict(...)] de datos.md no tienen versión C# todavía. Sí puedes leer Data Tables y Data Assets (DataTable.Get("Armas"), un campo Asset con [AssetType("DataAsset")]).
  • El depurador paso a paso del editor (puntos de parada, variables) es solo de Lua (en un .cs, la barra de estado lo dice). En C#, usa Log.Info y las excepciones (con fichero, línea y pila). Adjuntar Visual Studio al proceso de NovaEditor.exe (Depurar > Asociar al proceso, código administrado) puede servir, pero no está probado: los scripts se cargan desde memoria.
  • Los arreglos rápidos (la bombilla del editor de scripts) y el aviso de los textos obsoletos son de Lua.
  • Los tipos de tus scripts Lua en C#: GetScript("Vida") da un LuaScript sin tipo (con dynamic), no una clase con sus campos.
  • Un bucle infinito en C# no se puede cortar: en Lua el motor detiene el script a los 2 segundos; el código C# corre en el proceso del editor y lo deja colgado (cierra el editor desde el Administrador de tareas; lo guardado no se pierde).
  • Sin límite de memoria por script (el de Lua es de 256 MB por partida).
  • Algunas páginas de la documentación solo tienen ejemplos en Lua: con C# elegido en el selector de lenguaje, cada ejemplo sin versión C# lo dice (sección 18).

'Random' es una referencia ambigua Tienes using System;: escribe Nova.Random
Un static sigue con el valor de la partida anterior Los static duran toda la sesión del editor: límpialos en OnDestroy
Update no se llama Lo escribiste con otro nombre (update, OnUpdate): los del ciclo de vida van con su nombre exacto
Al recargar se pierde una lista de objetos tuyos La recarga conserva lo sencillo; lo de tus clases vuelve a su valor inicial (rellénalo en Start o guárdalo en campos)

17. Consejos de rendimiento#

  • Cada llamada a la API cruza a la máquina de Lua de la escena: es rápida, pero no gratis. Guarda lo que repites (var cuerpo = GetComponent<RigidBody>(); en Start, no en cada Update) y lee una vez lo que usas varias (Vec3 p = Entity.Position;).
  • Los campos public se copian entre el motor y el objeto C# en cada llamada del motor (solo los que cambian): diez campos no se notan; trescientos en mil entidades, sí. Lo interno, mejor private.
  • La matemática es C# puro (Vec3, Quat, Mathf.Lerp...) salvo las funciones de ángulos: en bucles grandes, usa las de C#.
  • Para muchas entidades a la vez, las funciones por lotes de la API (Scene.GetPositions, Physics por lotes, Spatial) hacen el trabajo en el motor con una sola llamada (nativas-juego.md).
  • El primer guardado tras abrir el editor tarda un par de segundos (el compilador arranca); los siguientes, una fracción.

18. La documentación en C##

La documentación en HTML (la del editor, Ayuda > Documentación, y la web) tiene arriba un selector de lenguaje: C#, Lua o C++. Lo que eliges se recuerda en el navegador:

  • El buscador (Ctrl+K) solo da resultados del lenguaje elegido, más las páginas que valen para todos (el editor, la interfaz, las físicas...).
  • Los bloques de código salen en el lenguaje elegido; si un ejemplo todavía no tiene versión en ese lenguaje, el bloque lo dice (y enseña el que hay).
  • La referencia de Lua es la de la API: en C# es la misma, con los nombres en PascalCase (sección 7).
