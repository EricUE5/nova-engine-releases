Esta guía explica cómo empezar: con el motor instalado o compilándolo desde el código fuente, cómo abrir el editor con los proyectos de ejemplo, cómo crear tu primer proyecto y tu primer script paso a paso y, para quien compila el motor, cómo ejecutar las pruebas. El orden de lectura del resto de la documentación está en indice.md.

Los juegos se programan en Lua (Luau): los scripts no se compilan, se recargan al guardarlos (también con el juego en marcha) y no hace falta Visual Studio. Visual Studio solo hace falta para compilar el propio motor desde el código fuente o para los scripts en C++, que son opcionales (scripts-cpp.md).

Dos formas de empezar#

Motor instalado Desde el código fuente
Para quién Para hacer juegos Para cambiar el motor (o estudiarlo)
Cómo NovaEngine-Setup.exe y Nova Hub: ver instalar.md Compilar con tools\build.cmd (abajo)
Hace falta Windows 10/11 de 64 bits y una GPU con Direct3D 11 Además, Visual Studio 2022 con C++
Proyectos nuevos Nova Hub > Nuevo proyecto > Vacío (Lua) Archivo > Nuevo proyecto... en el editor

Con el motor instalado, sáltate las secciones de compilar y de las pruebas: ve a Tu primer proyecto paso a paso.

Requisitos para compilar el motor#

Qué Detalle
Sistema Windows 10 u 11 de 64 bits
Compilador Visual Studio 2022 con la carga de trabajo "Desarrollo para el escritorio con C++" (MSVC 14.44, conjunto de herramientas v143)
SDK Windows SDK 10.0.26100
CMake y Ninja Los que instala Visual Studio con el componente "Herramientas de CMake de C++ para Windows". No hace falta instalarlos aparte
GPU Cualquier tarjeta con Direct3D 11. Sin GPU compatible se usa WARP (render por software de Windows), más lento pero funcional

tools\env.cmd busca Visual Studio con vswhere.exe y, si no lo encuentra, prueba la ruta C:\Program Files\Microsoft Visual Studio\2022\Community. Después carga vcvars64.bat y añade al PATH el CMake y el Ninja de Visual Studio. No necesitas abrir una "Developer Command Prompt": los scripts de tools\ preparan el entorno solos.

Compilar#

Todo se compila con tools\build.cmd desde la carpeta del repositorio:

Símbolo del sistema
tools\build.cmd                     :: preset debug, todo
tools\build.cmd release             :: preset release
tools\build.cmd shipping            :: preset shipping (para publicar)
tools\build.cmd debug NovaEditor    :: solo un target

La sintaxis es tools\build.cmd [debug|release|shipping] [target]. El script configura CMake en cada llamada (es rápido) para detectar carpetas o ficheros nuevos y después compila.

Presets#

Los presets están en CMakePresets.json. Todos usan Ninja y cl.

Preset Tipo de compilación Qué incluye Para qué
debug Debug Motor, editor, juego, pruebas Desarrollo diario y depuración
release RelWithDebInfo Motor, editor, juego, pruebas Desarrollo con buen rendimiento
shipping Release Motor y juego (sin editor ni pruebas) Publicar el juego

debug y release son compilaciones de desarrollo (NOVA_DEV = 1): los shaders se leen de engine/shaders y se recargan en caliente, el título de la ventana del juego muestra los FPS y el editor puede compilar los scripts C++. shipping desactiva todo eso.

Targets#

Target Resultado
nova_engine Librería estática del motor
NovaEditor Editor (NovaEditor.exe)
NovaGame Reproductor de juegos (NovaGame.exe)
NovaServer Servidor dedicado (NovaServer.exe)
NovaHub Nova Hub (NovaHub.exe)
nova_tests Pruebas del motor (nova_tests.exe)
doc_snippets Los ejemplos de C++ de docs/ compilados como una DLL (doc_snippets.dll)
sample_game, multiplayer_game Los scripts de los ejemplos en C++ (game/sample y game/multiplayer_sample)
nova_samplegen, nova_mpgen, nova_invgen Generadores de los assets de los ejemplos (el último, del inventario tipo Rust en Lua)
nova_net_tests, nova_physics_tests, nova_audio_tests Pruebas de las librerías de red, físicas y audio
nova_shaders Copia engine/shaders a bin/shaders

Los ejemplos en Lua (game/sample_lua, game/multiplayer_lua y game/inventario_lua) no tienen target: sus scripts los carga el motor.

Dónde queda el resultado#

Todo va a build\<preset>\:

build\debug\
  bin\NovaEditor.exe
  bin\NovaGame.exe
  bin\NovaServer.exe
  bin\NovaHub.exe
  bin\nova_tests.exe
  bin\sample_game.dll         scripts del ejemplo en C++
  bin\multiplayer_game.dll    scripts del ejemplo multijugador en C++
  bin\shaders\                copia de engine\shaders
  shadercache\                caché de shaders compilados (compilaciones de desarrollo)
  test_output\                imágenes de las pruebas de render

Ejecutar las pruebas#

Símbolo del sistema
tools\test.cmd                 :: todas las pruebas con el preset debug
tools\test.cmd release         :: con el preset release
tools\test.cmd debug json      :: solo las pruebas cuyo nombre contiene "json"

tools\test.cmd [preset] [filtro] compila el preset y ejecuta build\<preset>\bin\nova_tests.exe: núcleo (matemáticas, JSON, reflexión, PNG, ficheros, tareas), ECS y escenas, entrada, assets, shaders, mallas, glTF, animación, render, scripts Lua y C++, el editor, físicas, audio, red (servidor y clientes en memoria con latencia y pérdida), los ejemplos (también los de Lua, jugados en red), los tutoriales de la documentación, NovaServer.exe por UDP y unas pruebas de humo que lanzan NovaEditor.exe y NovaGame.exe sin ventana visible y guardan una captura. Sin filtro, después ejecuta con CTest las pruebas de las librerías nova_net, nova_physics y nova_audio, de Steam (sin el SDK) y del instalador. Ninguna prueba abre ventanas en pantalla ni suena. Las imágenes se guardan en build\<preset>\test_output. El preset shipping no compila las pruebas.

Los nombres de las pruebas empiezan por su área (math:, json:, reflexion:, ecs:, escena:, input:, assets:, shaders:, gltf:, animacion:, render:, editor:, lua:, lua ejemplos:, fisicas:, audio:, red:, multijugador:, servidor dedicado:, documentacion:...), así que el filtro sirve para ejecutar un grupo.

Las pruebas nunca escuchan en los puertos que usa la persona en su PC (7777-7779, 7790, 8788, 8798, 27100-27109): usan el puerto 0 o uno del rango de pruebas 40000-40999, y una salvaguarda hace fallar la que lo intente. La regla para las pruebas nuevas está en pruebas.md.

Variables de entorno de las pruebas:

Variable Efecto
NOVA_FORCE_WARP=1 Render por software (WARP) en lugar de la GPU
NOVA_D3D_DEBUG=1 Activa la capa de depuración de Direct3D 11 (si está instalada)
NOVA_PUERTOS_REGISTRO=<fichero> Apunta cada puerto que abre un proceso de las pruebas (pruebas.md)
Símbolo del sistema
set NOVA_FORCE_WARP=1
tools\test.cmd debug render

Abrir el editor#

Con el motor instalado, el editor se abre desde Nova Hub (doble clic en un proyecto). Desde el código fuente:

Símbolo del sistema
build\debug\bin\NovaEditor.exe
  • La primera vez aparece la ventana Proyectos. Pulsa Abrir el proyecto de ejemplo (solo en compilaciones de desarrollo: abre game\sample_lua, el ejemplo con sus scripts en Lua) o Abrir proyecto... y elige una carpeta con project.nova. Ejemplo en C++ (avanzado) abre game\sample, el mismo ejemplo con sus scripts en C++.
  • Las siguientes veces el editor abre directamente el último proyecto usado.
  • También puedes indicarlo en la línea de comandos:
Símbolo del sistema
build\debug\bin\NovaEditor.exe --project game\sample_lua

El proyecto de ejemplo abre la escena scenes/Principal.scene: un suelo, cajas (instancias de un prefab), esferas con distintos materiales, faroles con luces puntuales, un foco, un cono que gira (script Rotador.luau), un zorro que pasea solo (Paseante.luau) y un personaje controlable (Personaje.luau y la cámara, CamaraOrbital.luau). Sus scripts están en game\sample_lua\scripts: ábrelos con doble clic en el panel Contenido, cámbialos y guárdalos con el juego en marcha para ver cómo se recargan.

Pulsa Ctrl+P (o el botón de reproducir de la barra superior) para jugar:

Control Acción
W A S D, flechas o stick izquierdo Mover al personaje (relativo a la cámara)
Mayús izquierda, LB o L3 Correr
Botón derecho del ratón + mover Girar la cámara
Stick derecho Girar la cámara
Rueda del ratón Acercar o alejar la cámara
Esc Liberar el ratón y volver al panel Escena
Ctrl+P Detener

La entrada solo llega al juego mientras el panel Juego tiene el foco. Haz clic en él si el personaje no responde.

La guía completa del editor está en editor.md.

Los otros ejemplos en Lua#

Además del ejemplo 3D, el repositorio trae dos ejemplos multijugador en Lua: game/multiplayer_lua («Rey de la arena», con el servidor al mando) y game/inventario_lua (un inventario multijugador como el de Rust, ejemplo-inventario.md). Con el motor instalado, el inventario es la plantilla Inventario tipo Rust (Lua) de Nova Hub.

Para juegos por rondas con amigos está game/fiesta_lua («Fiesta»): una sala donde se crea la partida con un código, cada uno pulsa «Listo» y el líder empieza; las rondas cambian de escena para todos con pantalla de carga (lobby-y-escenas.md).

Símbolo del sistema
build\debug\bin\NovaEditor.exe --project game\multiplayer_lua
build\debug\bin\NovaGame.exe --project game\multiplayer_lua --host --name Ana
build\debug\bin\NovaGame.exe --project game\multiplayer_lua --connect 127.0.0.1:7778 --name Beto
build\debug\bin\NovaGame.exe --project game\inventario_lua --solo

En el editor, elige Anfitrión + clientes en el desplegable junto al botón de reproducir y pulsa Ctrl+P: el editor juega como anfitrión y abre una ventana de NovaGame.exe conectada a él. Empuja al otro personaje con E y mira cómo se ven igual en las dos pantallas; F3 muestra las estadísticas de red. Las demás formas de probarlo y cómo se hace un juego en red están en multijugador.md.

Los ejemplos en C++ (game/sample y game/multiplayer_sample) siguen en el repositorio para quien use scripts C++: ver scripts-cpp.md.

Ejecutar un juego sin el editor#

Símbolo del sistema
build\debug\bin\NovaGame.exe --project game\sample_lua

NovaGame.exe carga project.nova, los scripts (los .luau de scripts/ o, en un juego publicado, su bytecode; y la DLL de scripts C++ si el proyecto la tiene) y la escena inicial. Opciones útiles:

Opción Efecto
--project <carpeta> Proyecto a cargar. Sin ella se usa <carpeta del exe>\data (juego publicado)
--scene <ruta en assets> Otra escena inicial, por ejemplo scenes/Prueba.scene (la extensión se puede omitir: scenes/Prueba). Si no carga, el juego sale con el código 3 y el motivo en el log
--fullscreen / --windowed Fuerza pantalla completa o ventana
--width N / --height N Tamaño de la ventana
--warp Render por software

En el juego, Alt+Intro cambia entre ventana y pantalla completa. La lista completa de opciones está en publicar-juego.md.

Tu primer proyecto paso a paso#

1. Crear el proyecto#

Con el motor instalado:

  1. En Nova Hub, pulsa Nuevo proyecto. La plantilla elegida es Vacío (Lua): déjala.
  2. Escribe un Nombre (por ejemplo MiJuego), elige la Carpeta (por defecto Documentos\Nova Projects) y pulsa Crear. El proyecto se abre en el editor.

Desde el código fuente: en el editor, Archivo > Nuevo proyecto... (o la ventana Proyectos del arranque), escribe un Nombre y una Carpeta y pulsa Crear proyecto.

Con la plantilla Vacío (Lua), el proyecto queda así:

MiJuego\
  project.nova                 ajustes del proyecto (JSON)
  assets\
    scenes\Principal.scene     escena inicial con Sol, Entorno, Cámara, Suelo (con colisionador) y un Cubo
  scripts\
    GirarYFlotar.luau          el script de ejemplo del Cubo (plantilla Vacío (Lua))

No hay DLL, CMakeLists.txt ni nada que compilar: los scripts de scripts\ los carga el motor. Pulsa Ctrl+P: el cubo gira y flota con su script. (Un proyecto creado desde el editor compilado del código fuente empieza sin el Cubo ni la carpeta scripts\: la crea el primer Nuevo script....)

2. Crear objetos#

  1. Entidad > Objeto 3D > Cubo. El cubo aparece delante de la cámara del editor.
  2. Con el cubo seleccionado, pulsa W y arrastra las flechas del gizmo para moverlo. E rota y R escala.
  3. En el Inspector puedes escribir la posición, la rotación (en grados) y la escala.
  4. Añade una luz: Entidad > Luz > Luz puntual.

Para moverte por la escena, mantén pulsado el botón derecho del ratón sobre el visor Escena y usa W A S D (y Q / E para bajar y subir).

3. Darle un material#

  1. En el panel Contenido, entra en la carpeta materials (o crea una con Crear > Carpeta) y pulsa Crear > Material.
  2. El material nuevo se muestra en el Inspector. Cambia el Color base, la Rugosidad o Metálico. Los cambios se guardan solos en el fichero .mat.
  3. Arrastra el material desde Contenido hasta el cubo en el visor Escena.

4. Tu primer script#

  1. En el panel Contenido, abre la carpeta scripts y pulsa Crear > Nuevo script... (o clic derecho en la carpeta; si el proyecto no la tiene, Crear > Script... en assets o Scripts > Nuevo script...). Llámalo Saltarin: el editor crea scripts/Saltarin.luau con una plantilla.
  2. Doble clic en el fichero para abrirlo en tu editor de código (VS Code, si lo tienes) y cámbialo por esto:
Lua
-- Hace botar la entidad; con Espacio bota más alto. Los campos salen en el Inspector
local Saltarin = Script()

--[Range(0, 5), Tooltip("Metros")]
Saltarin.altura = 1
--[Range(0.1, 10), Tooltip("Botes por segundo")]
Saltarin.velocidad = 2

function Saltarin:Start()
    self._base = self.transform.position
    self._tiempo = 0
    Log.Info("Hola desde " .. self.name)
end

function Saltarin:Update(dt: number)
    self._tiempo += dt
    if Input.WasKeyPressed("Space") then
        self.altura = self.altura * 2
    end
    local bote = math.abs(math.sin(self._tiempo * self.velocidad * math.pi)) * self.altura
    self.transform.position = self._base + Vec3.new(0, bote, 0)
end

return Saltarin
  1. Guarda el fichero y arrástralo desde Contenido hasta el cubo de la Jerarquía (o al Inspector del cubo). Se le añade el componente Scripts con Saltarin, y sus campos Altura y Velocidad salen en el Inspector.
  2. Pulsa Ctrl+P: el cubo bota y la Consola dice Hola desde Cubo. Pulsa Espacio (con el panel Juego enfocado) y bota más alto.
  3. Con el juego en marcha, cambia math.abs por 0.5 + 0.5 * math.sin... o cualquier otra cosa y guarda: el editor recarga el script al momento, sin parar el juego y sin perder el estado.

Todo lo que pueden hacer los scripts (entrada, físicas, sonido, interfaz, red...) está en scripts-lua.md. El motor también trae dos scripts integrados que se añaden sin escribir código (Añadir componente > Scripts, y en él Añadir script): Rotador (gira la entidad) y Flotar (la sube y la baja).

5. Guardar y jugar#

  1. Pulsa Ctrl+S para guardar la escena. El asterisco junto al nombre de la escena (arriba a la derecha) indica cambios sin guardar.
  2. Pulsa Ctrl+P para jugar. El juego se ve desde la cámara principal en el panel Juego.
  3. Pulsa Ctrl+P otra vez para parar. Todo lo que cambie durante el juego se descarta al parar.

Solución de problemas#

Problema Causa y solución
[nova] No se encuentra Visual Studio 2022 con C++ al compilar el motor Falta Visual Studio 2022 con la carga de trabajo de C++, o está en otra ruta. Instálalo con el instalador de Visual Studio (para hacer juegos en Lua con el motor instalado no hace falta)
CMake o Ninja no se encuentran Instala el componente "Herramientas de CMake de C++ para Windows" de Visual Studio
Un error de Lua en la Consola (ERROR Lua: scripts/X.luau:12: ...) Fichero y línea del error: corrígelo y guarda (el juego sigue con la versión anterior). Errores comunes: scripts-lua.md
El script no sale al arrastrarlo o sale «Script Lua con errores o borrado» Tiene un error al cargarse (mira la Consola) o falta el return de la clase al final
El inspector muestra «Clase 'X' no cargada» en un proyecto con scripts C++ La DLL de scripts C++ no está compilada o no contiene esa clase: Compilar scripts (Ctrl+B). Los datos del script se conservan
El render va muy lento Puede estar usando WARP. La consola muestra Render: Direct3D 11 en <adaptador> (WARP) al arrancar
El juego publicado no arranca Mira el log en %LOCALAPPDATA%\<nombre del juego>\log.txt
La caja atraviesa el suelo El suelo no tiene Colisionador (el de una escena nueva ya lo trae; uno hecho a mano, no): ver fisicas.md
No se puede conectar a otra partida Ver los errores comunes de multijugador.md y servidor-dedicado.md

El editor escribe su log en %LOCALAPPDATA%\NovaEngine\editor.log.
