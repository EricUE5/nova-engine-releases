Lo recomendado es Lua. La lógica del juego se escribe normalmente en Lua (Luau): sin compilar ni instalar Visual Studio, se recarga al guardar, con los mismos componentes, el mismo Inspector y la red con atributos en comentarios. Todas las guías de esta documentación usan Lua; empieza por scripts-lua.md. Este documento es para quien necesita código nativo.

Los scripts en C++ siguen funcionando y se mezclan con los de Lua en el mismo proyecto y en la misma entidad (un script Lua lee los campos y llama a los métodos NOVA_METHOD de uno de C++ con GetScript). Merece la pena escribir una parte del juego en C++ cuando necesitas:

  • el máximo rendimiento: sistemas que recorren miles de entidades en cada frame, simulaciones pesadas, generación procedural;
  • componentes y sistemas propios (NOVA_COMPONENT, NOVA_SYSTEM), que luego también se usan desde Lua;
  • librerías externas de C o C++, o acceso al sistema, a ficheros o a una red propia (fuera del sandbox de Lua);
  • predicción propia con nova_net, o la API de Steam (lobbies, logros, overlay), que todavía no está en Lua.

Lo que cuesta: hace falta Visual Studio 2022 o sus Build Tools con C++ (instalar.md), compilar (Compilar scripts, Ctrl+B) cada vez que cambias el código, volver a compilar después de actualizar el motor, y el código nativo no tiene el aislamiento de Lua (un error grave puede cerrar el editor o el juego).

Este documento explica la clase nova::Behaviour, su ciclo de vida, cómo registrar scripts y campos, cómo está organizado el proyecto de ejemplo en C++, la entrada, el log, la interfaz con OnGUI, la recarga en caliente, cómo crear, abrir y añadir scripts desde el editor y cómo crear la DLL de un proyecto nuevo. Después, los componentes y sistemas propios, la API del motor desde C++ (físicas, audio, animación, prefabs, interfaz, red y Steam), ejemplos completos que se compilan con el motor, el tutorial multijugador en C++ y el ejemplo multijugador en C++.

Cómo funcionan los scripts#

  • Un script es una clase derivada de nova::Behaviour.
  • Los scripts del juego se compilan en una DLL (por ejemplo sample_game.dll) que enlaza la librería del motor nova_engine.
  • El editor y NovaGame.exe cargan esa DLL y le pasan su contexto del motor (ver arquitectura.md).
  • Los scripts se añaden a las entidades con el componente Scripts (nova::Script), que admite varios por entidad.
  • Sus campos reflejados se editan en el Inspector y se guardan con la escena.

Un script mínimo:

C++
#include "nova/core/Log.h"
#include "nova/platform/Input.h"
#include "nova/scripting/Behaviour.h"

class Jugador : public nova::Behaviour {
public:
    float velocidad = 4.0f;

    void OnStart() override { nova::log::Info("Hola desde {}", GetName()); }

    void OnUpdate(float dt) override
    {
        nova::Input& in = GetInput();
        GetTransform().position.x += in.GetAxis("MoverX") * velocidad * dt;
    }
};

NOVA_BEHAVIOUR(Jugador)
{
    NOVA_FIELD(velocidad).Range(0.0f, 20.0f).Tooltip("Metros por segundo");
}

Ciclo de vida#

Todas las funciones son virtuales y opcionales. Solo se llaman en modo juego, salvo OnDrawGizmos.

Función Cuándo se llama
OnCreate() Al empezar el juego (o en el primer frame, si el script se crea durante el juego). Los campos ya están cargados. Se llama aunque el script esté desactivado
OnStart() Justo antes del primer OnUpdate. Si el script está desactivado, se retrasa hasta que se active
OnFixedUpdate(float dt) En cada paso fijo (60 Hz por defecto), después de OnStart
OnUpdate(float dt) Una vez por frame
OnLateUpdate(float dt) Una vez por frame, después de la animación (ideal para cámaras)
OnDestroy() Al parar el juego, al destruir la entidad o al quitar el componente Scripts durante el juego
OnAnimationEvent(std::string_view nombre) Cuando el Animador de la misma entidad lanza un evento (al principio del frame siguiente)
OnDrawGizmos(nova::DebugDraw& dd) En cada frame del visor Escena del editor, también sin jugar. En el juego publicado no se dibuja
OnGUI() En cada frame mientras se juega, dentro del frame de ImGui: menús, marcadores, nombres. No se llama en el servidor dedicado
OnCollisionEnter(const nova::Collision& c) / OnCollisionExit(...) La entidad (con Colisionador o Controlador de personaje) empieza o deja de tocar otro cuerpo. Ver Físicas
OnTriggerEnter(nova::Entity otro) / OnTriggerExit(...) Algo entra o sale de un sensor de esta entidad, o esta entidad entra en un sensor ajeno
OnNetworkSpawn() La entidad aparece en la red (servidor: al replicarla; cliente: al recibirla, con sus campos replicados ya puestos). Si aparece desactivada, llega al activarse. Ver multijugador.md

Orden dentro de un frame: paso fijo (de 0 a N veces: red, físicas con sus avisos de choques y sensores, y OnFixedUpdate), OnUpdate de todos los scripts, animación, OnLateUpdate de todos los scripts, audio y, por último, OnGUI. Los scripts de entidades inactivas no reciben ninguna llamada.

El campo público enabled (la casilla del Inspector) desactiva OnStart, OnUpdate, OnFixedUpdate, OnLateUpdate y OnAnimationEvent.

Registrar scripts y campos#

Cada script se registra una vez con NOVA_BEHAVIOUR, normalmente al final de su .cpp. Dentro del bloque, NOVA_FIELD expone cada campo al Inspector y al guardado, y type configura el script:

C++
NOVA_BEHAVIOUR(OrbitCamera)
{
    type.Display("Cámara orbital");
    NOVA_FIELD(target).Display("Objetivo");
    NOVA_FIELD(distance).Display("Distancia").Range(0.5f, 50.0f);
}

Las opciones de los campos (.Range, .Slider, .Tooltip, .Color, .Asset, .Replicated...) y los tipos admitidos son los mismos que en los componentes: ver Opciones de NOVA_FIELD.

Dentro del mismo bloque se registran las RPCs de red del script con NOVA_RPC:

C++
NOVA_BEHAVIOUR(Jugador)
{
    NOVA_FIELD(puntos).ReadOnly().NoSerialize().Replicated().OnRep(&Jugador::OnRepPuntos);
    NOVA_RPC(Empujar, nova::RpcTarget::Server).MaxPerSecond(4.0f);
    NOVA_RPC(EfectoEmpujon, nova::RpcTarget::Multicast).Unreliable();
}

Cómo funcionan los campos replicados y las RPCs: Red y los conceptos de multijugador.md.

Reglas:

  • Los campos reflejados deben ser públicos. El estado interno (privado y sin NOVA_FIELD) no se guarda.
  • La macro recibe el nombre de la clase sin espacios de nombres. El nombre de la clase se guarda en las escenas: si la renombras, las escenas antiguas mostrarán "Clase no cargada" (sus datos se conservan).
  • Una clase que no está registrada no aparece en Añadir script.

NOVA_GAME_MODULE: una vez por DLL#

Cada DLL de scripts necesita, en un solo .cpp, el punto de entrada que usa el anfitrión para cargarla:

C++
// GameModule.cpp
#include "nova/scripting/GameModule.h"

NOVA_GAME_MODULE()

La macro exporta NovaGameLoad y NovaGameUnload. Al cargar, la DLL adopta el contexto del anfitrión y registra todos los tipos declarados con NOVA_BEHAVIOUR, NOVA_COMPONENT, NOVA_STRUCT y NOVA_SYSTEM.

En la DLL también puedes declarar componentes (NOVA_COMPONENT) y sistemas (NOVA_SYSTEM); ver Componentes y sistemas propios.

El proyecto de ejemplo (game/sample)#

Hay dos proyectos de ejemplo en C++: game/sample (un jugador: personaje, cámara, zorro y materiales), que se explica aquí, y game/multiplayer_sample (multijugador: el mismo personaje con red, cajas con físicas, NPC del servidor, menú y sonidos), que se recorre en El ejemplo multijugador en C++. El mismo ejemplo de un jugador con sus scripts en Lua es game/sample_lua.

game/
  CMakeLists.txt              NovaGame.exe y add_subdirectory(sample)
  sample/
    CMakeLists.txt            DLL sample_game y la herramienta nova_samplegen
    project.nova              "scriptModule": "sample_game"
    assets/                   escenas, materiales, modelos, prefabs, texturas, controladores
    scripts/
      GameModule.cpp          NOVA_GAME_MODULE()
      SampleScripts.h         declaraciones de los tres scripts
      ThirdPersonController.cpp
      OrbitCamera.cpp
      Wanderer.cpp
    tools/SampleGenerator.cpp generador de los assets del ejemplo

El CMakeLists.txt del ejemplo compila todos los .cpp y .h de scripts/ como una DLL que enlaza el motor:

CMake
file(GLOB SAMPLE_SCRIPTS CONFIGURE_DEPENDS ${CMAKE_CURRENT_SOURCE_DIR}/scripts/*.cpp ${CMAKE_CURRENT_SOURCE_DIR}/scripts/*.h)
add_library(sample_game SHARED ${SAMPLE_SCRIPTS})
target_link_libraries(sample_game PRIVATE nova_engine)
set_target_properties(sample_game PROPERTIES FOLDER game)
if(MSVC)
  target_compile_options(sample_game PRIVATE /W4)
endif()

Como usa file(GLOB ... CONFIGURE_DEPENDS) y tools\build.cmd vuelve a configurar CMake en cada compilación, los ficheros nuevos de scripts/ se compilan sin tocar el CMakeLists.txt.

La DLL queda en build\<preset>\bin\sample_game.dll, junto a NovaEditor.exe y NovaGame.exe, que la buscan ahí con el nombre indicado en scriptModule de project.nova.

nova_samplegen <carpeta del proyecto> regenera las texturas, materiales, controladores, el prefab y la escena del ejemplo. Solo hace falta si quieres volver a generarlos; su código es también un ejemplo de cómo construir escenas desde C++.

Entrada#

GetInput() devuelve el nova::Input del motor (nova/platform/Input.h). Hay dos formas de leerlo.

Acciones y ejes por nombre (recomendado)#

Las acciones son botones y los ejes son valores continuos. Se configuran por proyecto en Editar > Ajustes del proyecto > Controles (se guardan en project.nova), así que el jugador o el diseñador pueden cambiar los controles sin tocar el código. El mapa por defecto (MoverX, MoverY, MirarX, MirarY, Zoom, Saltar, Correr, Accion, Disparar y Pausa) y el formato de project.nova están en editor.md.

C++
nova::Input& in = GetInput();
if (in.WasActionPressed("Saltar")) { /* acaba de pulsarse */ }
if (in.IsActionDown("Correr")) { /* mantenida */ }
if (in.WasActionReleased("Disparar")) { /* acaba de soltarse */ }
const nova::Vec2 mover{in.GetAxis("MoverX"), in.GetAxis("MoverY")};

Consultas directas#

C++
using namespace nova;
Input& in = GetInput();

if (in.IsKeyDown(Key::W)) { }                 // mantenida
if (in.WasKeyPressed(Key::Space)) { }         // pulsada este frame
if (in.WasKeyReleased(Key::LeftShift)) { }    // soltada este frame
if (in.WasMousePressed(MouseButton::Left)) { }
const Vec2 pos = in.MousePosition();          // píxeles dentro de la ventana
const Vec2 delta = in.MouseDelta();           // movimiento raw de este frame
const float rueda = in.MouseWheel();

if (in.IsGamepadConnected(0)) {
    const float lx = in.GetGamepadAxis(GamepadAxis::LeftX, 0);
    if (in.WasGamepadPressed(GamepadButton::A, 0)) { }
    in.SetGamepadVibration(0.3f, 0.6f, 0);    // motores grave y agudo, 0..1
}

in.SetCursorLocked(true);                     // oculta y bloquea el cursor (cámaras)
  • Se admiten hasta 4 mandos XInput (índices 0 a 3). Los sticks tienen una zona muerta de 0,24 y los gatillos de 0,12.
  • Las teclas siguen los códigos de tecla virtual de Windows (nova::Key).
  • En el editor la entrada solo llega al juego mientras el panel Juego tiene el foco. Esc libera el cursor bloqueado.

Log#

C++
#include "nova/core/Log.h"

nova::log::Info("Cargando {} modelos", cantidad);
nova::log::Warn("Textura no encontrada: {}", ruta);
nova::log::Error("Vida negativa en {}: {:.2f}", GetName(), vida);
nova::log::Debug("Valor: {}", x);
nova::log::Trace("Detalle: {}", y);

Las funciones usan la sintaxis de std::format; la cadena de formato debe ser un literal (para un texto variable escribe nova::log::Info("{}", texto)). Los mensajes aparecen en la Consola del editor, en la consola del depurador y en el fichero de log (%LOCALAPPDATA%\NovaEngine\editor.log en el editor, %LOCALAPPDATA%\<nombre del juego>\log.txt en el juego y %LOCALAPPDATA%\<nombre del juego>\servidor.log en el servidor dedicado).

Interfaz en el juego (OnGUI)#

Para el HUD y los menús que verá el jugador, lo normal es la interfaz visual: se diseña en el panel Interfaz del editor, se adapta a cualquier resolución, funciona con mando y los scripts solo ponen los datos (UI("HUD/Vida/Barra").SetValue(vida); ver Interfaz e interfaz-ui.md). OnGUI sigue sirviendo para depurar y para menús rápidos, y se dibuja encima.

OnGUI() dibuja con Dear ImGui encima de la vista del juego (el panel Juego del editor o la ventana de NovaGame.exe). La DLL del juego comparte el contexto de ImGui del anfitrión, así que basta con incluir imgui.h:

C++
// Contador en pantalla con ImGui.
#include "nova/core/Context.h"
#include "nova/scripting/Behaviour.h"

#include "imgui.h"

class ContadorDeMonedas : public nova::Behaviour {
public:
    nova::i32 monedas = 0;

    void OnGUI() override
    {
        const nova::GameViewInfo& vista = nova::Ctx().gameView; // rectangulo de la vista del juego en pixeles
        ImGui::SetNextWindowPos(ImVec2(vista.x + 10.0f, vista.y + 10.0f));
        ImGui::Begin("Monedas", nullptr, ImGuiWindowFlags_AlwaysAutoResize | ImGuiWindowFlags_NoSavedSettings);
        ImGui::Text("Monedas: %d", monedas);
        if (ImGui::Button("Salir")) nova::RequestQuit();
        ImGui::End();
    }
};

NOVA_BEHAVIOUR(ContadorDeMonedas)
{
    NOVA_FIELD(monedas).Display("Monedas");
}
  • Coloca las ventanas respecto a Ctx().gameView: en el editor la vista del juego no ocupa toda la ventana.
  • nova::WorldToGameView(escena, puntoDelMundo, pantalla) (nova/scene/Components.h) proyecta un punto del mundo a la vista: nombres y marcadores sobre los objetos.
  • Mientras el ratón está sobre una ventana de ImGui o se escribe en un campo, NovaGame.exe no pasa la entrada al juego.
  • nova::RequestQuit() cierra NovaGame.exe al acabar el frame (en el editor no hace nada).
  • El menú de un juego multijugador (crear partida, unirse, desconectar) se explica en Red.

Recarga en caliente en el editor#

  1. Edita el código y pulsa Compilar scripts (Ctrl+B; el botón y el menú solo están activos en los proyectos con módulo de scripts C++). El editor ejecuta en segundo plano tools\build.cmd <preset> <target>, con el mismo preset con el que se compiló el editor (por ejemplo debug) y el target del proyecto (scriptTarget de project.nova o, si está vacío, scriptModule). La salida aparece en la Consola.
  2. El editor vigila la DLL original. Cuando cambia (y su fecha lleva medio segundo estable):
    • guarda en JSON la escena de edición y, si estás jugando, la de juego;
    • detiene el juego, vacía las escenas y destruye sus sistemas;
    • descarga la DLL anterior, con lo que se quitan sus tipos y sistemas;
    • carga la nueva y restaura las escenas desde el JSON;
    • si estabas jugando, vuelve a arrancar el juego (se llaman otra vez OnCreate y OnStart). Las entidades de red creadas durante la partida (personajes, objetos de Spawn) no se guardan: el servidor las vuelve a crear al arrancar, sin duplicarlas.
  3. Los campos reflejados de los scripts se conservan. El estado no reflejado (miembros privados, punteros, contadores internos) se pierde. Los campos guardados que la DLL cargada no conoce (por ejemplo, uno que quitaste o que aún no has compilado) tampoco se borran al guardar: siguen en la escena y vuelven a aplicarse cuando la clase los tenga.

También puedes compilar desde una terminal mientras el editor está abierto (tools\build.cmd debug sample_game): el editor detecta la DLL nueva igual.

El editor carga una copia de la DLL (en %TEMP%\NovaEngine\modules\<id del proceso>\), así que el enlazador puede sobrescribir la original aunque esté en uso. Scripts > Recargar scripts fuerza la recarga.

Notas:

  • Desde el código fuente, la compilación desde el editor solo está disponible en compilaciones de desarrollo (debug y release). Con el motor instalado, Compilar scripts ejecuta NovaBuild.exe, que compila con el SDK instalado y deja la DLL en <proyecto>/bin (ver instalar.md).
  • Compila siempre la DLL con el mismo preset que el editor que la carga: las compilaciones debug y release usan runtimes de C++ distintos. El editor y NovaGame.exe rechazan, con un mensaje en la consola, una DLL compilada para otra versión del motor u otro runtime.
  • Si cambias código del propio motor (engine/), hay que recompilar y reiniciar el editor.
  • En una sesión de edición en equipo los scripts se sincronizan como ficheros y cada PC compila su propia DLL. Mientras la tuya está desactualizada, los campos de los componentes Script quedan en solo lectura. Los scripts no deben cambiar datos de la escena en modo edición: cada PC lo haría por su cuenta y las escenas se desincronizarían.

Crear y abrir scripts desde el editor#

El panel Contenido muestra, debajo de assets, la carpeta scripts del proyecto (<proyecto>/scripts, fuera de assets/) con sus subcarpetas. Es la misma carpeta que compila Compilar scripts: tools\build.cmd en los ejemplos del código fuente (game/sample/scripts y game/multiplayer_sample/scripts) y NovaBuild.exe en los proyectos creados con Nova Hub y el motor instalado.

  • Los .cpp y los .h tienen su propio icono y color, con la extensión en la esquina. Buscar encuentra también los scripts, en todas las subcarpetas.
  • Doble clic en un script: se abre en el editor de código (ver Editor de código).
  • Clic derecho en un script: Abrir en el editor de código, Mostrar en el Explorador, Copiar ruta, Renombrar... y Eliminar (a la papelera)....
  • Después de renombrar o eliminar un script hay que volver a compilar (Ctrl+B). Antes de eliminar, el diálogo dice qué scripts contiene el fichero y cuántas veces los usa la escena abierta: esas entidades mostrarán "Clase no cargada" (sus datos se conservan). Renombrar el fichero no cambia el nombre de la clase, y si otro fichero lo incluye (#include) hay que cambiar también ese #include.
  • Si el fichero (o la carpeta) tiene el único NOVA_GAME_MODULE() del proyecto, el diálogo avisa en rojo: sin él la DLL de scripts no se puede cargar y no funciona ningún script. Nuevo script C++ (avanzado)... vuelve a crear GameModule.cpp si falta.
  • Eliminar nunca borra para siempre sin preguntar: si la unidad no tiene papelera de reciclaje (una unidad de red, algunos pendrives), no se borra nada y otro diálogo pregunta si quieres Borrar para siempre.
  • Los ficheros de código que sueltes desde el Explorador de Windows con la carpeta scripts abierta se copian ahí (no se importan como assets). Si ya hay uno con ese nombre, no se sustituye: la barra de estado dice cuáles se han quedado sin copiar.
  • Las subcarpetas de scripts/ no se compilan: los CMakeLists.txt de los proyectos usan scripts/*.cpp. Sirven para cabeceras (#include "ia/Enemigo.h") o para guardar código que no se usa. Si sueltas un .cpp en una subcarpeta, o arrastras a una entidad un script que está en una, el editor lo avisa: muévelo a scripts/.

Nuevo script C++#

Crear > Nuevo script C++ (avanzado)... (con la carpeta scripts abierta), el clic derecho en esa carpeta (o en el fondo de la rejilla) o Scripts > Nuevo script C++ (avanzado)... piden el nombre de la clase, que también es el nombre del fichero (Nuevo script..., sin más, crea un script Lua):

  • Tiene que ser un identificador de C++: empieza por una letra y solo lleva letras sin tildes, números y _ (sin espacios ni ñ), sin __ seguidos y sin palabras reservadas.
  • No puede empezar por NOVA_ (las macros del motor), ni llamarse como un método o miembro de nova::Behaviour (OnStart, OnUpdate, GetName, GetTransform, Destroy, Physics, enabled...) ni como los nombres que usan por dentro la plantilla y NOVA_BEHAVIOUR (velocidad, m_tiempo, dt, type, registry, builder): con esos nombres el script no compilaría.
  • Los nombres de los tipos son globales: no puede coincidir con otro script de scripts/ ni con un tipo registrado del motor o de la DLL cargada (Transform, Camera...), aunque esté en otro espacio de nombres. El diálogo lo comprueba mientras escribes y no deja crear un nombre repetido.
  • Con Crear también un .h la clase se declara en Nombre.h (para que otros scripts puedan incluirla) y se implementa en Nombre.cpp.
  • El script se crea siempre en scripts/: las subcarpetas no se compilan (los CMakeLists.txt usan scripts/*.cpp).
  • Si ningún fichero de scripts/ tiene NOVA_GAME_MODULE(), se crea también GameModule.cpp. Nunca se sobrescribe ningún fichero.

Al terminar, el diálogo ofrece Compilar ahora (Ctrl+B) y Abrir en el editor de código. Esta es la plantilla para una clase PuertaAutomatica (las pruebas del motor compilan la plantilla con /W4 /WX, cargan la DLL y juegan sus scripts):

C++
// PuertaAutomatica: script del juego en C++ (clase derivada de nova::Behaviour).
// Para usarlo, compila los scripts (Ctrl+B) y anadelo a una entidad desde el Inspector (Scripts >
// Anadir script) o arrastrando este fichero desde el panel Contenido a la entidad.
// Guia: Ayuda > Documentacion > Scripts en C++.
#include "nova/core/Log.h"
#include "nova/scripting/Behaviour.h"

class PuertaAutomatica : public nova::Behaviour {
public:
    // Campos publicos: se registran abajo con NOVA_FIELD
    float velocidad = 1.0f;

    void OnStart() override
    {
        nova::log::Info("PuertaAutomatica listo en '{}'", GetName());
    }

    void OnUpdate(float dt) override
    {
        m_tiempo += dt;
        // Cada frame. Por ejemplo, avanzar: GetTransform().position.z += velocidad * dt;
    }

private:
    float m_tiempo = 0.0f; // estado interno: no se guarda
};

// Registro: los campos con NOVA_FIELD salen en el Inspector y se guardan con la escena
NOVA_BEHAVIOUR(PuertaAutomatica)
{
    type.Display("PuertaAutomatica");
    NOVA_FIELD(velocidad).Display("Velocidad").Range(0.0f, 20.0f).Tooltip("Metros por segundo");
}

Añadir el script a una entidad#

Con los scripts compilados, arrastra el fichero desde Contenido a una entidad de la Jerarquía o a cualquier parte del Inspector de la entidad seleccionada: se le añade el componente Scripts (si no lo tiene) con ese script, y se puede deshacer con Ctrl+Z.

  • Si la clase aún no está en la DLL cargada (por ejemplo, un script recién creado), una ventana explica que hay que compilar primero, con el botón Compilar ahora (Ctrl+B); cuando se recarguen los scripts, vuelve a arrastrarlo. Si el fichero está en una subcarpeta de scripts/ (o no es un .cpp), la ventana explica que así no se compila y que hay que moverlo a scripts/.

Crear la DLL de un proyecto nuevo#

Con el motor instalado no hace falta nada de esto: los proyectos creados en Nova Hub con una plantilla de C++ («Vacío (C++, avanzado)» y las demás «(C++, avanzado)») ya traen scripts/ y su CMakeLists.txt, y Compilar scripts usa NovaBuild.exe con el SDK instalado (ver instalar.md). Lo que sigue es para proyectos dentro del código fuente del motor.

Un proyecto creado desde el editor (o con una plantilla de Lua) no tiene DLL de scripts (scriptModule vacío): sus scripts son Lua. Para añadirle una DLL de scripts C++:

1. Crea la carpeta de scripts#

Copia la estructura de game/sample. Si el proyecto está dentro del repositorio, por ejemplo en game/mijuego/:

game/mijuego/
  CMakeLists.txt
  project.nova
  assets/
  scripts/
    GameModule.cpp      NOVA_GAME_MODULE()
    MiScript.cpp

2. Escribe su CMakeLists.txt#

CMake
# game/mijuego/CMakeLists.txt
file(GLOB MIJUEGO_SCRIPTS CONFIGURE_DEPENDS ${CMAKE_CURRENT_SOURCE_DIR}/scripts/*.cpp ${CMAKE_CURRENT_SOURCE_DIR}/scripts/*.h)
add_library(mijuego SHARED ${MIJUEGO_SCRIPTS})
target_link_libraries(mijuego PRIVATE nova_engine)
set_target_properties(mijuego PROPERTIES FOLDER game)
if(MSVC)
  target_compile_options(mijuego PRIVATE /W4)
endif()

3. Añádelo al árbol de CMake#

En game/CMakeLists.txt, junto a add_subdirectory(sample):

CMake
add_subdirectory(mijuego)

Si el proyecto está fuera del repositorio, CMake necesita también una carpeta de compilación:

CMake
add_subdirectory("C:/Juegos/MiJuego" mijuego)

La DLL tiene que formar parte del árbol de CMake de Nova para que termine en build\<preset>\bin, junto al editor, y para que Compilar scripts la encuentre.

4. Indica el módulo en project.nova#

En Editar > Ajustes del proyecto > General, escribe mijuego en Módulo de scripts (y en Target de CMake si el target se llama distinto que la DLL). O directamente en project.nova:

JSON
"scriptModule": "mijuego",
"scriptTarget": "mijuego"

5. Compila#

Pulsa Compilar scripts (Ctrl+B) o ejecuta tools\build.cmd debug mijuego. El editor carga la DLL en cuanto aparece y tus clases salen en Añadir script.

Componentes y sistemas propios#

Los scripts Lua guardan sus datos en los campos de un script (escenas-y-componentes.md). Desde C++ se pueden declarar además componentes y sistemas de verdad, en un .cpp de la DLL del juego. Un componente de C++ sale en Añadir componente, se guarda con la escena y se usa desde Lua como los del motor (self:GetComponent("Salud").vida).

Componentes#

Un componente es un struct de datos. Se registra con NOVA_COMPONENT y cada campo con NOVA_FIELD, en un .cpp de la DLL del juego:

C++
#include "nova/core/Reflection.h"

enum class Equipo : nova::u8 { Rojo, Azul };

struct Salud {
    float vida = 100.0f;
    float maxima = 100.0f;
    bool invencible = false;
    Equipo equipo = Equipo::Rojo;
    nova::Vec3 colorBarra{0.2f, 0.9f, 0.3f};
};

NOVA_COMPONENT(Salud)
{
    type.Display("Salud").Category("Juego").Tooltip("Puntos de vida de la entidad");
    NOVA_FIELD(vida).Range(0.0f, 1000.0f).Tooltip("Vida actual").Replicated();
    NOVA_FIELD(maxima).Display("Vida máxima").Min(1.0f);
    NOVA_FIELD(invencible);
    NOVA_FIELD(equipo).Options({{"Red", "Rojo"}, {"Blue", "Azul"}}); // identificador (Lua y ficheros) y texto del Inspector
    NOVA_FIELD(colorBarra).Display("Color de la barra").Color();
}

El componente aparece en Añadir componente, se edita en el Inspector, se guarda con la escena y se copia al duplicar o al crear prefabs, sin más código.

Reglas:

  • Los campos reflejados deben ser públicos.
  • La macro recibe el nombre del tipo sin espacios de nombres (NOVA_COMPONENT(Salud), no NOVA_COMPONENT(juego::Salud)). Si el tipo está en un espacio de nombres, escribe la macro dentro de ese mismo espacio de nombres.
  • El nombre corto del tipo se guarda en los ficheros: renombrarlo rompe las escenas guardadas. No uses nombres que ya existen en el motor (Transform, Camera...), aunque estén en otro espacio de nombres.
  • El nombre del campo (vida) también se guarda en los ficheros. Usa .Display() para cambiar la etiqueta del Inspector sin tocar los ficheros. Sin .Display(), la etiqueta se genera del nombre (moveSpeed se muestra como "Move Speed").

AssetRef y EntityRef#

nova::AssetRef es una referencia a un asset por su UUID (el del .meta). Se resuelve con el AssetManager del contexto:

C++
#include "nova/assets/AssetManager.h"
#include "nova/core/Context.h"

struct Decoracion {
    nova::AssetRef modelo;
};

NOVA_COMPONENT(Decoracion)
{
    NOVA_FIELD(modelo).Asset("Model");
}

// En código:
void Ejemplo(const Decoracion& d)
{
    if (d.modelo.IsValid()) {
        std::shared_ptr<nova::Model> m = nova::Ctx().assets->GetModel(d.modelo.id);
        std::string ruta = nova::Ctx().assets->PathOf(d.modelo.id); // "models/Fox.glb"
    }
}

nova::EntityRef es una referencia a otra entidad por su UUID. Se convierte en manejador con FindByID:

C++
struct Seguidor {
    nova::EntityRef objetivo;
    float distancia = 3.0f;
};

// Dentro de un sistema o script:
const nova::Entity obj = scene.FindByID(seguidor.objetivo.id);
if (scene.IsValid(obj)) {
    const nova::Vec3 p = scene.GetWorldPosition(obj);
}

Las EntityRef se reasignan solas al duplicar entidades y al instanciar prefabs: si la referencia apunta a una entidad que se copia en la misma operación, pasa a apuntar a la copia. Las que apuntan fuera se mantienen.

Sistemas propios#

Cuando una lógica afecta a muchas entidades con los mismos componentes, un sistema es más simple y rápido que un script por entidad. Ejemplo completo con su componente:

C++
#include "nova/core/Reflection.h"
#include "nova/scene/Scene.h"
#include "nova/scene/System.h"

struct Giro {
    float velocidad = 90.0f; // grados por segundo
};

NOVA_COMPONENT(Giro)
{
    type.Display("Giro");
    NOVA_FIELD(velocidad).Range(-720.0f, 720.0f).Tooltip("Grados por segundo");
}

class GiroSystem : public nova::System {
public:
    void OnUpdate(nova::Scene& scene, float dt) override
    {
        scene.Each<Giro, nova::Transform>([&](nova::Entity e, Giro& g, nova::Transform& t) {
            if (!scene.IsActive(e)) return;
            const nova::Quat paso = nova::Quat::FromAxisAngle({0, 1, 0}, nova::Radians(g.velocidad) * dt);
            t.rotation = nova::Normalize(paso * t.rotation);
        });
    }
};

NOVA_SYSTEM(GiroSystem, 50, nova::SystemFlag_None);
  • El segundo argumento de NOVA_SYSTEM es el orden: menor se ejecuta antes. Los sistemas del motor usan red -1000, físicas -100, scripts 0, animación 100 y audio 200, así que 50 va entre los scripts y la animación.
  • El tercero son las flags. Con nova::SystemFlag_EditMode, OnUpdate y OnLateUpdate se ejecutan también en el editor sin pulsar Play.
  • Cada escena crea su propia instancia del sistema. Puedes guardar estado en la clase.
  • OnFixedUpdate se ejecuta a paso fijo (60 Hz por defecto), OnLateUpdate después de la animación, OnPlayStart / OnPlayStop al empezar y terminar el juego, OnDebugDraw en el visor Escena del editor y OnGUI dentro del frame de ImGui del juego (interfaz; no en el servidor dedicado).
  • Un sistema puede publicar una interfaz para los scripts con scene.SetService<Interfaz>(puntero) (así lo hacen las físicas, el audio y la red); se lee con scene.GetService<Interfaz>().

Iterar con Each#

C++
scene.Each<nova::PointLight>([](nova::Entity, nova::PointLight& luz) {
    luz.intensity *= 0.5f;
});

scene.Each<nova::MeshRenderer, nova::Transform>(
    [&](nova::Entity e, nova::MeshRenderer& mr, nova::Transform& t) {
        if (!scene.IsActive(e)) return;
        mr.castShadows = t.position.y > 0.0f;
    });
  • Each recorre el almacén del primer tipo y comprueba que la entidad tenga los demás. Pon primero el componente más escaso: Each<Giro, Transform> es mucho más rápido que Each<Transform, Giro>.
  • Recorre también las entidades inactivas; usa scene.IsActive(e) si debes saltarlas.
  • Dentro del bucle no añadas ni quites componentes de los tipos que recorres. Para destruir entidades usa scene.DestroyDeferred(e).
  • No guardes punteros a componentes entre frames: guarda la Entity o un EntityRef.

La escena desde C++#

Una escena (nova::Scene) es una lista de entidades. En C++ cada una es un manejador nova::Entity (índice

  • generación), que deja de ser válido cuando la entidad se destruye, y un UUID estable de 64 bits (scene.GetID(e)). El Transform es un struct con position, rotation (Quat) y scale. Los detalles internos (generaciones, almacenes de componentes) están en arquitectura.md.

Físicas#

El Controlador de personaje se maneja escribiendo su entrada desde un script; se aplica en el siguiente paso fijo:

C++
auto* cc = TryGetComponent<nova::CharacterController>();
cc->Move(direccion, correr);   // direccion horizontal en el mundo, longitud 0..1 (no se acumula: se sustituye)
cc->Face(guinada);             // radianes; 0 = mirando hacia +Z (como los modelos glTF)
cc->Jump();                    // salta en el siguiente paso fijo si esta en el suelo

Choques y sensores en los scripts#

Los scripts de una entidad con cuerpo (o con Controlador de personaje) reciben:

C++
void OnCollisionEnter(const nova::Collision& c) override;  // empieza a tocar otro cuerpo
void OnCollisionExit(const nova::Collision& c) override;   // deja de tocarlo
void OnTriggerEnter(nova::Entity otro) override;           // entra en un sensor (o algo entra en el mio)
void OnTriggerExit(nova::Entity otro) override;
Campo de Collision Qué es
other La otra entidad
point Punto de contacto en el mundo (cero en Exit)
normal Normal desde esta entidad hacia la otra (cero en Exit)
impulse Impulso estimado del choque en N·s: útil para el volumen de un golpe o el daño por caída
relativeSpeed Velocidad de acercamiento en m/s
  • Los dos cuerpos reciben el aviso (cada uno con la otra entidad en other y la normal hacia el otro).
  • Con los sensores, también los dos: el sensor recibe OnTriggerEnter(objeto) y el objeto que entra recibe OnTriggerEnter(sensor).
  • Se llaman en el paso fijo, después de simular, solo en scripts activos. Puedes destruir entidades dentro (Destroy).
  • Un objeto que se duerme apoyado no genera OnCollisionExit.
  • En multijugador, los avisos llegan en todas las máquinas que simulan: la lógica (dar puntos, quitar vida) va dentro de if (IsServer()).

Consultas y fuerzas: Physics()#

Physics() devuelve el IPhysicsScene de la escena (nova/physics/PhysicsScene.h). Fuera del modo juego, o en una escena sin físicas, es una implementación vacía: las consultas no tocan nada y el resto no hace nada.

Función Qué hace
Raycast(origen, dir, distancia, hit, filtro) Rayo: el impacto más cercano (RaycastHit: entity, point, normal, distance). También Raycast(...) directamente en el script
RaycastAll(origen, dir, distancia, hits, filtro) Todos los impactos, ordenados por distancia
SphereCast(radio, origen, dir, distancia, hit, filtro) Esfera lanzada: balas gruesas, «¿cabe por aquí?», cámaras que no atraviesan paredes
OverlapSphere(centro, radio, entidades, filtro) Entidades que tocan una esfera (explosiones, empujones)
OverlapBox(centro, mediasMedidas, rotacion, entidades, filtro) Lo mismo con una caja
AddForce(e, N), AddImpulse(e, N·s), AddImpulseAtPoint(e, impulso, punto), AddTorque(e, par) Fuerzas sobre cuerpos dinámicos (en los demás no hacen nada)
GetVelocity(e), SetVelocity(e, v), GetAngularVelocity(e), SetAngularVelocity(e, w) Velocidad de un cuerpo dinámico (o de un personaje)
Teleport(e, pos, rot) Mueve un cuerpo o personaje al instante, sin interpolar
IsSleeping(e), WakeUp(e), HasBody(e) Cuerpos dormidos (los quietos no gastan CPU)

El filtro (nova::PhysicsQuery) tiene layers (máscara de capas con PhysicsLayer::Bit(...), por defecto todas), ignore (una entidad a ignorar, por ejemplo la que dispara) y hitTriggers (incluir sensores; por defecto no):

C++
nova::PhysicsQuery q;
q.layers = nova::PhysicsLayer::Bit(nova::PhysicsLayer::Static) | nova::PhysicsLayer::Bit(nova::PhysicsLayer::Dynamic);
q.ignore = GetEntity();
nova::RaycastHit hit;
if (Physics().Raycast(origen, direccion, 50.0f, hit, q)) {
    nova::log::Info("Toca {} a {:.1f} m", GetScene().GetName(hit.entity), hit.distance);
}

Las constantes de capa son PhysicsLayer::Static, Dynamic, Player, Trigger y Debris.

La posición real del último paso fijo de un cuerpo (el Transform está interpolado) es Physics().GetBodyPose(e, pos, rot). Escribir el Transform de un cuerpo dinámico o de un personaje lo teletransporta; Physics().Teleport lo hace de forma explícita y, en red, Network().Teleport(GetScene(), e, pos, rot) avisa además a los clientes.

Disparos con compensación de latencia. Las cajas de impacto (nova::Hitbox, nova/physics/Hitbox.h) y el rebobinado del servidor están en nova/physics/LagCompensation.h: nova::RaycastRewind(GetScene(), origen, dir, distancia, Network().RpcCaller(), impacto, opciones) dentro de una RPC de servidor (con opciones.viewTime, la Network().ViewTime() que envía el cliente con el disparo), nova::RaycastHitboxes sin rebobinar, nova::RewindSecondsFor y nova::ValidateShotOrigin. impacto es un nova::HitboxHit (entity, hitbox, point, normal, distance, part, damageMultiplier, isHitbox). Funcionan igual que desde Lua: multijugador.md.

Audio#

Audio() devuelve el IAudioScene de la escena (nova/audio/AudioScene.h). En un servidor dedicado, sin motor de audio o fuera del modo juego es una implementación vacía: el código del juego puede llamarla siempre.

PlayOneShot2D(sonido, volumen = 1, tono = 1, bus = Ui) Sonido 2D de un solo uso (interfaz, avisos)

C++
// Un paso en los pies del personaje, con algo de variacion en el tono
Audio().PlayOneShot(sonidoPaso, GetScene().GetWorldPosition(GetEntity()), 0.6f, 0.9f + 0.2f * aleatorio01);
// Un clic de interfaz
Audio().PlayOneShot2D(sonidoClic);

Función Qué hace

Prefabs#

Instantiate(prefab, posicion, padre = {}) instancia un prefab (nova::AssetRef, normalmente un campo registrado con .Asset("Prefab")) en esa posición del mundo y devuelve la raíz (o una entidad nula). Los scripts de las entidades creadas reciben OnCreate y OnStart en su primer frame. Desde código del motor o de un sistema, la función equivalente es nova::InstantiatePrefab(scene, json, padre, AssetRef) (scene/SceneSerializer.h), con el JSON que devuelve Ctx().assets->GetPrefab(id).

Interfaz#

Desde cualquier Behaviour (incluye nova/scripting/Behaviour.h):

UI("HUD/Vida/Barra").SetValue(75.0f);              // barra, deslizador, interruptor (> 0,5) o desplegable (índice)
UI("HUD/Munición/Cantidad").SetText("12 / 90");    // texto, campo de texto o el texto de un botón
UI("HUD/Aviso").Show();                            // pantallas: con su transición; lo demás: activar
UI("MenúPausa").Toggle();
UI("Tienda/Comprar").SetInteractable(dinero >= precio);
UI("HUD/Vida").SetColor({1, 0, 0, 1});             // imagen o texto
UI("Inventario/Ventana/Detalles/Icono").SetSprite(FindAsset("sprites/espada.png"));
UI("Tienda").SetPosition({0, -40}).SetSize({600, 400});

// Lo que pasó este frame (sondeo)
if (UI("Menú/Botones/Jugar").WasClicked()) Empezar();
if (UI("Opciones/Ventana/Volumen").ValueChanged()) volumen = UI("Opciones/Ventana/Volumen").GetValue();

  • Las funciones que cambian datos escriben en los componentes. Lo que necesita estado de la partida (transiciones, foco, sondeo, oyentes, tweens) solo funciona jugando; en el editor sin jugar y en el servidor dedicado no hace nada.
  • Los oyentes que añade un script con UI("...") son suyos: se quitan solos cuando se destruye el script (el personaje muere o la red lo quita), así que capturar this es seguro. Un ui::Element creado a mano (ui::Element(&GetScene(), id)) no tiene dueño: quita sus oyentes en OnDestroy o usa .OwnedBy(this).
  • Una pantalla que muestras desde un script (Show()) sale ya ese mismo frame con su transición (y sus animaciones «al mostrarse» en su primer valor): no se ve entera un instante.
  • OnShow y OnHide avisan cuando el elemento pasa a verse o deja de verse por lo que sea: Show() y Hide(), una acción del inspector, SetActive, su padre o su pantalla. Una pantalla con transición avisa al empezar a mostrarse o a ocultarse (no al terminar el fundido). Lo que se ve al añadir el oyente no cuenta como cambio.
  • ShowDialog usa los botones que hay en el «Botones» del diálogo (dos en el de la paleta: duplica uno para tener más) y oculta los que sobran. El botón pulsado llega con su índice (desde 0) y su texto; un clic fuera (con Cerrar al pulsar fuera) llega como -1.
  • Para que un botón llame a un método desde el inspector, regístralo con NOVA_METHOD(Metodo) dentro de NOVA_BEHAVIOUR. Un enlace solo puede llamar a métodos sin argumentos o con uno de tipo bool, entero, enum, float o std::string: el Valor del evento (o el valor Fijo) se convierte a ese tipo. Los métodos con más argumentos o con otros tipos (Vec2...) salen en la lista pero no se pueden elegir; llámalos desde un método de un argumento o con un oyente.
  • La API completa está comentada en nova/ui/UiScene.h. Lo que hace cada widget y cada evento está en interfaz-ui.md.

En los eventos con arrastrar y soltar, la carga de C++ es un ui::UiPayload (ui::UiPayload::Int(id, "objeto"), Text y Number); On(ui::UiEventType::DragEnter, ...) sirve para cualquier tipo de evento.

Los conceptos (servidor autoritativo, replicación, dueño, predicción) y los componentes de red están en multijugador.md. En C++, un campo se replica con .Replicated() en su NOVA_FIELD y una RPC es un método void registrado con NOVA_RPC. Estas funciones de nova::Behaviour deciden qué parte le toca a cada máquina (igual que en Lua):

IsOwner() nunca (no hay dueños) si la entidad es del jugador local si es de este jugador nunca
IsLocalPlayer() nunca si es el personaje del jugador local si es su personaje nunca

IsHost(), IsDedicatedServer() Anfitrión u Offline; servidor dedicado

Campos replicados#

Cualquier campo reflejado de un componente o de un script puede replicarse:

C++
NOVA_FIELD(vida).Range(0.0f, 100.0f).Step(0.1f).Replicated();                    // todos
NOVA_FIELD(municion).Replicated(nova::RepCondition::OwnerOnly);                  // solo el dueño
NOVA_FIELD(apuntando).Replicated(nova::RepCondition::SkipOwner);                 // todos menos el dueño
NOVA_FIELD(puntos).Replicated().OnRep(&Jugador::OnRepPuntos);                    // con aviso al llegar
Condición Quién lo recibe Ejemplos
RepCondition::All (por defecto) Todos los que tienen la entidad Vida, puntos, equipo, nombre
RepCondition::OwnerOnly Solo el dueño de la entidad Munición, inventario, cargas, objetivos secretos
RepCondition::SkipOwner Todos menos el dueño Lo que el dueño ya calcula o predice (CharacterController::grounded)

En las máquinas que no lo reciben, un campo OwnerOnly (o uno SkipOwner en la del dueño) conserva su valor local: el del prefab o la escena al aparecer la entidad, o el que le ponga el script de esa máquina. En el tutorial, Beto ve siempre las cargas de Ana con el valor del prefab (3): no uses ese valor para nada.

OnRep. .OnRep(&Clase::Metodo) llama a un método sin argumentos (del mismo componente o script) cuando llega un valor nuevo:

  • solo en los clientes: el servidor (y el anfitrión, que es servidor) no lo recibe, porque el valor nace ahí. Si el anfitrión necesita el mismo efecto, llama al método a mano tras cambiar el valor (como SumarPuntos en el tutorial);
  • también con los valores iniciales: al aparecer la entidad en un cliente se llama para cada campo cuyo valor recibido es distinto del local (el del prefab o la escena). OnNetworkSpawn() llega antes, con todos los campos ya puestos;
  • se llama durante el paso fijo, después de aplicar todos los campos de ese tick y antes del OnFixedUpdate de los scripts. Dentro de un OnRep se pueden destruir entidades, añadir componentes, desconectar o parar la escena: la desconexión y la parada se aplican al terminar el tick de red.

Tipos admitidos y cómo viajan:

Tipo En la red
bool 1 bit
i32, u32 Con .Range(min, max): solo los bits necesarios. Sin rango: entero de 64 bits comprimido
float Con .Range(min, max): cuantizado con precisión .Step(x) o, sin Step, (max - min) / 4096. Sin rango: los 32 bits
u64, AssetRef, EntityRef 64 bits
enum con .Options(...) Solo los bits necesarios
Vec2, Vec3 Precisión de 1 mm
Quat Comprimido (14 bits por componente)
std::string Hasta 256 bytes
Vec4, structs y std::vector No se replican (aviso en el log): usa varios campos o una RPC

Reglas:

  • Solo el servidor cambia los campos replicados. Si un cliente cambia uno, el cambio se queda en esa máquina hasta que el servidor envía un valor nuevo; para pedir un cambio, usa una RPC Server.
  • Ojo con el rango de los float: .Range(0, 1000) sin Step da una precisión de ~0,24. Añade .Step(0.01f) si necesitas más.
  • Con .Range(min, max), un valor fuera del rango llega recortado a los clientes (el rango del inspector es también el de la red): usa un rango que cubra todos los valores que puede tomar el campo.
  • Los componentes y scripts de una entidad de red se fijan al crearla: un script añadido a la entidad después de que aparezca en la red no replica sus campos.
  • Un EntityRef replicado (o como argumento de una RPC) vale en todas las máquinas: los objetos del mapa tienen el mismo UUID en todas, y los creados en partida desde un prefab se crean en los clientes con el UUID del servidor (abajo).
  • Una entidad de red desactivada también está en la red: el servidor replica su estado activo y OnNetworkSpawn le llega cuando se activa.
  • Cada campo replicado forma parte del esquema de red: añadir, quitar o cambiar el tipo o el rango de uno hace incompatibles las versiones del juego (multijugador.md).

RPCs#

Una RPC es un método void de un script, registrado con NOVA_RPC dentro de NOVA_BEHAVIOUR, que se llama con CallRpc("Nombre", argumentos...):

C++
NOVA_BEHAVIOUR(Torreta)
{
    NOVA_RPC(Disparar, nova::RpcTarget::Server).MaxPerSecond(10.0f);  // el dueño pide disparar
    NOVA_RPC(Retroceso, nova::RpcTarget::Owner);                      // el servidor avisa al dueño
    NOVA_RPC(Fogonazo, nova::RpcTarget::Multicast).Unreliable();      // efecto para todos
    NOVA_RPC(Pulsar, nova::RpcTarget::Server).AnyCaller();            // cualquiera puede pulsarlo
}

Opciones:

Opción Efecto
.Unreliable() Sin garantía de entrega (efectos que pueden perderse). Por defecto son fiables y ordenadas
.AnyCaller() Server: cualquier cliente puede llamarla, aunque no sea dueño de la entidad (botones, puertas del mapa). Sin ella, el servidor descarta las llamadas de quien no es el dueño
.MaxPerSecond(n) Server: llamadas por segundo permitidas a cada cliente; las demás se descartan (0 = el límite global, 60)

Dónde se ejecuta cada una:

Llamada desde Server Owner Multicast
Cliente Viaja al servidor No permitido (aviso en el log) No permitido (aviso en el log)
Anfitrión / Offline En el acto, en esta máquina En el cliente dueño (o aquí si el dueño es el jugador local) Aquí y en todos los clientes
Servidor dedicado En el acto, en el servidor En el cliente dueño En el servidor y en todos los clientes
Sin sesión (None) Aquí Aquí Aquí
  • Dentro de una RPC Server, Network().RpcCaller() dice qué jugador la llamó.
  • Una RPC Owner de una entidad del servidor (dueño 0) no llega a nadie.
  • Una Multicast también se ejecuta en el propio servidor, sea anfitrión o dedicado (en el dedicado no suena nada: Audio() no hace nada allí). Aun así, la lógica de la partida queda más clara en el código del servidor que la llama; deja la Multicast para efectos (sonidos, partículas, mensajes).
  • La entidad debe estar en la red (Identidad de red). Si no lo está, en el servidor la RPC se ejecuta solo allí y en un cliente no se envía (CallRpc devuelve false).

Argumentos. Admitidos: bool, enteros, enums, float (sin NaN ni infinitos), Vec2, Vec3, Vec4, Quat, std::string (hasta 1024 bytes), EntityRef y AssetRef. El receptor valida el tamaño y el formato: si algo no cuadra, la llamada se descarta con un aviso en el registro (como mucho uno cada 2 s), y el servidor expulsa al cliente que envía 30 llamadas así. Para tipos propios, especializa nova::RpcArg<T> con Write y Read (ver nova/core/ByteStream.h).

CallRpc compara los argumentos con los parámetros del método y los convierte cuando se puede:

C++
void Curar(float cantidad);   // la RPC espera un float
CallRpc("Curar", 10.0f);       // bien
CallRpc("Curar", 10);          // bien: el int se convierte a float
CallRpc("Saludar", "hola");    // bien: el literal se convierte a std::string
CallRpc("Curar", "diez");      // no se envía: devuelve false y lo dice en el registro

Conversiones: entre números (un float a un entero solo si no tiene decimales, y siempre que quepa: 300 no cabe en un u8), de enteros a enums y de textos ("...", std::string_view) a std::string. Si el número de argumentos o algún tipo no encaja, CallRpc devuelve false sin enviar nada y escribe en el registro, por ejemplo, CallRpc: Jugador.Curar espera (f32) y se llamó con (string). Los tipos de los parámetros forman parte del esquema de red (multijugador.md).

El personaje de un jugador se predice igual que desde Lua: escribe su entrada con cc->Move, cc->Face y cc->Jump (TryGetComponent<nova::CharacterController>()) solo en la máquina del dueño (IsLocalPlayer()).

Crear y destruir objetos en partida#

Crear (siempre en el servidor):

C++
// Instancia el prefab, le pone Identidad de red si no la tiene y lo replica. El ultimo argumento es el
// dueno (0 = el servidor; el id de un jugador si debe poder enviar RPCs Server de ese objeto).
const nova::Entity bala = Network().Spawn(GetScene(), prefabBala, origen, rotacion, Network().RpcCaller());

Instantiate(prefab, posicion) en el servidor también vale: el servidor replica sola cualquier entidad nueva con Identidad de red al siguiente paso fijo, aunque ya esté desactivada (se replica su estado activo: sirve para reservas de objetos). Requisitos:

  • el objeto debe salir de un prefab (los clientes lo crean con él). Una entidad hecha a mano en partida no se puede replicar (aviso: «se creó durante la partida y no tiene prefab»);
  • el prefab debe tener Transform de red, o los clientes no sabrán dónde ponerlo.

En un cliente, Spawn no hace nada (aviso en el log) y Instantiate crea un objeto solo local, útil para efectos (casquillos, chispas).

Destruir: Destroy(entidad) en el servidor la destruye en todos. En un cliente solo la destruye en esa máquina. Lo que se creó con un jugador como dueño se destruye solo cuando ese jugador sale.

Señalar objetos de red entre máquinas. Un objeto creado desde un prefab tiene el mismo UUID en todas las máquinas (el servidor envía el de la raíz y los de los hijos se derivan de él), así que un EntityRef en un campo replicado o en una RPC sirve para decir «esta caja». El netId de la Identidad de red también es el mismo en todas:

C++
// Entidad de red por su netId (0 o desconocido = entidad nula).
nova::Entity BuscarPorNetId(nova::Scene& scene, nova::u32 netId)
{
    nova::Entity encontrada;
    scene.Each<nova::NetworkIdentity>([&](nova::Entity e, nova::NetworkIdentity& id) {
        if (netId != 0 && id.netId == netId) encontrada = e;
    });
    return encontrada;
}

El menú: pedir una sesión#

El flujo del menú:

  1. NovaGame.exe sin --host, --connect ni --solo arranca la escena inicial sin sesión (modo None; salvo que el proyecto diga otra cosa en red.modoInicial): el menú lo detecta con Network().Mode() == NetworkMode::None.
  2. El menú pide una sesión: Network().RequestSession(desc) con desc.mode = Offline, Host o Client (y address para unirse).
  3. El anfitrión recarga la escena inicial y la arranca con esa sesión. En NovaGame.exe, el nombre del jugador se guarda en %LOCALAPPDATA%\<nombre del juego>\opciones.json para la próxima vez.
  4. Para volver al menú, pide una sesión con mode = NetworkMode::None. Si el servidor se cierra o expulsa al jugador, el cliente vuelve solo al menú y Network().LastError() explica por qué: se conserva en el menú y se borra al empezar otra partida (desconectarse uno mismo no cuenta como error).

En el editor, Jugar siempre arranca con una sesión (multijugador.md), así que el menú principal no aparece; para probarlo usa NovaGame.exe --project <proyecto> sin opciones de red. Desconectar desde el menú de pausa para el modo juego del editor.

OnGUI() se llama en cada frame mientras se juega (no en el servidor dedicado); Ctx().gameView da el rectángulo de la vista del juego y WorldToGameView(scene, punto, pantalla) proyecta un punto del mundo (nombres sobre los jugadores). Un menú completo está en el tutorial en C++ (MenuArena).

Steam#

Cómo se configura Steam, el App ID, el SDK y la subida del juego están en steam.md. Desde Lua solo están las direcciones steam:<SteamID64> (Network.Connect("steam:...")); los lobbies, los logros, el rich presence y el overlay se usan desde C++.

Direcciones de Steam#

En nova_net una persona de Steam es una dirección Address::custom(steamId64). En texto: steam:76561197960287930. Se usa en todas partes donde iba una IP:

C++
NetworkSessionDesc s = Network().Session();
s.mode = NetworkMode::Client;
s.address = "steam:76561197960287930"; // por Steam (sin Steam: error claro y vuelta al menú)
Network().RequestSession(s);

s.mode = NetworkMode::Host;
s.useSteam = true;                      // anfitrión por Steam (sin Steam: UDP, con aviso en el log)
Network().RequestSession(s);

Network().Transport() dice qué transporte usa la sesión (Udp, Steam, Memory o Custom), y Players() muestra la dirección de cada jugador (steam:<id> o ip:puerto). El SteamID de un jugador conectado por Steam es auténtico (lo garantiza Steam): sirve para listas de baneos.

Lobbies desde tus scripts#

Los scripts (la DLL del juego) usan siempre nova::steam::Get(scene), que devuelve el Steam del anfitrión; nunca es nulo y, sin Steam, todas las llamadas devuelven false o vacío:

C++
#include "nova/steam/SteamScene.h"

void MiMenu::OnGUI()
{
    nova::steam::Service& steam = nova::steam::Get(GetScene());
    if (!steam.IsAvailable()) return; // editor, motor sin SDK o Steam cerrado

    if (ImGui::Button("Crear partida")) {
        nova::steam::LobbyOptions o;
        o.type = nova::steam::LobbyType::FriendsOnly;
        o.maxMembers = 4;
        o.map = "Arena";
        steam.CreateLobby(o); // NovaGame.exe arranca el anfitrión cuando se cree
    }
    for (const nova::steam::LobbyInfo& l : steam.Lobbies()) {
        if (ImGui::Button(l.name.c_str())) steam.JoinLobby(l.id); // y se conecta solo
    }
}

No uses nova::steam::Current() ni nova::steam::IsAvailable() desde la DLL: la DLL lleva su propia copia de la librería y esas funciones siempre dirían "no disponible" ahí.

ThirdPersonController.cpp#

Controlador en tercera persona del personaje (CesiumMan):

  • Lee los ejes MoverX y MoverY y los convierte en una dirección relativa a la cámara. La cámara se indica con el campo camera (un EntityRef), que se resuelve con FindByID. Del vector adelante de la cámara se quita la componente vertical para moverse sobre el plano XZ.
  • Corre mientras la acción Correr está pulsada y acelera o frena de forma suave hacia la velocidad objetivo.
  • Gira el personaje con Slerp hacia la dirección deseada. Como los modelos glTF miran hacia +Z, la guiñada es atan2(x, z) y avanza en la dirección rotation.Rotate({0, 0, 1}).
  • Pasa la velocidad al Animador con SetFloat("velocidad", ...); el controlador Personaje.controller mezcla las animaciones según ese parámetro.
  • OnDrawGizmos dibuja un círculo y una flecha en el visor Escena para ver dónde mira el personaje.
C++
// Controlador en tercera persona: mueve al personaje con WASD / stick izquierdo (relativo a la
// camara), corre con Shift / LB y pasa la velocidad al Animator (parametro "velocidad").
#include "SampleScripts.h"

#include "nova/animation/Animator.h"
#include "nova/core/Log.h"
#include "nova/platform/Input.h"
#include "nova/render/DebugDraw.h"

using namespace nova;

void ThirdPersonController::OnStart()
{
    m_speed = 0.0f;
    log::Info("ThirdPersonController listo en '{}'", GetName());
}

void ThirdPersonController::OnUpdate(float dt)
{
    Input& in = GetInput();
    Vec2 move{in.GetAxis("MoverX"), in.GetAxis("MoverY")};
    const float amount = std::min(1.0f, Length(move));

    // Direccion relativa a la camara (sobre el plano XZ)
    Vec3 forward{0, 0, -1};
    Vec3 right{1, 0, 0};
    const Entity cam = GetScene().FindByID(camera.id);
    if (GetScene().IsValid(cam)) {
        const Quat camRot = GetScene().GetWorldRotation(cam);
        forward = camRot.Forward();
        forward.y = 0.0f;
        forward = Normalize(forward);
        right = Normalize(Cross(forward, Vec3::Up()));
    }
    Vec3 desired = right * move.x + forward * move.y;
    if (LengthSq(desired) > 1e-6f) desired = Normalize(desired);

    const bool running = in.IsActionDown("Correr");
    const float targetSpeed = amount * (running ? runSpeed : walkSpeed);
    // Acelerar/frenar suavemente
    const float delta = acceleration * dt;
    m_speed = m_speed < targetSpeed ? std::min(targetSpeed, m_speed + delta) : std::max(targetSpeed, m_speed - delta);

    Transform& t = GetTransform();
    if (amount > 0.1f) {
        // El modelo mira hacia +Z (glTF): guinada = atan2(x, z)
        const float yaw = std::atan2(desired.x, desired.z);
        const Quat target = Quat::FromAxisAngle({0, 1, 0}, yaw);
        t.rotation = Slerp(t.rotation, target, Saturate(turnSpeed * dt));
    }
    const Vec3 facing = t.rotation.Rotate({0, 0, 1});
    t.position += facing * (m_speed * dt);

    if (auto* anim = TryGetComponent<Animator>()) {
        anim->SetFloat("velocidad", m_speed);
    }
}

void ThirdPersonController::OnDrawGizmos(DebugDraw& dd)
{
    const Vec3 p = GetScene().GetWorldPosition(GetEntity());
    dd.Circle(p + Vec3{0, 0.02f, 0}, {0, 1, 0}, 0.4f, Color::Cyan);
    dd.Arrow(p + Vec3{0, 0.05f, 0}, p + Vec3{0, 0.05f, 0} + GetTransform().rotation.Rotate({0, 0, 0.8f}), Color::Cyan);
}

OrbitCamera.cpp#

Cámara orbital que sigue al objetivo (el campo target):

  • Usa OnLateUpdate, que se ejecuta después de que el personaje se haya movido y animado; así la cámara no va un frame por detrás.
  • Gira con el ratón mientras se mantiene el botón derecho (o siempre, si lockCursor está activo) y con el stick derecho. La rueda acerca y aleja dentro de minDistance y maxDistance.
  • pitch y yaw son campos reflejados: el ángulo de la cámara sobrevive a la recarga de scripts. m_focus no, pero se recalcula en el primer frame.
  • Suaviza el punto de mira con Lerp y se coloca detrás del objetivo: como la cámara mira hacia -Z, el desplazamiento es rot.Rotate({0, 0, distance}). Después orienta la cámara con Quat::LookRotation.
C++
// Camara orbital en tercera persona.
#include "SampleScripts.h"

#include "nova/platform/Input.h"

using namespace nova;

void OrbitCamera::OnStart()
{
    m_init = false;
    if (lockCursor) GetInput().SetCursorLocked(true);
}

void OrbitCamera::OnLateUpdate(float dt)
{
    Scene& scene = GetScene();
    const Entity tgt = scene.FindByID(target.id);
    if (!scene.IsValid(tgt)) return;

    Input& in = GetInput();
    // Mirar: raton (con el boton derecho o el cursor bloqueado) y stick derecho
    const bool mouseLook = lockCursor || in.IsMouseDown(MouseButton::Right);
    const Vec2 mouse = mouseLook ? in.MouseDelta() * 0.15f : Vec2{};
    yaw -= (mouse.x + in.GetGamepadAxis(GamepadAxis::RightX) * 120.0f * dt) * sensitivity;
    pitch -= (mouse.y - in.GetGamepadAxis(GamepadAxis::RightY) * 90.0f * dt) * sensitivity;
    pitch = Clamp(pitch, -70.0f, 20.0f);
    distance = Clamp(distance - in.MouseWheel() * 0.5f, minDistance, maxDistance);

    const Vec3 targetPos = scene.GetWorldPosition(tgt) + Vec3{0, height, 0};
    if (!m_init) {
        m_focus = targetPos;
        m_init = true;
    }
    m_focus = Lerp(m_focus, targetPos, Saturate(smoothing * dt));

    const Quat rot = Quat::FromEulerDegrees({pitch, yaw, 0.0f});
    const Vec3 offset = rot.Rotate({0, 0, distance}); // la camara mira hacia -Z: se coloca detras (+Z)
    Vec3 eye = m_focus + offset;
    eye.y = std::max(eye.y, 0.3f); // no atravesar el suelo
    scene.SetWorldPosition(GetEntity(), eye);
    scene.SetWorldRotation(GetEntity(), Quat::LookRotation(m_focus - eye));
}

Wanderer.cpp#

Paseo autónomo del zorro:

  • En OnStart calcula el centro de un círculo a la izquierda del zorro, a radius metros.
  • Alterna cuatro fases (quieto, andar, correr, andar) según los tiempos configurados y suaviza la velocidad.
  • Avanza por el círculo, orienta el zorro según la tangente y pasa la velocidad al Animador. El controlador Zorro.controller tiene un árbol de mezcla 1D con los clips Survey, Walk y Run.
  • OnDrawGizmos dibuja el círculo. Fuera del modo juego m_center aún no está calculado, así que usa la posición actual (GetScene().IsPlaying()).
C++
// Paseo autonomo: el zorro da vueltas alrededor de su punto de inicio alternando quieto, andar y
// correr. Demuestra el arbol de mezcla 1D del Animator (parametro "velocidad").
#include "SampleScripts.h"

#include "nova/animation/Animator.h"
#include "nova/render/DebugDraw.h"

using namespace nova;

void Wanderer::OnStart()
{
    const Vec3 p = GetTransform().position;
    // El centro del circulo queda a la izquierda del zorro
    const Vec3 facing = GetTransform().rotation.Rotate({0, 0, 1});
    const Vec3 left = Cross(Vec3::Up(), facing);
    m_center = p + left * radius;
    const Vec3 rel = p - m_center;
    m_angle = std::atan2(rel.x, rel.z);
    m_timer = 0.0f;
    m_phase = 0;
}

void Wanderer::OnUpdate(float dt)
{
    m_timer += dt;
    const float durations[4] = {idleTime, walkTime, runTime, walkTime * 0.5f};
    if (m_timer > durations[m_phase]) {
        m_timer = 0.0f;
        m_phase = (m_phase + 1) % 4;
    }
    const float target = m_phase == 0 ? 0.0f : (m_phase == 2 ? runSpeed : walkSpeed);
    m_speed += (target - m_speed) * Saturate(3.0f * dt);

    // Avanzar sobre el circulo (girando hacia la izquierda del zorro)
    m_angle += (m_speed / std::max(radius, 0.1f)) * dt;
    Transform& t = GetTransform();
    t.position = m_center + Vec3{std::sin(m_angle), 0.0f, std::cos(m_angle)} * radius;
    // Mirar en la direccion del movimiento (tangente)
    const Vec3 tangent{std::cos(m_angle), 0.0f, -std::sin(m_angle)};
    t.rotation = Quat::FromAxisAngle({0, 1, 0}, std::atan2(tangent.x, tangent.z));

    if (auto* anim = TryGetComponent<Animator>()) {
        anim->SetFloat("velocidad", m_speed);
    }
}

void Wanderer::OnDrawGizmos(DebugDraw& dd)
{
    const Vec3 c = GetScene().IsPlaying() ? m_center : GetTransform().position;
    dd.Circle(c + Vec3{0, 0.02f, 0}, {0, 1, 0}, radius, Color::Orange);
}

Una moneda que se recoge#

Una moneda que gira sobre sí misma y desaparece cuando el jugador se acerca. Busca al jugador por nombre con FindEntity, compara posiciones de mundo con GetWorldPosition y se destruye con Destroy.

Guárdalo como game/sample/scripts/MonedaSimple.cpp (o en la carpeta de scripts de tu proyecto):

C++
// Moneda: gira y desaparece cuando el jugador se acerca.
#include "nova/core/Log.h"
#include "nova/render/DebugDraw.h"
#include "nova/scripting/Behaviour.h"

using namespace nova;

class MonedaSimple : public Behaviour {
public:
    float velocidadGiro = 180.0f;            // grados por segundo
    float radioRecogida = 1.0f;              // metros
    std::string nombreJugador = "Personaje"; // entidad que recoge la moneda

    void OnStart() override
    {
        m_jugador = FindEntity(nombreJugador);
        if (!GetScene().IsValid(m_jugador)) {
            log::Warn("Moneda '{}': no hay ninguna entidad llamada '{}'", GetName(), nombreJugador);
        }
    }

    void OnUpdate(float dt) override
    {
        // Girar alrededor del eje Y
        Transform& t = GetTransform();
        t.rotation = Normalize(Quat::FromAxisAngle({0, 1, 0}, Radians(velocidadGiro) * dt) * t.rotation);

        // Recoger si el jugador esta cerca
        if (!GetScene().IsValid(m_jugador)) return;
        const Vec3 yo = GetScene().GetWorldPosition(GetEntity());
        const Vec3 jugador = GetScene().GetWorldPosition(m_jugador);
        if (Distance(yo, jugador) < radioRecogida) {
            log::Info("Moneda recogida: {}", GetName());
            Destroy(GetEntity());
        }
    }

    void OnDrawGizmos(DebugDraw& dd) override
    {
        dd.Sphere(GetScene().GetWorldPosition(GetEntity()), radioRecogida, Color::Yellow);
    }

private:
    Entity m_jugador; // estado interno: no se guarda
};

NOVA_BEHAVIOUR(MonedaSimple)
{
    type.Display("Moneda simple").Tooltip("Gira y desaparece cuando el jugador se acerca");
    NOVA_FIELD(velocidadGiro).Display("Velocidad de giro").Range(0.0f, 720.0f).Tooltip("Grados por segundo");
    NOVA_FIELD(radioRecogida).Display("Radio de recogida").Range(0.1f, 10.0f).Tooltip("Metros");
    NOVA_FIELD(nombreJugador).Display("Jugador").Tooltip("Nombre de la entidad del jugador");
}

Para probarla:

  1. Guarda el fichero y pulsa Compilar scripts (Ctrl+B).
  2. Crea un cilindro (Entidad > Objeto 3D > Cilindro), escálalo a 0,6 x 0,05 x 0,6, rótalo 90° en X y dale el material Oro.mat.
  3. Añádele el componente Scripts y, con Añadir script, el script Moneda simple.
  4. Pulsa Ctrl+P y lleva al personaje hasta la moneda.

Detalles:

  • FindEntity recorre las entidades por nombre: llámalo en OnStart y guarda el resultado, no en cada frame.
  • Destroy no destruye en el acto: marca la entidad y se destruye al final de la fase, así que el resto del frame sigue siendo seguro. Al destruirse se llama a OnDestroy de sus scripts.
  • La esfera amarilla de OnDrawGizmos muestra el radio de recogida en el visor Escena, también sin jugar.
  • En lugar de buscar por nombre podrías usar un campo nova::EntityRef jugador; y resolverlo con GetScene().FindByID(jugador.id), como hace ThirdPersonController con su cámara. Así el enlace no se rompe si renombras al jugador.
  • Para crear monedas desde código, haz un prefab con ella y usa Instantiate(prefab, posicion) con un campo nova::AssetRef prefab; registrado con .Asset("Prefab").

Personaje sencillo (un jugador o multijugador)#

En una entidad con Controlador de personaje. Si la entidad es de red, solo la maneja su dueño; sin red, la maneja el jugador.

C++
// Personaje sencillo: WASD relativo a la camara, Mayus para correr y Espacio para saltar.
#include "nova/network/NetworkComponents.h"
#include "nova/physics/PhysicsComponents.h"
#include "nova/platform/Input.h"
#include "nova/scene/Components.h"
#include "nova/scripting/Behaviour.h"

#include <cmath>

using namespace nova;

class PersonajeSimple : public Behaviour {
public:
    void OnUpdate(float) override
    {
        // En red, solo el dueno lee los controles; sin red no hay dueno y lo maneja esta maquina
        if (HasComponent<NetworkIdentity>() && !IsLocalPlayer()) return;
        CharacterController* cc = TryGetComponent<CharacterController>();
        if (!cc) return;
        Input& in = GetInput();
        Vec3 adelante{0, 0, -1};
        const Entity cam = FindPrimaryCamera(GetScene());
        if (GetScene().IsValid(cam)) {
            adelante = GetScene().GetWorldRotation(cam).Forward();
            adelante.y = 0.0f;
            adelante = LengthSq(adelante) > 1e-6f ? Normalize(adelante) : Vec3{0, 0, -1};
        }
        const Vec3 derecha = Normalize(Cross(adelante, Vec3::Up()));
        Vec3 dir = derecha * in.GetAxis("MoverX") + adelante * in.GetAxis("MoverY");
        if (LengthSq(dir) > 1.0f) dir = Normalize(dir);
        cc->Move(dir, in.IsActionDown("Correr"));
        if (LengthSq(dir) > 0.01f) cc->Face(std::atan2(dir.x, dir.z));
        if (in.WasActionPressed("Saltar")) cc->Jump();
    }
};

NOVA_BEHAVIOUR(PersonajeSimple)
{
    type.Display("Personaje sencillo");
}

Plataforma móvil#

En una entidad con Colisionador y Cuerpo rígido de tipo Cinemático. Los personajes y las cajas que están encima viajan con ella.

C++
// Plataforma cinematica que va y viene entre su posicion inicial y otra.
#include "nova/scripting/Behaviour.h"

#include <algorithm>
#include <cmath>

using namespace nova;

class PlataformaMovil : public Behaviour {
public:
    Vec3 recorrido{0.0f, 0.0f, 6.0f}; // desplazamiento desde la posicion inicial
    float segundosPorViaje = 4.0f;

    void OnStart() override { m_inicio = GetTransform().position; }

    void OnFixedUpdate(float dt) override
    {
        if (!IsServer()) return; // en multijugador la mueve el servidor (con Transform de red)
        m_tiempo += dt;
        const float periodo = std::max(segundosPorViaje, 0.1f) * 2.0f;
        const float t = 0.5f - 0.5f * std::cos(m_tiempo * kTwoPi / periodo); // ida y vuelta suave
        GetTransform().position = m_inicio + recorrido * t;
    }

private:
    Vec3 m_inicio;
    float m_tiempo = 0.0f;
};

NOVA_BEHAVIOUR(PlataformaMovil)
{
    type.Display("Plataforma móvil");
    NOVA_FIELD(recorrido).Display("Recorrido").Tooltip("Metros desde la posición inicial");
    NOVA_FIELD(segundosPorViaje).Display("Segundos por viaje").Range(0.1f, 60.0f);
}

Disparar con un rayo#

En cualquier entidad (por ejemplo la cámara). Con la acción Disparar (clic izquierdo) lanza un rayo desde la cámara y empuja lo que toque si es dinámico. En multijugador, el disparo sería una RPC Server y el rayo lo lanzaría el servidor.

C++
// Dispara un rayo desde la camara principal y empuja el objeto dinamico que toque.
#include "nova/core/Log.h"
#include "nova/physics/PhysicsComponents.h"
#include "nova/platform/Input.h"
#include "nova/render/DebugDraw.h"
#include "nova/scene/Components.h"
#include "nova/scripting/Behaviour.h"

using namespace nova;

class DisparoConRayo : public Behaviour {
public:
    float alcance = 100.0f; // metros
    float fuerza = 20.0f;   // N s

    void OnUpdate(float) override
    {
        if (!GetInput().WasActionPressed("Disparar")) return;
        Scene& scene = GetScene();
        const Entity cam = FindPrimaryCamera(scene);
        if (!scene.IsValid(cam)) return;
        const Vec3 origen = scene.GetWorldPosition(cam);
        const Vec3 dir = scene.GetWorldRotation(cam).Forward();
        PhysicsQuery q;
        q.ignore = GetEntity();
        RaycastHit hit;
        if (!Raycast(origen, dir, alcance, hit, q) || !scene.IsValid(hit.entity)) return;
        log::Info("Impacto en '{}' a {:.1f} m", scene.GetName(hit.entity), hit.distance);
        const RigidBody* rb = scene.TryGet<RigidBody>(hit.entity);
        if (rb && rb->type == BodyType::Dynamic) Physics().AddImpulseAtPoint(hit.entity, dir * fuerza, hit.point);
    }
};

NOVA_BEHAVIOUR(DisparoConRayo)
{
    type.Display("Disparo con rayo");
    NOVA_FIELD(alcance).Display("Alcance").Range(1.0f, 1000.0f);
    NOVA_FIELD(fuerza).Display("Fuerza").Range(0.0f, 1000.0f).Tooltip("Impulso en N s");
}

Sonido al chocar#

En un objeto con Colisionador y Cuerpo rígido. El volumen depende de la fuerza del golpe.

C++
// Sonido de golpe con volumen segun el impulso del choque.
#include "nova/scripting/Behaviour.h"

#include <algorithm>

using namespace nova;

class SonidoDeGolpe : public Behaviour {
public:
    AssetRef sonido;
    float impulsoMinimo = 2.0f;   // N s: por debajo no suena (roces, apoyos)
    float impulsoMaximo = 40.0f;  // N s: a partir de aqui suena al maximo

    void OnCollisionEnter(const Collision& c) override
    {
        if (c.impulse < impulsoMinimo) return;
        const float volumen = std::clamp(c.impulse / impulsoMaximo, 0.1f, 1.0f);
        Audio().PlayOneShot(sonido, c.point, volumen); // en un servidor dedicado no hace nada
    }
};

NOVA_BEHAVIOUR(SonidoDeGolpe)
{
    type.Display("Sonido de golpe");
    NOVA_FIELD(sonido).Display("Sonido").Asset("Audio");

    NOVA_FIELD(impulsoMaximo).Display("Impulso máximo").Range(0.1f, 1000.0f);

Radio que suena al acercarse#

En una entidad con Colisionador marcado como Es sensor (por ejemplo una esfera de radio 4) y Fuente de audio con Bucle y sin Reproducir al empezar. Suena mientras tu personaje está dentro.

C++
// Radio que suena mientras el personaje del jugador esta dentro de su sensor.
#include "nova/physics/PhysicsComponents.h"
#include "nova/scripting/Behaviour.h"

using namespace nova;

class RadioDeZona : public Behaviour {
public:
    void OnTriggerEnter(Entity otro) override
    {
        if (EsMiPersonaje(otro) && !Audio().IsPlaying(GetEntity())) Audio().Play(GetEntity());
    }
    void OnTriggerExit(Entity otro) override
    {
        if (EsMiPersonaje(otro)) Audio().Stop(GetEntity());
    }

private:
    // El sonido es local: cada maquina reacciona solo a su propio personaje
    bool EsMiPersonaje(Entity e) const
    {
        Scene& scene = GetScene();
        const Entity local = Network().LocalPlayer(scene);
        if (scene.IsValid(local)) return e == local;  // partida en red
        return scene.Has<CharacterController>(e);     // un jugador sin red
    }
};

NOVA_BEHAVIOUR(RadioDeZona)
{
    type.Display("Radio de zona");
}

Opciones de sonido#

Un menú con ImGui para el volumen general (el del Oyente de audio), la música y los efectos.

C++
// Opciones de volumen: general (AudioListener), musica y efectos (buses).
#include "nova/audio/AudioComponents.h"
#include "nova/core/Context.h"
#include "nova/scripting/Behaviour.h"

#include "imgui.h"

using namespace nova;

class OpcionesDeSonido : public Behaviour {
public:
    float musica = 0.8f;
    float efectos = 1.0f;
    bool visible = true;

    void OnStart() override
    {
        Audio().SetBusVolume(AudioBus::Music, musica);
        Audio().SetBusVolume(AudioBus::Sfx, efectos);
    }

    void OnGUI() override
    {
        if (!visible) return;
        const GameViewInfo& gv = Ctx().gameView;
        ImGui::SetNextWindowPos(ImVec2(gv.x + 20.0f, gv.y + 60.0f), ImGuiCond_FirstUseEver);
        ImGui::Begin("Sonido", &visible, ImGuiWindowFlags_AlwaysAutoResize | ImGuiWindowFlags_NoSavedSettings);
        bool hecho = false;
        GetScene().Each<AudioListener>([&](Entity, AudioListener& oyente) {
            if (hecho) return; // solo el primero (el que se usa)
            ImGui::SliderFloat("General", &oyente.volume, 0.0f, 1.0f);
            hecho = true;
        });
        if (ImGui::SliderFloat("Música", &musica, 0.0f, 1.0f)) Audio().SetBusVolume(AudioBus::Music, musica);
        if (ImGui::SliderFloat("Efectos", &efectos, 0.0f, 1.0f)) Audio().SetBusVolume(AudioBus::Sfx, efectos);
        ImGui::End();
    }
};

La vida en el HUD de la plantilla (tutorial 1):

C++
// Vida del jugador en el HUD de la plantilla: barra, numero y un aviso cuando queda poca.
#include "nova/platform/Input.h"
#include "nova/scripting/Behaviour.h"

#include <algorithm>
#include <format>

using namespace nova;

class HudVidaEjemplo : public Behaviour {
public:
    float vida = 100.0f;
    float vidaMaxima = 100.0f;

    void OnStart() override { Mostrar(); }

    // Otro script la llama al recibir un golpe: GetBehaviour<HudVidaEjemplo>()->Herir(10)
    void Herir(float cantidad)
    {
        const bool teniaMucha = vida > 25.0f;
        vida = std::max(0.0f, vida - cantidad);
        Mostrar();
        // El panel de la vida parpadea en rojo y vuelve a su color
        UI("HUD/Vida").TintTo({1.0f, 0.35f, 0.35f, 1.0f}, 0.05f);
        m_parpadeo = 0.15f;
        if (teniaMucha && vida <= 25.0f) {
            UI("HUD/Aviso").SetText("¡Te queda poca vida!").Show();
            UI("HUD/Aviso").FadeTo(1.0f, 0.3f);
        }
    }

    void Curar() { vida = vidaMaxima; Mostrar(); UI("HUD/Aviso").Hide(); }

    void OnUpdate(float dt) override
    {
        if (m_parpadeo > 0.0f && (m_parpadeo -= dt) <= 0.0f) UI("HUD/Vida").TintTo({1, 1, 1, 1}, 0.2f);
        // Prueba en el editor: H hiere y C cura
        if (GetInput().WasKeyPressed(Key::H)) Herir(10.0f);
        if (GetInput().WasKeyPressed(Key::C)) Curar();
    }

private:
    void Mostrar()
    {
        // La barra va de 0 a 100 (Minimo y Maximo de la Barra de progreso)
        UI("HUD/Vida/Barra").SetValue(vida / vidaMaxima * 100.0f);
        UI("HUD/Vida/Valor").SetText(std::format("{:.0f}", vida));
    }
    float m_parpadeo = 0.0f;
};

NOVA_BEHAVIOUR(HudVidaEjemplo)
{
    type.Display("Vida en el HUD (ejemplo)");
    NOVA_FIELD(vida).Display("Vida");
    NOVA_FIELD(vidaMaxima).Display("Vida máxima");
    NOVA_METHOD(Curar); // asi un boton de la interfaz tambien puede llamarlo
}

// Inventario que crea sus casillas con un prefab de interfaz y responde al clic en cada una.
// El prefab: una casilla de la plantilla Inventario (Imagen + Casilla, con los hijos "Icono" y "Cantidad").
#include "nova/scripting/Behaviour.h"

#include <format>
#include <vector>

class InventarioEjemplo : public Behaviour {

Arrastrar y soltar sobre las casillas de la plantilla Inventario (en Rejilla deja la ruta del contenido de la rejilla):

C++
// Inventario con arrastrar y soltar sobre las casillas de la plantilla Inventario: soltar mueve o cambia de
// sitio, junta montones del mismo objeto, Mayus al soltar parte el monton y soltar fuera lo tira al suelo.
#include "nova/core/Log.h"
#include "nova/scripting/Behaviour.h"

#include <format>
#include <vector>

using namespace nova;

class InventarioArrastreEjemplo : public Behaviour {
public:
    std::string rejilla = "Inventario/Ventana/Casillas/Contenido";

    void OnStart() override
    {
        m_casillas.assign(20, {});
        m_casillas[0] = {1, 30, -1.0f}; // 30 piedras
        m_casillas[1] = {2, 1, 0.8f};   // un hacha al 80 %
        ui::Element contenido = UI(rejilla);
        for (i32 i = 0; i < 20; ++i) {
            ui::Element casilla = contenido.Slot(i);
            casilla.OnDrop([this](const ui::UiEvent& e) { Soltar(e); });
            casilla.OnEndDrag([this](const ui::UiEvent& e) {
                if (e.drag.result == ui::UiDropResult::Outside) Tirar(Indice(e.entity));
            });
        }
        Pintar();
    }

private:
    struct Objeto {
        i32 id = 0;
        i32 cantidad = 0;
        float durabilidad = -1.0f; // -1 = no se gasta
    };

    i32 Indice(Entity e) const { return ui::Element(&GetScene(), GetScene().GetID(e)).GetSlotIndex(); }
    Objeto& En(i32 i) { return m_casillas[static_cast<size_t>(i)]; }

    void Soltar(const ui::UiEvent& e)
    {
        const i32 de = Indice(e.drag.source), a = Indice(e.entity);
        if (de < 0 || a < 0 || de == a) return;
        Objeto& origen = En(de);
        Objeto& destino = En(a);
        if (e.pointer.shift && destino.id == 0 && origen.cantidad > 1) {
            destino = origen; // Mayus: la mitad del monton
            destino.cantidad = origen.cantidad / 2;
            origen.cantidad -= destino.cantidad;
        } else if (destino.id == origen.id && origen.durabilidad < 0.0f) {
            destino.cantidad += origen.cantidad; // el mismo objeto: se juntan
            origen = {};
        } else {
            std::swap(origen, destino);
        }
        Pintar();
    }

    void Tirar(i32 i)
    {
        if (i < 0) return;
        log::Info("Al suelo: objeto {} x{}", En(i).id, En(i).cantidad); // aqui se pediria al servidor (CallRpc)
        En(i) = {};
        Pintar();
    }

    void Pintar()
    {
        ui::Element contenido = UI(rejilla);
        for (i32 i = 0; i < 20; ++i) {
            const Objeto& o = En(i);
            ui::Element casilla = contenido.Slot(i);
            casilla.Child("Icono").SetVisible(o.id != 0);
            casilla.Child("Cantidad").SetText(o.cantidad > 1 ? std::format("x{}", o.cantidad) : std::string());
            casilla.Child("Durabilidad").SetVisible(o.id != 0 && o.durabilidad >= 0.0f).SetValue(o.durabilidad * 100.0f);
            casilla.SetDraggable(o.id != 0).SetDragPayload(ui::UiPayload::Int(o.id, "objeto"));
            if (o.id != 0) casilla.SetTooltip(std::format("Objeto {}", o.id), std::format("Cantidad: {}", o.cantidad), o.durabilidad);
            else casilla.SetTooltipEnabled(false);
        }
    }

    std::vector<Objeto> m_casillas;
};

NOVA_BEHAVIOUR(InventarioArrastreEjemplo)
{
    type.Display("Inventario con arrastrar (ejemplo)");
    NOVA_FIELD(rejilla).Display("Rejilla");
}

Una prueba con red mala#

Lo más fiable es una prueba automática como tests/test_multiplayer.cpp: un servidor dedicado y dos clientes en el mismo proceso, conectados por una red en memoria con latencia, variación y pérdida simuladas, sin ventanas. Este es el esqueleto:

C++
// Prueba sin ventanas: servidor dedicado y un cliente en el mismo proceso, con red mala simulada.
#include "nova/network/Network.h"
#include "nova/scene/SceneSerializer.h"

#include "nova/net/memory_transport.h"
#include "nova/net/sim_transport.h"

#include <memory>

using namespace nova;

// Una "maquina": transporte en memoria, simulador de red mala, su NetworkManager y su escena.
// La escena se declara la ultima para que se destruya antes que su red.
struct Maquina {
    std::unique_ptr<net::MemoryTransport> transporte;
    std::unique_ptr<net::SimulatedTransport> redMala;
    std::unique_ptr<NetworkManager> red;
    Scene escena;
};

constexpr u16 kPuertoServidor = 41500;

bool Arrancar(Maquina& m, net::MemoryNetwork& internet, u16 direccion, const Json& mapa, NetworkMode modo)
{
    if (!DeserializeScene(m.escena, mapa)) return false;
    m.transporte = internet.createTransport(net::Address::loopback(direccion));
    net::NetworkConditions c;
    c.latencyMs = 80.0f; // de ida: ping de ~160 ms
    c.jitterMs = 15.0f;
    c.lossPercent = 5.0f;
    m.redMala = std::make_unique<net::SimulatedTransport>(*m.transporte, c, direccion);
    m.red = CreateNetworkManager();
    NetworkSessionDesc d;
    d.mode = modo;
    d.address = "127.0.0.1";
    d.port = kPuertoServidor; // el cliente se conecta al extremo con esta direccion
    d.lanDiscovery = false;
    d.transport = m.redMala.get();
    m.red->SetSession(d);
    m.escena.SetService<NetworkManager>(m.red.get());
    m.escena.StartPlay();
    return m.red->IsRunning();
}

// 'mapa' es el JSON de una escena (Json::LoadFile de un .scene). Devuelve las estadisticas del cliente.
NetworkStats ProbarConRedMala(const Json& mapa)
{
    net::MemoryNetwork internet;
    Maquina servidor, cliente;
    Arrancar(servidor, internet, kPuertoServidor, mapa, NetworkMode::DedicatedServer);
    Arrancar(cliente, internet, kPuertoServidor + 1, mapa, NetworkMode::Client);
    for (int i = 0; i < 600; ++i) { // 10 s de partida a 60 Hz
        servidor.escena.Update(1.0f / 60.0f);
        cliente.escena.Update(1.0f / 60.0f);
    }
    const NetworkStats s = cliente.red->Stats(); // rttMs, lossPercent, corrections, maxPredictionError...
    cliente.escena.StopPlay();
    servidor.escena.StopPlay();
    return s;
}

El jugador#

El script del jugador se ejecuta en todas las máquinas que tienen ese personaje, así que cada parte empieza preguntando a quién le toca:

  • los controles solo en la máquina del dueño (IsLocalPlayer()): se escriben en el CharacterController y la red se encarga de predecirlos y enviarlos;
  • la animación la calculan el servidor y el dueño; los demás la reciben con el Animador de red;
  • las reglas (recargar cargas, empujar, sumar puntos, devolver al jugador si se cae) solo en el servidor.
C++
// Personaje del tutorial: movimiento predicho, puntos replicados, RPCs y HUD.
#include "MiArena.h"

#include "nova/animation/Animator.h"
#include "nova/core/Context.h"
#include "nova/core/Log.h"
#include "nova/network/NetworkComponents.h"
#include "nova/physics/PhysicsComponents.h"
#include "nova/platform/Input.h"
#include "nova/scene/Components.h"

#include "imgui.h"

#include <algorithm>
#include <cmath>
#include <format>

using namespace nova;

void Jugador::OnNetworkSpawn()
{
    // Servidor: al crearse el personaje. Clientes: al recibirlo (los campos replicados ya traen su valor)
    if (IsServer()) cargas = cargasMaximas;
    if (const NetworkIdentity* id = TryGetComponent<NetworkIdentity>()) {
        log::Info("Aparece {} con {} puntos", id->ownerName, puntos);
    }
    if (IsLocalPlayer()) MostrarAviso("WASD para moverte, E para empujar");
}

void Jugador::OnUpdate(float dt)
{
    CharacterController* cc = TryGetComponent<CharacterController>();
    if (!cc) return;

    // 1. Controles: solo el jugador de esta maquina. La red predice el movimiento y lo envia al servidor.
    if (IsLocalPlayer()) {
        Input& in = GetInput();
        Scene& scene = GetScene();
        Vec3 adelante{0, 0, -1};
        const Entity cam = FindPrimaryCamera(scene);
        if (scene.IsValid(cam)) {
            adelante = scene.GetWorldRotation(cam).Forward();
            adelante.y = 0.0f;
            adelante = LengthSq(adelante) > 1e-6f ? Normalize(adelante) : Vec3{0, 0, -1};
        }
        const Vec3 derecha = Normalize(Cross(adelante, Vec3::Up()));
        Vec3 dir = derecha * in.GetAxis("MoverX") + adelante * in.GetAxis("MoverY");
        if (LengthSq(dir) > 1.0f) dir = Normalize(dir);
        cc->Move(dir, in.IsActionDown("Correr"));
        if (LengthSq(dir) > 0.01f) cc->Face(std::atan2(dir.x, dir.z)); // los modelos glTF miran hacia +Z
        if (in.WasActionPressed("Saltar")) cc->Jump();
        if (in.WasActionPressed("Accion")) CallRpc("Empujar"); // peticion al servidor
    }

    // 2. Animacion: la calculan el servidor y el dueno; los demas la reciben (NetworkAnimator)
    if (HasAuthority() || IsLocalPlayer()) {
        if (Animator* anim = TryGetComponent<Animator>()) {
            anim->SetFloat("velocidad", std::sqrt(cc->velocity.x * cc->velocity.x + cc->velocity.z * cc->velocity.z));
        }
    }

    if (m_avisoTiempo > 0.0f) m_avisoTiempo -= dt;
}

void Jugador::OnFixedUpdate(float dt)
{
    if (!IsServer()) return; // las reglas de la partida solo las aplica el servidor
    if (cargas < cargasMaximas) {
        m_recarga += dt;
        if (m_recarga >= segundosPorCarga) {
            m_recarga = 0.0f;
            ++cargas; // se replica solo (y solo al dueno)
        }
    }
    // Si se cae del mapa, vuelve al centro sin interpolar en los clientes
    if (GetScene().GetWorldPosition(GetEntity()).y < -10.0f) {
        Network().Teleport(GetScene(), GetEntity(), {0.0f, 1.0f, 0.0f}, Quat::Identity());
    }
}

void Jugador::SumarPuntos(i32 cantidad)
{
    if (!IsServer()) return;
    puntos += cantidad;
    // El anfitrion no recibe OnRep (el valor nace en su maquina): llama al mismo codigo
    if (IsClient()) OnRepPuntos();
}

void Jugador::OnRepPuntos()
{
    if (!IsLocalPlayer()) return; // el marcador ya lo ensena; el sonido, solo para quien puntua
    Audio().PlayOneShot2D(sonidoPunto, 0.8f);
    MostrarAviso(std::format("¡{} puntos!", puntos));
}

void Jugador::Empujar()
{
    // RPC Server: solo llega al servidor y solo si la pide el dueno de este personaje
    if (!IsServer()) return;
    if (cargas <= 0) {
        CallRpc("Aviso", "Sin cargas: espera un momento"); // solo lo ve el dueno
        return;
    }
    --cargas;
    Scene& scene = GetScene();
    const Vec3 pos = scene.GetWorldPosition(GetEntity());
    const Vec3 frente = scene.GetWorldRotation(GetEntity()).Rotate({0, 0, 1});
    const Vec3 centro = pos + Vec3{0, 0.8f, 0} + frente * alcanceEmpujon;
    PhysicsQuery q;
    q.layers = PhysicsLayer::Bit(PhysicsLayer::Dynamic);
    q.ignore = GetEntity();
    std::vector<Entity> tocadas;
    Physics().OverlapSphere(centro, 1.0f, tocadas, q);
    for (Entity e : tocadas) {
        const RigidBody* rb = scene.TryGet<RigidBody>(e);
        if (!rb || rb->type != BodyType::Dynamic) continue;
        Vec3 dir = scene.GetWorldPosition(e) - pos;
        dir.y = 0.0f;
        dir = LengthSq(dir) > 1e-4f ? Normalize(dir) : frente;
        dir.y = 0.35f; // un poco hacia arriba
        Physics().AddImpulse(e, dir * (std::max(rb->mass, 0.1f) * fuerzaEmpujon));
    }
    CallRpc("EfectoEmpujon", centro); // sonido en todas las pantallas
}

void Jugador::EfectoEmpujon(Vec3 donde)
{
    Audio().PlayOneShot(sonidoEmpujon, donde); // en un servidor dedicado no hace nada
}

Detalles que conviene entender:

  • cc->Move, cc->Face y cc->Jump no mueven nada en ese momento: guardan la entrada. En cada paso fijo la red la recoge, la simula en la máquina del dueño (predicción) y la envía al servidor, que la simula también. Nunca muevas el Transform de un personaje de red a mano.
  • CallRpc("Empujar") desde el cliente viaja al servidor; en el anfitrión o en un jugador (Offline) se ejecuta en el acto. El código es el mismo.
  • En Empujar, el servidor valida (¿le quedan cargas?) antes de hacer nada: un cliente tramposo puede llamar a la RPC cuando quiera, pero no puede saltarse esa comprobación.
  • CallRpc("Aviso", "..."): los argumentos se convierten al tipo del método cuando se puede (un literal a std::string, un entero a float); si no encajan, CallRpc lo dice en el registro y no envía nada (RPCs).
  • OnRepPuntos solo se llama en los clientes: cuando llega un valor nuevo y, al aparecer el personaje, si su valor inicial no es el del prefab. El anfitrión no recibe OnRep (el valor nace en su máquina): por eso SumarPuntos lo llama a mano.

{

    Transform& t = GetTransform();

    m_recogida = true;
    jugador->SumarPuntos(valor);
    Destroy(GetEntity()); // destruida en el servidor: desaparece en todos los clientes
}

El generador de monedas#

C++
// Generador de monedas del tutorial: solo el servidor crea monedas (Network().Spawn).
#include "MiArena.h"

#include "nova/network/NetworkComponents.h"

#include <cmath>

using namespace nova;

namespace {
// Aleatorio sencillo (xorshift)
float Aleatorio01(u32& s)
{
    s ^= s << 13;
    s ^= s >> 17;
    s ^= s << 5;
    return static_cast<float>(s & 0xFFFFFF) / static_cast<float>(0xFFFFFF);
}
} // namespace

void GeneradorDeMonedas::OnUpdate(float dt)
{
    // En los clientes y en el menu (sin sesion) no se crea nada
    if (!IsServer() || Network().Mode() == NetworkMode::None || !prefabMoneda.IsValid()) return;
    m_tiempo += dt;
    if (m_tiempo < intervalo) return;
    m_tiempo = 0.0f;
    int monedas = 0;
    GetScene().Each<NetworkIdentity>([&](Entity, NetworkIdentity& id) {
        if (id.prefab == prefabMoneda) ++monedas;
    });
    if (monedas >= maximo) return;
    const float a = Aleatorio01(m_semilla) * kTwoPi;
    const float r = std::sqrt(Aleatorio01(m_semilla)) * radio;
    const Vec3 pos = GetScene().GetWorldPosition(GetEntity()) + Vec3{std::sin(a) * r, 0.6f, std::cos(a) * r};
    // Instancia el prefab en el servidor y lo replica: los clientes lo crean con el mismo prefab
    Network().Spawn(GetScene(), prefabMoneda, pos, Quat::Identity());
}

void CamaraArena::OnLateUpdate(float dt)

    Scene& scene = GetScene();
    const Entity jugador = Network().LocalPlayer(scene); // el personaje de ESTA maquina (o ninguno)
    Vec3 objetivo{0.0f, 1.0f, 0.0f};
    if (scene.IsValid(jugador)) {

        if (in.IsMouseDown(MouseButton::Right)) m_giro -= in.MouseDelta().x * 0.2f;
        objetivo = scene.GetWorldPosition(jugador) + Vec3{0.0f, 1.2f, 0.0f};
    } else {
        m_giro += 10.0f * dt; // vista general mientras no hay personaje
    }
    const Vec3 deseada = objetivo + Quat::FromEulerDegrees({0.0f, m_giro, 0.0f}).Rotate({0.0f, altura, distancia});
    const Vec3 ojo = Lerp(scene.GetWorldPosition(GetEntity()), deseada, Saturate(suavizado * dt));
    scene.SetWorldPosition(GetEntity(), ojo);
    scene.SetWorldRotation(GetEntity(), Quat::LookRotation(objetivo - ojo));
}

El menú no arranca la red por su cuenta: rellena un NetworkSessionDesc (partiendo de la sesión actual, que ya trae el puerto y el nombre del servidor del proyecto) y se lo pide al anfitrión con RequestSession. NovaGame.exe recarga entonces la escena inicial con esa sesión; el editor hace lo mismo con su escena.

void MenuArena::OnStart()
{
    std::snprintf(m_nombre, sizeof(m_nombre), "%s", Network().PlayerName().c_str());
}

void MenuArena::OnUpdate(float)
{
    NetworkManager& red = Network();
    const bool enMenu = red.Mode() == NetworkMode::None && red.IsAvailable();
    // Buscar partidas en la red local solo mientras se ve el menu
    if (enMenu && !m_buscando) {
        red.StartLanSearch();
        m_buscando = true;
    } else if (!enMenu && m_buscando) {
        red.StopLanSearch();
        m_buscando = false;
    }
    if (!enMenu && GetInput().WasActionPressed("Pausa")) m_pausa = !m_pausa;
}

void MenuArena::OnGUI()
{
    NetworkManager& red = Network();
    const GameViewInfo& gv = Ctx().gameView;
    ImGui::SetNextWindowPos(ImVec2(gv.x + gv.width * 0.5f, gv.y + gv.height * 0.5f), ImGuiCond_Always, ImVec2(0.5f, 0.5f));
    ImGui::SetNextWindowSize(ImVec2(380.0f, 0.0f), ImGuiCond_Always);
    const ImGuiWindowFlags flags = ImGuiWindowFlags_NoResize | ImGuiWindowFlags_NoMove | ImGuiWindowFlags_NoCollapse |
                                   ImGuiWindowFlags_NoSavedSettings | ImGuiWindowFlags_AlwaysAutoResize;
    NetworkSessionDesc sesion = red.Session(); // puerto, plazas y nombre del servidor del proyecto
    sesion.transport = nullptr;
    const ImVec2 ancho(-1.0f, 0.0f);

    if (red.Mode() == NetworkMode::None) {
        if (!red.IsAvailable()) return; // escena sin servicio de red
        ImGui::Begin("Arena de monedas", nullptr, flags);
        if (ImGui::InputText("Tu nombre", m_nombre, sizeof(m_nombre))) red.SetPlayerName(m_nombre);
        if (!red.LastError().empty()) ImGui::TextColored(ImVec4(1.0f, 0.5f, 0.4f, 1.0f), "%s", red.LastError().c_str());
        sesion.playerName = m_nombre;
        if (ImGui::Button("Jugar solo", ancho)) {
            sesion.mode = NetworkMode::Offline;
            red.RequestSession(sesion);
        }
        if (ImGui::Button("Crear partida", ancho)) {
            sesion.mode = NetworkMode::Host;
            red.RequestSession(sesion);
        }
        ImGui::InputText("IP", m_ip, sizeof(m_ip));
        if (ImGui::Button("Unirse", ancho)) {
            sesion.mode = NetworkMode::Client;
            sesion.address = m_ip; // el puerto es el del proyecto
            red.RequestSession(sesion);
        }
        ImGui::SeparatorText("Partidas en la red local");
        for (const LanServerEntry& s : red.LanServers()) {
            const std::string texto = s.name + "  (" + std::to_string(s.players) + "/" + std::to_string(s.maxPlayers) + ")";
            if (ImGui::Selectable(texto.c_str(), false, s.compatible ? 0 : ImGuiSelectableFlags_Disabled)) {
                const size_t dosPuntos = s.address.rfind(':'); // "ip:puerto"
                sesion.mode = NetworkMode::Client;
                sesion.address = s.address.substr(0, dosPuntos);
                if (dosPuntos != std::string::npos) sesion.port = static_cast<u16>(std::atoi(s.address.c_str() + dosPuntos + 1));
                red.RequestSession(sesion);
            }
        }
        if (ImGui::Button("Salir", ancho)) RequestQuit();
        ImGui::End();
        return;
    }
    if (!m_pausa) return;
    ImGui::Begin("Pausa", nullptr, flags);
    ImGui::TextUnformatted(red.StatusText().c_str());
    if (ImGui::Button("Continuar", ancho)) m_pausa = false;
    if (ImGui::Button("Desconectar", ancho)) {
        sesion.mode = NetworkMode::None; // volver al menu principal
        red.RequestSession(sesion);
    }
    if (ImGui::Button("Salir del juego", ancho)) RequestQuit();
    ImGui::End();
}

El HUD del ejemplo#

La entidad HUD de Arena.scene es una interfaz hecha con los componentes del motor (ver interfaz-ui.md): abajo a la izquierda, Empujones (icono, «Empujones: N» con la fuente Karla y la barra Recarga, gris mientras recarga y naranja cuando se puede empujar); abajo a la derecha, Red («Jugadores: N» y el ping, o «Anfitrión» o «Un jugador»). Su lienzo no Recibe entrada: nunca se queda con el ratón del juego.

Para cambiar su aspecto, abre el ejemplo en el editor, elige HUD y edítalo en el panel Interfaz. El script HudArena (en la misma entidad) solo pone los datos: lee pushes (replicado) y CooldownFraction() del PlayerController del jugador local, Network().Players() y Network().Stats().rttMs, y los escribe en los elementos que busca una vez en OnStart (Child("Empujones/Valor"), Child("Empujones/Recarga")...) con SetText y SetValue. Fuera de una partida (el menú principal de OnGUI) baja a 0 el alfa del Grupo (alfa) del lienzo; OnGUI se sigue dibujando encima.

La prueba del ejemplo#

tests/test_multiplayer.cpp carga multiplayer_game.dll, arranca un servidor dedicado y dos clientes («Ana» y «Beto») con 50 ms de latencia y un 3 % de pérdida, y comprueba que los jugadores aparecen en todos, que el movimiento predicho coincide con el del servidor, que la caja empujada se ve igual en los dos clientes, que la animación y el contador de empujones se replican, que suenan los pasos (con audio nulo) y que al desconectar desaparece el personaje. Es un buen modelo para probar tu juego sin abrir ventanas.
