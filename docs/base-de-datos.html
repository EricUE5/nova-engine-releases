Database guarda los datos de tu juego en tablas, como una hoja de cálculo o como MySQL, pero sin instalar ni configurar nada: los personajes de un roleplay, sus coches, sus casas, el dinero, los objetos del inventario. Lo escribe y lo lee el servidor del juego; los jugadores nunca tocan la base de datos directamente, así que nadie se puede dar dinero editando un fichero.

  • Para desarrollar, el modo local guarda todo en un fichero de tu PC (base-datos.db): no hay que desplegar nada. Lo ves y lo cambias en el editor con la ventana Base de datos.
  • Para publicar, el modo remoto usa el mismo servicio Nova Datos de Cloudflare que Persistence, con la clave de servidor del juego.
  • Las operaciones importantes son atómicas: Database.Increment cobra sin que el dinero baje nunca de 0 aunque dos servidores cobren a la vez, y Database.Transaction hace varias cosas todo o nada.
  • Todo es asíncrono: la respuesta llega a tu función unos milisegundos después y el juego no se para.

1. Qué es una base de datos#

Una tabla es como una hoja de Excel con un nombre. Cada columna es un dato con su tipo (el nombre es texto, el dinero es un número) y cada fila es una cosa: un personaje, un coche, una casa.

Tabla characters (los personajes):

id account first_name cash pos
1 steam:7656...01 Ana 450 (12.0, 0.0, -3.5)
2 steam:7656...01 Beto 20 (40.1, 0.0, 8.0)
3 steam:7656...02 Cris 1200 (0.0, 0.0, 0.0)
  • El id lo pone la base de datos (1, 2, 3...): es el número de cada fila, nunca se repite y no cambia. Con él hablas de un personaje en concreto («el personaje 3»).
  • Una cuenta puede tener varios personajes (Ana y Beto son de la misma cuenta): con Persistence eso era una lista dentro de un documento; con una tabla es una fila por personaje, y buscas los de una cuenta con Database.Find("characters", { account = cuenta }).
  • Otras tablas guardan otras cosas y apuntan a un personaje por su id: vehicles (con owner = 3), houses, items...

¿Y MySQL? Muchos servidores de roleplay usan MySQL (o MariaDB): un programa aparte que hay que instalar, arrancar y configurar con su usuario y su contraseña. Nova Engine trae SQLite dentro del motor: el mismo SQL para lo de cada día (SELECT, INSERT, UPDATE, DELETE, WHERE, ORDER BY, JOIN, COUNT, SUM...), las mismas tablas, filas y columnas, pero en un solo fichero y sin instalar nada. Lo que cambia:

MySQL Database de Nova
Instalar y arrancar un servidor de base de datos Sí No (modo local: un fichero; remoto: Nova Datos)
Usuario y contraseña de la base de datos Sí (y si se filtran, cualquiera entra) No: solo el servidor del juego, con su clave
Funciones sencillas sin escribir SQL No (siempre SQL) Sí: Insert, Find, Update, Increment...
SQL de verdad Sí Sí, con Database.Query
Tipos INT, VARCHAR(50), TINYINT(1), JSON... int, text, bool, json y también vec3 y color del motor
Cambiar las columnas ALTER TABLE a mano Solo: añades la columna en CreateTable
Ver los datos Un programa aparte (HeidiSQL, phpMyAdmin) La ventana Base de datos del editor

2. Probarlo ya#

Un proyecto nuevo ya está en modo local (Ajustes del proyecto > Datos > Modo: Local). Pon este script en una entidad de la escena, pulsa Jugar y mira la Consola:

Lua
local BdPrimerosPasos = Script()

function BdPrimerosPasos:Start()
    if not IsServer() then return end
    -- 1. La tabla (si ya existe no pasa nada; si añades columnas, se añaden solas)
    Database.CreateTable("visits", { id = "id", player = "text", time = "time" })
    -- 2. Una fila nueva cada vez que juegas
    Database.Insert("visits", { player = "yo", time = Database.Now() }, function(id, err)
        if err then
            print("No se pudo guardar:", err)
            return
        end
        print("Visita número", id)
        -- 3. Contar las filas
        Database.Count("visits", function(n)
            print("Llevas", n, "visitas")
        end)
    end)
end

return BdPrimerosPasos

Cada vez que juegas, el número sube: la tabla vive en %LOCALAPPDATA%\<tu juego>\base-datos.db, junto a la carpeta datos-locales de Persistence. Abre Ventana > Scripts > Base de datos para ver la tabla visits con sus filas.

Fíjate en que no hace falta esperar a que CreateTable termine para hacer el Insert: las peticiones salen en orden y llegan en orden.

3. ¿Database o Persistence?#

Las dos guardan datos que duran entre partidas, en el mismo sitio (modo local o Nova Datos) y con las mismas reglas (solo el servidor). Usa la que encaje con tus datos; un juego puede usar las dos.

Si tus datos son... Usa Por qué
Muchas cosas del mismo tipo que buscas por un dato: personajes, coches, casas, facturas, multas Database Una fila por cosa; buscas, ordenas y cuentas sin leerlo todo
Dinero que se cobra y se paga entre jugadores Database (Increment con min, Transaction) Atómico y sin bajar de 0
Cosas que se relacionan: los coches de un personaje, las llaves de una casa Database Una columna con el id del otro (owner) y Find o un JOIN
Ver y arreglar los datos a mano mientras desarrollas Database La ventana Base de datos: rejilla, editar celdas, SQL
Un bloque por jugador que se lee y se guarda entero: ajustes, progreso, alijo de un juego de extracción Persistence Un documento JSON por clave, con su versión
Lo que el jugador puede leer o cambiar sin servidor (modo remoto: lecturaCliente, acciones del juego) Persistence Database es solo del servidor

Si ya tienes datos en Persistence y quieres pasarlos a tablas, mira la sección 11.

4. Crear tablas y columnas#

Lua
Database.CreateTable("characters", {
    id = "id",                         -- el número de la fila (lo pone la base de datos)
    account = "text index",            -- la cuenta del jugador (con índice: buscar por cuenta es rápido)
    first_name = "text required",      -- obligatorio
    last_name = "text required",
    cash = "int default 500",          -- empieza con 500
    bank = "int default 0",
    job = "text default 'parado'",
    pos = "vec3",                      -- dónde estaba
    inventory = "json default []",     -- una lista o una tabla de Lua, tal cual
    created = "time",                  -- cuándo se creó (Database.Now())
})

CreateTable crea la tabla si no existe y, si ya existe, añade las columnas nuevas (con su valor por defecto en las filas que ya había). Así, cuando tu juego crece, solo añades una línea a la definición y la próxima vez que arranque el servidor la columna aparece sola, también en el PC de un amigo o en el servidor publicado.

Tipos:

Tipo En Lua Ejemplo
id número entero que pone la base de datos 1, 2, 3...
int número entero cash = 500
number número con decimales fuel = 0.75
text texto first_name = "Ana"
bool true o false alive = true
json cualquier tabla o lista de Lua (también números y textos) inventory = { "movil", "llaves" }
vec3 Vec3 pos = Vec3.new(12, 0, -3.5)
color Color car_color = Color.new(1, 0, 0, 1)
time segundos Unix (los de Database.Now(); la ventana Base de datos los enseña como fecha) created = Database.Now()

Después del tipo (en cualquier orden):

Extra Qué hace
default <valor> El valor si no se dice otro: "int default 0", "bool default true", "text default 'hola mundo'", "json default {}"
required Obligatorio: Insert sin este dato da un error
unique No puede haber dos filas con el mismo valor (una matrícula, un teléfono)
index Buscar por esta columna es rápido (para la que más usas en los filtros, como account)

Nombres de tablas y columnas: letras, números y _, empezando por letra (first_name, no nombre completo). Las columnas se guardan con el id primero y las demás por orden alfabético (las tablas de Lua no tienen orden).

Lo que no cambia solo. Si cambias el tipo de una columna que ya existía (cash = "int" a cash = "number"), la consola avisa y la columna se queda como estaba: cambiar el tipo de datos que ya hay es delicado. Si quitas una columna de la definición, se conserva con sus datos (sale una nota en la consola). Para hacerlo a mano:

  • Cambiar el tipo de una columna: añade una columna nueva con otro nombre (cash2 = "number"), copia los datos con Database.Query("UPDATE characters SET cash2 = cash") y usa la nueva.
  • Borrar una columna: Database.Query("ALTER TABLE characters DROP COLUMN job") (en la pestaña SQL de la ventana Base de datos, con confirmación).

5. Las funciones#

Regla de las respuestas: a tu función le llega primero el resultado y después el error. Si algo falla, el resultado es nil y el error dice qué pasó (en español). Así siempre se comprueba igual:

Lua
Database.FindOne("characters", { id = 3 }, function(personaje, err)
    if err then print("Algo falló:", err) return end
    if not personaje then print("No existe") return end
    print(personaje.first_name, personaje.cash)
end)
Función Qué hace A tu función le llega
Database.CreateTable(tabla, columnas, cb?) Crea la tabla o añade las columnas nuevas (true, nil) o (nil, error)
Database.Insert(tabla, fila, cb?) Añade una fila (id, nil): el id de la fila nueva
Database.Find(tabla, filtro?, opciones?, cb) Las filas que cumplen el filtro (filas, nil): una lista (vacía si no hay ninguna)
Database.FindOne(tabla, filtro, cb) La primera fila que lo cumple (fila, nil) o (nil, nil) si no hay
Database.Count(tabla, filtro?, cb) Cuántas filas lo cumplen (n, nil)
Database.Update(tabla, filtro, cambios, cb?) Cambia columnas de las filas del filtro (cambiadas, nil)
Database.Delete(tabla, filtro, cb?) Borra las filas del filtro (borradas, nil)
Database.Increment(tabla, filtro, sumas, límites?, cb?) Suma (o resta) atómicamente; con { min = 0 } falla si alguna se quedaría por debajo (fila, nil): la fila ya cambiada
Database.Transaction(function(tx) ... end, cb?) Varias operaciones todo o nada (true, nil) o (nil, error)
Database.Query(sql, parámetros?, cb) SQL de verdad, con ? (sección 7) (filas, nil, info)
Database.Now() La hora de ahora en segundos Unix (para las columnas time) —
Database.GetMode() "local", "remote" u "off" —
  • El filtro es una tabla de columnas y valores que tienen que coincidir todos: { account = cuenta, alive = true }. Para «está vacía» usa Database.NULL: { job = Database.NULL }. Para «mayor que», «contiene» o «entre», usa Database.Query.
  • Opciones de Find: { orderBy = "cash", descending = true, limit = 10, offset = 0 } (los 10 más ricos).
  • Update, Delete e Increment con el filtro vacío dan un error en vez de cambiar todas las filas: si de verdad quieres cambiarlas todas, hazlo con Database.Query.
  • Si escribes mal una columna (cahs) o le das un tipo que no es (cash = "mucho"), el error sale en la línea del script, antes de enviar nada.
  • Sin función, Insert, Update, Delete, Increment, CreateTable y Transaction se hacen igual y, si fallan, el error sale en la consola.

Esperar la respuesta sin funciones. Dentro de una tarea (Task.Spawn, Task.Delay...), si no pasas función, la llamada espera a la respuesta (sin parar el juego) y la devuelve. Queda más corto cuando haces varias cosas seguidas:

Lua
local BdEsperar = Script()

function BdEsperar:Start()
    if not IsServer() then return end
    Task.Spawn(function()
        Database.CreateTable("visits", { id = "id", player = "text", time = "time" })
        local id = Database.Insert("visits", { player = "yo", time = Database.Now() })
        local ultimas, err = Database.Find("visits", nil, { orderBy = "id", descending = true, limit = 5 })
        if err then print(err) return end
        print("Visita", id, "- últimas:", #ultimas)
    end)
end

return BdEsperar

Fuera de una tarea, Find, FindOne, Count y Query necesitan su función (si no, un error te lo recuerda).

Transacciones. Dentro de la función de Database.Transaction apuntas lo que hay que hacer con tx.Insert, tx.Update, tx.Delete, tx.Increment y tx.Query, y al terminar tu función se hace todo junto: si algo falla (un tx.Increment con min que no se cumple, una columna unique repetida), no se hace nada. Dentro no se lee (todo se aplica al final): si necesitas un dato antes, léelo antes de la transacción. Devuelve false para no hacer nada. Database.LAST_ID es el id de la fila que acaba de crear el tx.Insert anterior (para crear un personaje y su primer coche de una vez).

6. Ejemplo completo: personajes y dinero de un roleplay#

Un servidor de roleplay: cada jugador entra con su cuenta, elige uno de sus personajes o crea uno nuevo, aparece donde lo dejó, cobra y paga, y su posición se guarda sola. Todo lo decide el servidor; el cliente solo pide cosas con eventos y enseña lo que le contestan.

Lua
--[Global]
local BdPersonajes = Script()

local activo = {} -- jugador -> id de su personaje

function BdPersonajes:Awake()
    if not IsServer() then return end
    Database.CreateTable("characters", {
        id = "id",
        account = "text index",
        first_name = "text required",
        last_name = "text required",
        cash = "int default 500",
        bank = "int default 2000",
        job = "text default 'parado'",
        pos = "vec3",
        created = "time",
    })

    -- El jugador pide sus personajes (para la pantalla de elegir)
    RegisterNetEvent("rp:misPersonajes", function()
        local jugador = source
        local cuenta = Persistence.GetAccount(jugador)
        if not cuenta then return end
        Database.Find("characters", { account = cuenta }, { orderBy = "created" }, function(filas, err)
            if err then Log.Warn("Personajes: " .. err) return end
            local lista = {}
            for _, p in filas do
                table.insert(lista, { id = p.id, nombre = p.first_name .. " " .. p.last_name, dinero = p.cash })
            end
            TriggerClientEvent("rp:tusPersonajes", jugador, lista)
        end)
    end)

    -- Crear un personaje (como mucho 3 por cuenta). Lo que manda el cliente se comprueba SIEMPRE
    RegisterNetEvent("rp:crearPersonaje", function(nombre: string, apellido: string)
        local jugador = source
        local cuenta = Persistence.GetAccount(jugador)
        if not cuenta or type(nombre) ~= "string" or type(apellido) ~= "string" then return end
        if #nombre < 2 or #nombre > 20 or #apellido < 2 or #apellido > 20 then return end
        Database.Count("characters", { account = cuenta }, function(n)
            if not n or n >= 3 then
                TriggerClientEvent("rp:error", jugador, "Ya tienes 3 personajes")
                return
            end
            Database.Insert("characters", { account = cuenta, first_name = nombre, last_name = apellido, created = Database.Now() },
                function(id, err)
                    if err then TriggerClientEvent("rp:error", jugador, "No se pudo crear") return end
                    TriggerClientEvent("rp:personajeCreado", jugador, id)
                end)
        end)
    end)

    -- Elegir personaje: solo uno de SU cuenta
    RegisterNetEvent("rp:elegir", function(id: number)
        local jugador = source
        local cuenta = Persistence.GetAccount(jugador)
        if not cuenta or type(id) ~= "number" then return end
        Database.FindOne("characters", { id = id, account = cuenta }, function(p)
            if not p then return end -- no existe o es de otro: no se hace nada
            activo[jugador] = p.id
            TriggerClientEvent("rp:aparecer", jugador, p.pos or Vec3.new(0, 1, 0), p.cash)
        end)
    end)

    -- Guardar la posición de todos cada 30 segundos (y al salir)
    Task.Every(30, function() self:GuardarPosiciones() end)
    AddEventHandler("playerDropped", function(jugador)
        self:GuardarPosicion(jugador)
        activo[jugador] = nil
    end)
end

function BdPersonajes:GuardarPosicion(jugador: number)
    local id = activo[jugador]
    local personaje = Network.GetPlayerEntity(jugador)
    if id and personaje then
        Database.Update("characters", { id = id }, { pos = personaje.position })
    end
end

function BdPersonajes:GuardarPosiciones()
    for jugador in activo do self:GuardarPosicion(jugador) end
end

-- Cobrar (una tienda, una multa): nunca baja de 0 aunque dos cosas cobren a la vez
function BdPersonajes:Cobrar(jugador: number, cuanto: number, hecho: (boolean) -> ())
    local id = activo[jugador]
    if not id then hecho(false) return end
    Database.Increment("characters", { id = id }, { cash = -cuanto }, { min = 0 }, function(p, err)
        if err then
            TriggerClientEvent("rp:error", jugador, "No tienes bastante dinero")
            hecho(false)
            return
        end
        TriggerClientEvent("rp:dinero", jugador, p.cash)
        hecho(true)
    end)
end

-- Pagar a otro jugador: sale de uno y entra en el otro, o nada
function BdPersonajes:Pagar(de: number, a: number, cuanto: number)
    local origen, destino = activo[de], activo[a]
    if not origen or not destino or cuanto <= 0 then return end
    Database.Transaction(function(tx)
        tx.Increment("characters", { id = origen }, { cash = -cuanto }, { min = 0 })
        tx.Increment("characters", { id = destino }, { cash = cuanto })
    end, function(ok)
        if ok then
            TriggerClientEvent("rp:aviso", a, "Te han pagado " .. cuanto .. " $")
        else
            TriggerClientEvent("rp:error", de, "No tienes bastante dinero")
        end
    end)
end

return BdPersonajes

Para cobrar desde otro script del servidor (una tienda): Global("BdPersonajes"):Cobrar(jugador, 50, function(ok) if ok then DarObjeto(jugador) end end).

Lo importante:

  • La cuenta la pone el servidor (Persistence.GetAccount(source)), nunca el cliente: así nadie elige un personaje ajeno. Por eso FindOne busca por id y account.
  • El dinero solo lo cambia Increment (con min = 0) o una Transaction. Nunca «leo el dinero, le resto y lo guardo» en dos pasos: si dos tiendas cobran a la vez, una de las dos restas se perdería.
  • Todo lo que llega del cliente se comprueba (tipos, largos, que el personaje sea suyo).

7. SQL de verdad con Database.Query (y por qué siempre con parámetros)#

Para lo que no cabe en Find (mayor que, entre dos valores, sumar, juntar dos tablas), escribe SQL. Cada ? se rellena con un valor de la lista, en orden:

Lua
-- Los 10 personajes más ricos (dinero en mano + banco)
Database.Query("SELECT first_name, cash + bank AS total FROM characters ORDER BY total DESC LIMIT ?", { 10 }, function(filas, err)
    if err then print(err) return end
    for i, p in filas do print(i, p.first_name, p.total) end
end)

-- Los coches de los personajes de una cuenta (dos tablas juntas)
Database.Query([[
    SELECT v.plate, v.model, c.first_name
    FROM vehicles v JOIN characters c ON c.id = v.owner
    WHERE c.account = ?
]], { cuenta }, function(coches) print(#coches, "coches") end)

-- Lo que no devuelve filas: info dice cuántas cambió
Database.Query("UPDATE characters SET bank = bank + ? WHERE job = ?", { 100, "policia" }, function(_, err, info)
    if not err then print("Sueldo pagado a", info.changes, "policías") end
end)

Nunca pegues un texto del jugador dentro del SQL. Imagina que buscas un personaje por el nombre que escribe el jugador y lo pegas con ..:

Lua
-- MAL: si el jugador escribe   x' OR '1'='1   el SQL queda «WHERE first_name = 'x' OR '1'='1'» y devuelve TODOS
Database.Query("SELECT * FROM characters WHERE first_name = '" .. nombre .. "'", nil, function() end)

-- BIEN: el nombre va aparte; la base de datos lo trata siempre como un texto, ponga lo que ponga
Database.Query("SELECT * FROM characters WHERE first_name = ?", { nombre }, function() end)

Eso es la inyección SQL: con el texto adecuado, alguien podría leer datos de otros, darse dinero o borrar tablas. Con ? es imposible, porque el valor nunca forma parte del SQL. Las funciones Insert, Find, Update... usan ? siempre por dentro. Además, Database.Query solo deja una sentencia cada vez (un ; con algo detrás es un error), ni PRAGMA, ATTACH o BEGIN/COMMIT (para varias cosas de una vez está Database.Transaction).

En las respuestas de Query, las columnas de una tabla salen con su tipo (bool, vec3, json...); las calculadas (cash + bank AS total, COUNT(*)) salen como números o textos.

8. Seguridad: el servidor decide#

  • Database solo funciona en el servidor: el anfitrión, NovaServer.exe o una partida sin red. En un cliente da el error «Database solo funciona en el servidor». El cliente pide con un evento (TriggerServerEvent) y el servidor decide si lo hace (ver seguridad-red.md).
  • En modo remoto hace falta además la clave de servidor del juego (la misma que usa Persistence; nunca va en el juego publicado): por eso el anfitrión jugador, que no la tiene, no puede usar Database en modo remoto. Los datos con valor de un juego publicado los guarda un servidor tuyo.
  • Comprueba lo que manda el cliente: tipos (type(x) == "number"), largos, rangos, y que lo que pide sea suyo.
  • Siempre parámetros en Database.Query (sección 7).
  • Modo local: el fichero está en tu PC sin contraseña. Vale para desarrollar y para un servidor que es tuyo; un jugador con el juego publicado en modo local podría editar su propio fichero.

9. La ventana Base de datos del editor#

Ventana > Scripts > Base de datos (o Ajustes del proyecto > Datos > Abrir base de datos). Tiene dos pestañas arriba: Tablas (Database), lo de esta sección, y Partidas (SaveGame), las partidas que guardan tus scripts con SaveGame.Save.

La pestaña Tablas (Database) enseña el base-datos.db del modo local de este PC, el mismo que usa el juego al pulsar Jugar y NovaServer.exe:

  • A la izquierda, las tablas con cuántas filas tienen, y Crear tabla (lo mismo que Database.CreateTable).
  • Filas: la rejilla con las columnas y su tipo. Por páginas de 50, ordena con un clic en el título de una columna y busca un texto en todas las columnas. Los vec3 salen como (1.00, 2.00, 3.00), los colores con su muestra, los bool como true/false, las horas como fecha y el JSON en una línea (pasa el ratón para verlo entero).
    • Doble clic en una celda para cambiarla: sale el valor de antes y el de después, y solo se guarda al pulsar Guardar el cambio. Se comprueba el tipo (un int tiene que ser un número entero, un vec3 tres números, un json JSON válido...). NULL deja la celda vacía.
    • Añadir fila, Borrar fila (la elegida, con confirmación) y Exportar CSV (toda la tabla, con la búsqueda y el orden de ahora, a la carpeta exportado junto a base-datos.db; se abre con Excel o Google Sheets).
  • Estructura: las columnas con su tipo amigable, el de SQLite, si son obligatorias y su valor por defecto; y Añadir columna.
  • SQL: escribe una consulta y Ejecutar (o Ctrl+Intro). Las que solo leen (SELECT) van directas; las que cambian datos (INSERT, UPDATE, DELETE, CREATE, DROP...) piden confirmación.
  • Persistence > Documentos: los documentos de Persistence del modo local, por cuenta y clave, con su versión y el JSON en árbol. Solo para ver.
  • Mientras juegas, con Actualizar sola al jugar la ventana vuelve a leer la base de datos cada segundo: ves lo que guardan tus scripts al momento. También hay Actualizar y Abrir carpeta.

En modo remoto, la ventana sigue enseñando la base de datos local de tu PC (lo avisa arriba): la del servicio Nova Datos todavía no se puede ver desde el editor.

Partidas (SaveGame)#

La pestaña Partidas (SaveGame) enseña las partidas que guardan tus scripts con SaveGame.Save (ficheros .json de la carpeta de guardado del juego), para ver qué se guardó de verdad y cambiarlo a mano al probar: darte dinero, saltar a un nivel, romper una partida a propósito.

  • Carpeta: Editor (guardado-editor), donde guardan tus scripts al pulsar Jugar en el editor, o Juego (guardado), la de NovaGame.exe en este PC (el juego publicado). Las dos están en %LOCALAPPDATA%\<juego>\.
  • A la izquierda, las partidas con su tamaño y la fecha de la última vez que se guardaron. Con Actualizar sola al jugar, mientras juegas la lista y la partida abierta se vuelven a leer cada segundo: ves al momento lo que guarda tu script (si la abierta tiene cambios sin guardar, no se toca; sale un aviso).
  • El árbol con las columnas Clave, Tipo y Valor: tablas ({3 claves}) y listas ([5 elementos]) que se abren, números, textos, booleanos, Vec2/Vec3/Vec4/Quat como (1.00, 2.00, 3.00), colores con su muestra y su #RRGGBB, y assets con su ruta. Las claves salen como en Lua: [5] es la clave numérica 5 de una tabla con huecos.
  • Buscar por clave: escribe parte de una clave (posic) y el árbol se queda con lo que coincide, con dónde está y con lo que tiene dentro.
  • Editar: elige un valor del árbol y cámbialo abajo: un número o un texto escribiéndolo, un booleano con la casilla, un vector con sus números, un color con el selector y un asset con su ruta (models/coche.glb) o su id. El desplegable de al lado cambia el tipo del valor. En una tabla, Añadir clave (un nombre, o [3] para una clave numérica) y en una lista Añadir elemento, del tipo que elijas. Quitar (con confirmación) quita una clave o un elemento: los de detrás de un elemento de lista bajan uno, como table.remove.
  • Los cambios se quedan en la ventana (la partida sale con * y (cambios sin guardar)) hasta que pulsas Guardar cambios y lo confirmas. Se escribe con el mismo formato y los mismos límites que SaveGame.Save: claves ordenadas, una tabla con claves [1] a [n] se guarda como lista, el tamaño máximo (guardadoMaxKB), sin NaN ni valores vacíos dentro de tablas y hasta 32 niveles. Si algo no vale, lo dice y no escribe nada. Guardar sin cambiar nada deja el fichero igual, byte a byte. Descartar vuelve a lo que hay en el disco.
  • Si el juego está en marcha, la ventana lo avisa: si tu script vuelve a llamar a SaveGame.Save con esa partida, sobrescribe tus cambios, y lo que ya cargó con SaveGame.Load no cambia hasta que la vuelva a cargar. Lo normal es cambiar la partida con el juego parado y luego pulsar Jugar.
  • Duplicar (con un nombre que valga para SaveGame: letras sin tildes, números, _ y -), Exportar JSON (un .json fácil de leer en la carpeta exportado, junto a partidas: claves como en Lua, {"type": "Vec3", "x": 1, ...}, colores con hex y assets con path), Borrar partida (con confirmación; lo mismo que SaveGame.Delete) y Abrir carpeta en el Explorador.

10. Modo remoto (publicar)#

Con Ajustes del proyecto > Datos > Modo: Remoto, Database usa el servicio Nova Datos que ya despliegas para Persistence (datos-persistentes.md, sección 6): cada juego tiene su propia base de datos (un objeto con SQLite en Cloudflare, aparte de las cuentas y los documentos) y solo la usan tus servidores con la clave de servidor del juego, con cada petición firmada como las de Persistence.

  • Si ya tenías el servicio desplegado, vuelve a desplegarlo (desplegar.cmd > 1): la base de datos es una clase nueva del servicio y se crea sola al desplegar (no se toca nada de lo que ya había).
  • Los servidores necesitan la clave como siempre: NOVA_DATOS_CLAVE o clave-datos.txt junto a NovaServer.exe (sección 7 de datos-persistentes.md).
  • Las funciones y las respuestas son las mismas que en local; las peticiones que se piden en el mismo frame viajan juntas en una sola (en orden).
  • Para probarlo sin desplegar, el servicio local de Node también tiene la base de datos: node datos-server\local\servidor-local.js (con --guardar datos.json, las tablas se quedan en datos.json.bd_<juego>.sqlite).

Estado: el modo remoto está probado en este PC de dos formas: con el servicio local de Node (el mismo código sobre un entorno que imita a Cloudflare, con el SQLite de Node; lo usan las pruebas del motor) y con workerd, el runtime de Cloudflare, gracias a Miniflare (datos-server\herramientas\probar-bd-workerd.mjs). Aún no se ha probado desplegado en Cloudflare.

11. De Persistence a Database#

Si tu juego ya guarda datos con Persistence (por ejemplo, la lista de personajes de cada cuenta en un documento personajes) y quieres pasarlos a una tabla, hazlo una vez desde el servidor: lee el documento de cada jugador cuando entra y, si aún no se migró, crea sus filas y marca el documento como migrado, todo de una vez con una transacción para que no se dupliquen si el servidor se cae a medias.

Lua
--[Global]
local BdMigrarPersonajes = Script()

function BdMigrarPersonajes:Awake()
    if not IsServer() then return end
    Database.CreateTable("characters", {
        id = "id", account = "text index", first_name = "text required", last_name = "text required",
        cash = "int default 500", pos = "vec3",
    })
    -- Cuentas ya migradas (una fila por cuenta: si está, no se repite)
    Database.CreateTable("migrations", { id = "id", account = "text unique", time = "time" })

    AddEventHandler("playerAccount", function(_jugador, cuenta)
        -- 1. ¿Ya se migró esta cuenta?
        Database.FindOne("migrations", { account = cuenta }, function(hecha, err)
            if err or hecha then return end
            -- 2. Lo que había en Persistence: { { nombre = "Ana", apellido = "Ruiz", dinero = 450 }, ... }
            Persistence.Get(cuenta, "personajes", function(lista)
                if type(lista) ~= "table" then lista = {} end
                -- 3. Todo de una vez: sus personajes y la marca de migrada (unique: dos servidores no lo duplican)
                Database.Transaction(function(tx)
                    for _, p in lista do
                        tx.Insert("characters", {
                            account = cuenta,
                            first_name = tostring(p.nombre or "Sin nombre"),
                            last_name = tostring(p.apellido or "-"),
                            cash = math.floor(tonumber(p.dinero) or 500),
                        })
                    end
                    tx.Insert("migrations", { account = cuenta, time = Database.Now() })
                end, function(ok, err2)
                    if ok then
                        Log.Info("Migrada la cuenta " .. cuenta .. " (" .. #lista .. " personajes)")
                    elseif err2 then
                        Log.Warn("No se migró " .. cuenta .. ": " .. err2)
                    end
                end)
            end)
        end)
    end)
end

return BdMigrarPersonajes
  • El documento de Persistence no se borra: si algo sale mal, sigue ahí. Cuando lo hayas comprobado (en la ventana Base de datos ves las dos cosas: las tablas y, en Persistence > Documentos, los documentos), puedes borrarlo con Persistence.Delete(cuenta, "personajes").
  • La columna unique de migrations es lo que impide migrar dos veces aunque el jugador entre en dos servidores a la vez: la segunda transacción falla entera y no crea personajes repetidos.
  • Para datos de jugadores que no vuelven a entrar, haz lo mismo desde un script de una sola vez que recorra las cuentas que conozcas (en modo local, son las carpetas de datos-locales).

12. Límites#

Límite Local Remoto
Filas que devuelve una consulta 10.000 (más: info.truncated) 1.000
Operaciones de una transacción unas 60 unas 60
Tamaño de una petición — 256 KB
Tamaño de la base de datos El disco El de tu plan de Cloudflare (el gratuito: 5 GB en total, junto con Persistence)
  • Rendimiento local: miles de operaciones por segundo. Si el editor y un NovaServer.exe del mismo juego escriben a la vez en el mismo fichero, se esperan por turnos (hasta 5 segundos; si no, error «ocupada»).
  • Rendimiento remoto: cada frame, lo pedido viaja en una petición; cuenta como 1 petición al Worker y 1 al objeto (datos-persistentes.md, sección 8). Guardar la posición de 30 jugadores cada 30 segundos son 2 peticiones por minuto.
  • Los números enteros son exactos hasta 2^53 (unos 9.000 billones: de sobra para el dinero).
  • Para que buscar sea rápido con muchas filas, pon index en las columnas de tus filtros.

13. Problemas#

Mensaje Qué pasa
«Database solo funciona en el servidor» Lo llamas en un cliente: pide los datos al servidor con un evento
«En modo remoto, Database solo funciona en un servidor con la clave de servidor del juego» El anfitrión jugador o un servidor sin NOVA_DATOS_CLAVE: usa un NovaServer.exe con la clave, o el modo local
«No existe la tabla 'x' (créala antes con Database.CreateTable)» Falta el CreateTable (o está escrita de otra forma)
«La tabla 'x' no tiene la columna 'y'» Una columna mal escrita, o falta en CreateTable
«la columna 'cash' de 'characters' es int y le das un string» El tipo del valor no es el de la columna
«'cash' quedaría por debajo de 0 (no se ha cambiado nada)» Increment con min: no alcanza el dinero. En una transacción, no se hizo nada de ella
«No hay ninguna fila en 'x' que cumpla el filtro» Increment sobre una fila que no existe
«Ya hay una fila con ese valor en 'plate' (la columna es única: unique)» Un valor repetido en una columna unique
«Falta el valor de 'first_name' (la columna es obligatoria: required)» Insert sin una columna required
«el filtro está vacío y cambiaría TODAS las filas» Update, Delete o Increment con {}: pon un filtro o usa Database.Query
«falta la función que recibe la respuesta» Find, FindOne, Count o Query sin función fuera de una tarea
«Una sola sentencia cada vez» Un ; en medio del SQL de Database.Query
«Esa sentencia no está permitida aquí» PRAGMA, ATTACH, BEGIN/COMMIT en Database.Query: usa Database.Transaction
«La base de datos está ocupada por otro proceso» Otro servidor (o el editor) escribía a la vez durante más de 5 s: vuelve a intentarlo
