Los datos de un juego (los objetos que se pueden robar, las armas, los niveles, las recompensas...) no deberían estar escritos dentro del código. Nova Engine tiene herramientas para separarlos, todas declaradas en Lua y editables en el editor:

En Nova Para qué
Struct({...}) un tipo de datos con sus campos (nombre, precio, peso, icono...)
List(...), Dict(...) listas y diccionarios en el Inspector
Data Asset (.datos) un asset con los valores de un struct: Lingote.datos
Data Table (.tabla) filas de un struct, como una hoja de cálculo, con CSV
Enum (.enum) una lista de valores con nombre que comparten varios scripts
Curva (.curva, Curve()) una función y = f(x) dibujada con puntos

Todo se guarda con la escena o el prefab (o en su propio asset), tiene deshacer y rehacer, funciona en la edición en equipo, se recarga en caliente al cambiarlo, viaja en el .novapak al publicar y sale en el autocompletado de VS Code y del editor de scripts.

El ejemplo completo de esta guía está en game/botin_lua, en el código del motor (ábrelo con Archivo > Abrir proyecto). Con el motor instalado, los pasos de abajo lo montan desde un proyecto «Vacío (Lua)» en unos minutos.

Paso a paso: el botín de un juego de robos#

1. El tipo de datos: Struct#

Un objeto del botín tiene un nombre, un precio, un peso, un tipo y un icono. Se declara una vez, en un módulo (un script que no es una clase y que otros piden con require), por ejemplo scripts/datos/Objeto.luau:

Lua
local Objeto = Struct({
    nombre = "",
    --[Tooltip("Lo que paga el perista")]
    precio = 0, --[Int]
    --[Range(0, 50)]
    peso = 1.0,
    tipo = Enum("TipoObjeto", "Botín"), -- el enum compartido (paso 5)
    icono = Asset("Texture"),
    --[Range(0, 1)]
    rareza = 0.5,
})

return Objeto
  • Cada campo es como un campo de un script: el tipo sale del valor (número, texto, booleano, Vec3, Color, Entity(), Asset("Tipo"), Enum(...), otro struct, List(...), Curve()...) y el valor es el de por defecto.
  • Los atributos van igual que en los scripts (--[Range(0, 1)], --[Int], --[Tooltip("...")]...), al final de la línea del campo o en la línea de encima.
  • Los campos salen en el orden en el que están escritos (en el Inspector y en las columnas de las tablas).
  • El nombre del struct es el del local (Objeto). También se puede dar a mano: Struct("Objeto", {...}).
  • Si cambias el struct (un campo nuevo, otro valor por defecto), los scripts que lo usan se recargan y los valores ya guardados se conservan por nombre: un campo nuevo sale con su valor por defecto y uno que desaparece se ignora.

2. Una lista de structs en el Inspector#

En el script de la furgoneta de la banda (scripts/Botin.luau):

Lua
local Objeto = require("./datos/Objeto")

local Botin = Script()

--[Header("Botín")]
Botin.furgoneta = List(Objeto)   -- lo que lleva la banda
Botin.destacado = Asset("Objeto") -- un Data Asset de tipo Objeto (paso 3)
Botin.calor = 0.2 --[Range(0, 1)]
Botin.pagoSegunCalor = Curve("EaseIn") -- paso 6

return Botin

En el Inspector, Furgoneta es una lista plegable:

  • + añade un elemento (con los valores por defecto del struct) y × vacía la lista.
  • Cada elemento se despliega con sus campos, como un componente. El botón de la papelera lo quita.
  • El asa (⋯) de cada elemento: arrástrala encima del asa de otro elemento para moverlo ahí, o haz clic para Duplicar, Subir, Bajar o Quitar.
  • Todo se deshace con Ctrl+Z y llega a los demás en la edición en equipo.

Otras formas de declarar listas y diccionarios:

Lua
Botin.pesos = List(0)                     -- lista de números
Botin.nombres = List("", { "a", "b" })     -- de textos, con valores iniciales
Botin.puertas = List(Entity())            -- de entidades
Botin.iconos = List(Asset("Texture"))     -- de assets
Botin.multiplicadores = Dict(1.0)         -- diccionario texto -> número
Botin.porTienda = Dict(Objeto)            -- texto -> struct
Botin.precios = { 10, 20 } --[List(number)] -- una tabla con su tipo en un atributo
Botin.extras = {} --[List(Objeto)]           -- (también --[List(Asset, "Texture")] y --[Dict(number)])
Botin.especial = Objeto({ nombre = "Corona", precio = 5000 }) -- un struct con otros valores por defecto

3. Data Assets: un asset por objeto#

Un Data Asset es un fichero .datos con los valores de un struct: Lingote.datos, Corona.datos... Así un diseñador cambia el precio del lingote sin tocar ningún script ni ninguna escena.

  1. En Contenido, entra en la carpeta donde lo quieres (por ejemplo datos/objetos).
  2. Crear > Datos (Data Asset) > Objeto. El menú lista los structs de tus scripts.
  3. Elígelo: el Inspector enseña sus campos, como un componente. Cada cambio se guarda al soltar el campo, con deshacer.
  4. Para usarlo, arrástralo a un campo Asset("Objeto") de un script (el selector solo ofrece Data Assets de ese tipo; Asset("DataAsset") acepta cualquiera).

En Lua, el asset se lee como una tabla:

Lua
local d = self.destacado      -- campo Asset("Objeto")
print(d.nombre, d.precio)     -- sus valores
local todo = d:Get()          -- la tabla entera
local lingote = DataAsset("Lingote")          -- por su nombre (o su ruta: "datos/objetos/Lingote.datos")

4. La Data Table del botín (y Excel)#

Con muchos objetos es más cómodo una tabla: una fila por objeto, una columna por campo.

  1. Contenido > Crear > Tabla de datos > Objeto. Se abre la ventana Tabla de datos (también con doble clic en una .tabla, o Ventana > Tabla de datos).
  2. + Fila añade una fila con los valores por defecto. La primera columna es la clave de la fila (Corona, Lingote...): doble clic en ella para cambiarla (no puede repetirse).
  3. Cada celda se edita en su sitio (números, textos, casillas, desplegables de enums y de assets). Las celdas de structs, listas y curvas se editan con su botón ⋯.
  4. Buscar filtra las filas (por cualquier celda, sin importar tildes) y un clic en una cabecera ordena la vista.
  5. Duplicar y Borrar actúan sobre la fila elegida. Todo tiene deshacer.

CSV y hojas de cálculo:

  • Exportar CSV… guarda la tabla en un .csv (primera columna clave, una por campo).
  • Importar CSV… sustituye las filas por las del fichero: separador ,, ; o tabulador, comillas, números con punto o con coma (12,5). Las columnas se reconocen por el nombre del campo o por su nombre visible; las que no son campos se ignoran con un aviso.
  • Copiar deja las filas (o la elegida) con tabuladores para pegarlas en Excel o Google Sheets, y Pegar hace lo contrario: con la fila de cabecera, las filas se ponen por clave (las que ya están solo cambian en las columnas pegadas); sin cabecera, las celdas van por orden desde la fila elegida.

En Lua:

Lua
local t = DataTable("Botin")               -- por su nombre o su ruta
print(t:Row("Corona").precio)              -- una fila (nil si no existe)
for _, fila in t:Rows() do                 -- todas, en su orden; cada una con .key
    print(fila.key, fila.precio)
end
local caros = t:Filter(function(f) return f.precio >= 1000 end)
local barato = t:Find(function(f, clave) return f.precio < 100 end)
print(t:Count(), t:Has("Reloj"), table.concat(t:Keys(), ", "))

Las filas son de solo lectura (las comparten todos los scripts). Para cambiar algo en la partida, cópialo: local mio = table.clone(t:Row("Corona")).

5. Un enum compartido#

El tipo de objeto (Arma, Botín, Consumible) lo usan varios structs y scripts. En vez de escribir la lista en cada sitio:

  1. Contenido > Crear > Enum y renómbralo TipoObjeto.enum.
  2. En el Inspector, Añadir valor, cambia los nombres y ordénalos.
  3. Úsalo con su nombre: Enum("TipoObjeto") o con otro valor por defecto: Enum("TipoObjeto", "Arma").

El Inspector enseña un desplegable y en Lua el valor es el texto (if o.tipo == "Arma" then). Cambiar el nombre de un valor no cambia los que ya estaban guardados.

También se puede compartir un enum desde un módulo de Lua:

Lua
-- scripts/datos/Tipos.luau
local Tipos = {}
Tipos.Rareza = Enum({ "Común", "Rara", "Épica" })
return Tipos

-- en otro script
local Tipos = require("./datos/Tipos")
Arma.rareza = Tipos.Rareza                 -- el primero por defecto
Arma.rarezaJefe = Tipos.Rareza:Default("Épica")

6. Curvas#

Cuánto paga el perista según lo «caliente» que esté el botín: poco recién robado, el precio entero cuando ya nadie lo busca. Eso es una curva.

  • Como campo: Botin.pagoSegunCalor = Curve() (o un preajuste: Curve("Smooth"), "Linear", "EaseIn", "EaseOut", "Constant", "Flat", "Bell"; o puntos: Curve({ {0, 0.2}, {1, 1} })). En el Inspector se ve en pequeño y, desplegada, se edita.
  • Como asset compartido: Contenido > Crear > Curva (.curva); se edita en el Inspector y se usa en un campo Asset("Curve").

En el editor de curvas: arrastra los puntos, doble clic en un hueco añade uno y el clic derecho en un punto cambia su interpolación hasta el siguiente (constante, lineal, Bézier, entrada suave, salida suave, suave), sus tangentes (automáticas, libres —con asas para arrastrar— o planas) o lo quita. El clic derecho en un hueco aplica un preajuste. Son las mismas curvas que la Línea de tiempo.

En Lua:

Lua
local factor = self.pagoSegunCalor:Evaluate(1 - self.calor)   -- campo Curve()
local f2 = self.curvaDelPerista:Evaluate(0.5)                 -- campo Asset("Curve")

Antes del primer punto vale lo del primero y después del último, lo del último. curva.minX, curva.maxX, curva.count y curva:Points() dan sus puntos.

7. Todo junto#

Lua
function Botin:Valor(objeto)
    local curva = self.curvaDelPerista or self.pagoSegunCalor
    return math.floor(objeto.precio * curva:Evaluate(1 - self.calor) + 0.5)
end

function Botin:Start()
    local tabla = DataTable("Botin")
    local total = 0
    for _, objeto in self.furgoneta do
        total += self:Valor(tabla:Row(objeto.nombre) or objeto)
    end
    print("La furgoneta vale", total)
end

Valores en Lua: copias#

self.furgoneta, self.destacado (de un struct) y los demás campos compuestos devuelven una copia como tabla de Lua. Cambiarla no cambia el campo: hay que volver a asignarla.

Lua
local lista = self.furgoneta
table.insert(lista, Objeto({ nombre = "Cuadro", precio = 900 }))
self.furgoneta = lista               -- ahora sí
self.precios = { oro = 11 }          -- un diccionario entero

Guarda la copia en un local si la usas varias veces en el mismo frame (cada lectura crea una tabla). Objeto() crea un valor con los valores por defecto y Objeto({ precio = 5 }), con esos cambios.

Multijugador#

Los structs y las listas no se replican como campos (no caben en las instantáneas de la red, que llevan valores pequeños): si pones --[Replicated] encima, el motor avisa. Para enviarlos a los clientes, guárdalos en una tabla replicada, que respeta sus límites (1024 claves y 64 KB por tabla):

Lua
--[Replicated]
Caja.contenido = {}

function Caja:Start()
    if self:IsServer() then
        self.contenido.objeto = self.objeto            -- un struct
        self.contenido.lista = { Objeto({ nombre = "A" }), Objeto({ nombre = "B" }) }
    end
end

Las Data Tables, los Data Assets, los enums y las curvas son assets: los tienen todos los jugadores (van en el juego), así que no hace falta enviarlos.

Publicar#

No hay que hacer nada: los .datos, .tabla, .enum y .curva van en el .novapak como cualquier otro asset, y los scripts guardan en su bytecode el orden de los campos de sus structs.

Autocompletado#

nova.d.luau (VS Code y el editor de scripts integrado) declara:

  • un tipo por cada struct (Objeto con sus campos y sus tipos; los enums, con sus valores entre comillas);
  • DataTable("Botin") con el tipo de sus filas: t:Row("Corona"). completa precio, peso...;
  • los enums compartidos como tipos (TipoObjeto);
  • los campos de tus scripts: List(Objeto) es {Objeto}, Asset("Objeto") es un asset con los campos de Objeto, Enum({...}) y Enum("TipoObjeto") sus valores y Curve() una CurveValue con Evaluate.

Se rehace solo al guardar un script o al crear una tabla o un enum (si el proyecto ya usa nova.d.luau).

Ficheros#

Son JSON (se pueden revisar en git o editar con un editor de texto; el motor los recarga al guardarlos):

JSON
// datos/objetos/Lingote.datos
{ "formato": "nova-datos", "version": 1, "tipo": "Objeto",
  "valores": { "nombre": "Lingote de oro", "precio": 500, "peso": 12.5, "tipo": "Botín", "icono": null, "rareza": 0.3 } }

// datos/Botin.tabla
{ "formato": "nova-tabla", "version": 1, "tipo": "Objeto",
  "filas": [ { "clave": "Corona", "valores": { "nombre": "Corona real", "precio": 5000 } } ] }

// datos/TipoObjeto.enum
{ "formato": "nova-enum", "version": 1, "valores": ["Arma", "Botín", "Consumible"] }

// datos/PagoSegunCalor.curva
{ "formato": "nova-curva", "version": 1,
  "claves": [ { "t": 0, "v": 0.25, "entrada": 0, "salida": 0, "interp": "Smooth", "tangentes": "Auto" } ] }

Un campo que falta toma su valor por defecto y uno que sobra se ignora.

Avisos y límites#

  • Un Struct sin nombre (sin local ni nombre a mano) se llama Struct<línea> y avisa: dale un nombre para usarlo en Data Assets y tablas.
  • Dos structs con el mismo nombre en scripts distintos: gana el último que se carga.
  • Si un Data Asset o una tabla son de un struct que ya no existe (renombrado, o un script con errores), el editor lo dice y no los toca: los valores siguen en el fichero.
  • Enum("Nombre") necesita que exista Nombre.enum en assets/: si no, el script no carga y la Consola lo dice.
  • Asset("DataAsset"), Asset("DataTable") y Asset("Curve") (hasta la 0.9.36, "Datos", "Tabla" y "Curva", que siguen valiendo con un aviso) aceptan cualquier asset de esa clase; Asset("Objeto"), solo Data Assets de ese struct.
  • En un asset, id, path y valid son del asset: si tu struct tiene un campo con ese nombre, léelo con asset:Get().id.
