Herramientas para programar juegos en Lua sin repetir código: Gameplay Tags (etiquetas jerárquicas), interfaces (contratos que cumplen varios scripts), eventos del Inspector, temporizadores con mango y pools de objetos (también de objetos de red).

Todo funciona igual en el editor, en NovaGame.exe y en NovaServer.exe, y tiene sus tipos en nova.d.luau (autocompletado en VS Code y en el editor de scripts integrado).

1. Gameplay Tags: etiquetas jerárquicas#

Una etiqueta de juego es un nombre con partes separadas por puntos: Estado.Herido, Objeto.Botin.Oro, Arma.Pistola. Objeto.Botin.Oro es hija de Objeto.Botin, que es hija de Objeto. Preguntar por una etiqueta encaja con ella y con todas sus hijas:

Lua
entidad:HasTag("Objeto.Botin")      -- true si tiene Objeto.Botin, Objeto.Botin.Oro, Objeto.Botin.Plata...
entidad:HasTagExact("Objeto.Botin") -- solo Objeto.Botin
Tags.Matches("Objeto.Botin.Oro", "Objeto.Botin") -- true

Se compara por partes: Objeto.Bot no encaja con Objeto.Botin.

Son las etiquetas de siempre#

Las etiquetas de juego son las del componente Etiquetas (Tags) que ya usabas con Scene.FindByTag. Una etiqueta sin puntos ("Enemigo") funciona exactamente igual que antes. Lo que cambia:

  • entidad:HasTag("X") ahora también es true si la entidad tiene una hija de X (X.Algo). Con etiquetas sin puntos no cambia nada.
  • Scene.FindByTag y Scene.FindAllByTag siguen siendo exactas (como siempre). Las jerárquicas son Scene.FindWithTag y Scene.FindAllWithTag.
  • Las IA, los decals y la vegetación siguen comparando sus etiquetas exactas.

Declararlas en el proyecto#

En Ventana > Scripts > Etiquetas de juego se ve el árbol de las etiquetas del proyecto. Se guardan en assets/etiquetas.json (va con el juego publicado).

  • + Etiqueta añade una en la raíz; + Hija, una dentro de la elegida.
  • Renombrar enseña antes en qué escenas, prefabs y scripts se usa (y cuántas veces). Con Cambiar también sus usos se cambian a la vez en esos ficheros (dentro de comillas en los scripts) y en la escena abierta, con deshacer.
  • Borrar quita la etiqueta y sus hijas del proyecto. Los usos no se tocan: siguen funcionando en los scripts, pero ya no salen en el selector.
  • Cada etiqueta puede llevar un comentario (para qué sirve), que sale al pasar el ratón.

Declararlas no es obligatorio: un script puede usar cualquier nombre válido. Las declaradas salen en el selector del Inspector, en el autocompletado (HasTag(" y te las propone) y viajan más cortas por la red.

En el Inspector#

El componente Etiquetas y los campos Tags() de los scripts se ven como «chips» (clic para quitar una) y un botón + con el árbol de las del proyecto (con buscador) y una caja para escribir otra. Una etiqueta que no está declarada se ve en amarillo. Todo tiene deshacer (Ctrl+Z).

Campos Tags()#

Un campo Tags() es un contenedor de etiquetas que se edita en el Inspector y se guarda con la escena. En Lua es un TagContainer unido al campo: lo que añadas o quites cambia el campo.

Lua
-- Estados con etiquetas: un solo sitio con todo lo que le pasa al jugador
local EstadosDelJugador = Script()
EstadosDelJugador.estado = Tags({ "Estado.Vivo" })
EstadosDelJugador.inmune = Tags() -- se rellena en el Inspector (p. ej. Estado.Envenenado)

function EstadosDelJugador:Herir(cantidad: number)
    if self.estado:HasAny({ "Estado.Muerto", "Estado.Invulnerable" }) then
        return
    end
    self.estado:Add("Estado.Herido")
    if cantidad > 50 then
        self.estado:Remove({ "Estado.Vivo", "Estado.Herido" })
        self.estado:Add("Estado.Muerto")
    end
end

function EstadosDelJugador:Envenenar()
    if self.inmune:Has("Estado.Envenenado") then
        return -- inmune
    end
    self.estado:Add("Estado.Envenenado")
    -- Las etiquetas de la entidad (componente Etiquetas) tambien: se replican si tiene Identidad de red
    self.entity:AddTag("Estado.Envenenado")
end

function EstadosDelJugador:PuedeCorrer(): boolean
    return self.estado:Has("Estado.Vivo") and not self.estado:Has("Estado.Herido")
end

return EstadosDelJugador
TagContainer Qué hace
c:Has(etiqueta) Alguna encaja (jerárquico)
c:HasExact(etiqueta) Tiene exactamente esa
c:HasAny(lista) / c:HasAll(lista) Encaja con alguna / con todas (jerárquico). La lista puede ser una etiqueta, {...} u otro contenedor
c:Add(...) / c:Remove(...) Añade las que falten / quita esas (exactas). true si cambió algo
c:Clear(), c:GetAll(), c:Count() (o #c), c:Copy() Vaciar, lista de textos, cuántas, copia suelta

self.campo = { "A", "B" } sustituye el contenido del campo. Tags.Container({...}) crea un contenedor suelto.

En las entidades#

Entidad Qué hace
e:HasTag(t) Tiene t o una hija suya
e:HasTagExact(t) Tiene exactamente t
e:HasAnyTag(lista) / e:HasAllTags(lista) Alguna / todas (jerárquico)
e:AddTag(t) / e:RemoveTag(t) Como siempre
e:GetTags() Sus etiquetas como TagContainer unido a la entidad (e:GetTags():Add("X") cambia la entidad)
Scene.FindAllWithTag(t) / Scene.FindWithTag(t) Las entidades con t o una hija (jerárquico)

En red#

Las etiquetas del componente Etiquetas de una entidad con Identidad de red se replican: lo que el servidor añade o quita (con AddTag, RemoveTag, GetTags(), e.tags = {...} o desde C++) llega a todos los clientes. Las del proyecto viajan por su número (#3) y las demás por su nombre; caben unos 256 bytes por entidad (de sobra para decenas de etiquetas del proyecto). Los campos Tags() de los scripts no se replican (como los structs): si los clientes los necesitan, usa las etiquetas de la entidad o una tabla replicada.

2. Interfaces#

Una interfaz es un contrato: una lista de funciones. Varios scripts distintos la cumplen y el que llama no necesita saber cuál es. Sirve para «cualquier cosa que se pueda recoger», «cualquier cosa que reciba daño»...

Declarar e implementar#

La interfaz va en un módulo (para que la usen varios scripts con require):

Lua
-- scripts/InterfazRecogible.luau: lo que tiene que tener todo lo que se puede recoger
return Interface("Recogible", { "AlCoger", "Descripcion" })

Sin nombre (Interface({ "AlCoger" })) se llama como el fichero. El script dice que la implementa con Clase:Implements(...) (con la interfaz o con su nombre; se puede encadenar con Script()):

Lua
local Recogible = require("./InterfazRecogible")

local BotinOro = Script()
BotinOro:Implements(Recogible)
BotinOro.valor = 250 --[Int]

function BotinOro:AlCoger(jugador: Entity): number
    Log.Info(jugador.name .. " recoge oro")
    self:Destroy()
    return self.valor
end

function BotinOro:Descripcion(): string
    return "Lingote de oro (" .. self.valor .. ")"
end

return BotinOro

Si un script dice implementar una interfaz y le falta una función, sale un aviso en la Consola con el fichero y la línea del Implements (también en el editor de scripts): BotinOro dice implementar la interfaz Recogible pero le falta la función Descripcion.

Llamar sin saber qué script es#

Lua
-- El jugador recoge lo que toca, sea lo que sea (oro, armas, llaves...)
local RecolectorBotin = Script()
RecolectorBotin.total = 0 --[Int]

function RecolectorBotin:OnTriggerEnter(otra: Entity)
    if not otra:Implements("Recogible") then
        return
    end
    -- Forma 1: Interfaces.Call devuelve lo que devuelva la funcion (nada si nadie la implementa)
    local valor = Interfaces.Call(otra, "Recogible", "AlCoger", self.entity)
    self.total += valor or 0
end

function RecolectorBotin:Mirar(otra: Entity)
    -- Forma 2: un objeto con las funciones de la interfaz
    local recogible = otra:GetInterface("Recogible")
    if recogible then
        Log.Info("Ves: " .. recogible:Descripcion())
    end
end

return RecolectorBotin
Función Qué hace
Interface(nombre?, { funciones }) Declara la interfaz (y la registra por su nombre)
Clase:Implements(interfaz o nombre) La clase la cumple (se comprueba al cargar el script)
e:Implements(interfaz) Algún script de la entidad la implementa
e:GetInterface(interfaz) Objeto con sus funciones (i:AlCoger(...); i.script es la instancia), o nil
Interfaces.Call(e, interfaz, "Funcion", ...) La función del primer script que la implementa; devuelve lo suyo
Interfaces.CallAll(e, interfaz, "Funcion", ...) En todos los que la implementan; devuelve cuántos
Interfaces.Implements(e, interfaz) Igual que e:Implements
Interfaces.Get(nombre) La interfaz registrada con ese nombre
interfaz:IsImplementedBy(e) Igual que e:Implements(interfaz)

Llamar a una función que no está en la interfaz es un error que dice cuáles tiene. En red, una función de la interfaz con [Server] o [Multicast] viaja por la red como siempre.

3. Eventos en el Inspector y por código#

Un campo Event() es una lista de enlaces que se rellena en el Inspector, sin código: cada uno es «entidad + script + función (+ un argumento opcional)». El script lo lanza con self.evento:Invoke(...) y se llama a todas esas funciones.

Paso a paso: una puerta que enciende una alarma#

Lua
local PuertaConEvento = Script()
--[Tooltip("Lo que pasa al abrirla (rellénalo en el Inspector)")]
PuertaConEvento.alAbrir = Event()
--[Hide]
PuertaConEvento.alCerrar = Event() -- solo por código: no sale en el Inspector
PuertaConEvento.abierta = false

function PuertaConEvento:Abrir(quien: Entity?)
    if self.abierta then
        return
    end
    self.abierta = true
    self.alAbrir:Invoke(quien) -- llama a los enlaces del Inspector y a los Connect
end

function PuertaConEvento:Cerrar()
    self.abierta = false
    self.alCerrar:Invoke()
end

return PuertaConEvento
Lua
local LuzDeAlarma = Script()

function LuzDeAlarma:Encender(quien: Entity?)
    Log.Info("¡Alarma! " .. (if quien then quien.name else "alguien") .. " ha abierto la puerta")
end

function LuzDeAlarma:Parpadear(veces: number)
    Log.Info("Parpadea " .. veces .. " veces")
end

return LuzDeAlarma
  1. Pon PuertaConEvento en la puerta y LuzDeAlarma en la luz.
  2. En el Inspector de la puerta, el campo Al Abrir es una lista: pulsa +.
  3. En el enlace nuevo, arrastra la luz desde la Jerarquía a Entidad (o elígela en la lista).
  4. Script: el desplegable enseña los scripts de esa entidad (o «el que tenga la función»).
  5. Función: el desplegable enseña las funciones de ese script: elige Encender.
  6. Opcional: Argumento. Vacío, la función recibe los argumentos de Invoke (aquí, quien). Con un valor (3, true, un texto), recibe solo ese: un segundo enlace a Parpadear con argumento 3.

La lista tiene lo de todas las listas del Inspector: arrastrar para ordenar, duplicar, quitar y vaciar, y todo con deshacer y rehacer (Ctrl+Z / Ctrl+Y, el historial de la barra). Una función que ya no existe se ve en amarillo; al lanzarse, un enlace a una entidad borrada o a una función que no existe da un aviso en la Consola (no un error).

Suscribirse por código#

Lua
local conexion = puerta:GetScript("PuertaConEvento").alAbrir:Connect(function(quien)
    Log.Info("se abrió")
end)
conexion:Disconnect() -- deja de recibirlo
ScriptEvent Qué hace
ev:Invoke(...) Llama a las suscripciones y después a los enlaces del Inspector. Devuelve cuántas funciones se llamaron
ev:Connect(fn) fn(...) en cada Invoke. Devuelve una conexión con :Disconnect() e :IsConnected()
ev:Once(fn) Como Connect, solo la próxima vez
ev:DisconnectAll() Quita las suscripciones por código (los enlaces del Inspector se quedan)
ev:ListenerCount() Suscripciones más enlaces
Event.new() Un evento suelto (sin Inspector) para un módulo: local AlMorir = Event.new()

Una suscripción se quita sola al destruirse quien se suscribió o el dueño del evento: nunca llama a un self que ya no existe. Un error dentro de una función suscrita o enlazada se escribe en la Consola y los demás se siguen llamando. self.evento = algo es un error: un Event() no se asigna.

Con prefabs#

Los enlaces guardan la entidad por su identificador, como los campos Entity(). Dentro de un prefab (la puerta con su luz hija), cada instancia enlaza con su luz: al instanciar, las referencias internas pasan a las entidades nuevas. Un enlace a una entidad de la escena (fuera del prefab) se queda apuntando a esa entidad.

En red: dónde se lanza#

Invoke se ejecuta en la máquina que lo llama, como una llamada normal: no envía nada por sí mismo. Lo normal en un juego en red:

  • Lanza el evento en el servidor (que es quien decide si la puerta se abre).
  • Las funciones enlazadas que tienen que verse en todos (la luz, el sonido) llévalas con [Multicast]: el enlace las llama a través de la instancia, así que una función [Multicast] llega a todos y una [Server] llamada desde un cliente viaja al servidor, igual que si la llamaras con self:Funcion(). Así funciona en anfitrión y cliente y en servidor dedicado.
  • Lo que solo es visual y local (un efecto en la pantalla de un jugador) puede lanzarse en el cliente.

Los enlaces existen en todas las máquinas (van en la escena o en el prefab), porque las entidades de red tienen el mismo identificador en todas.

4. Temporizadores con mango#

Timer es un temporizador que se puede parar, seguir, consultar y cancelar desde fuera:

Lua
local VenenoTemporizado = Script()
VenenoTemporizado.vida = 100

function VenenoTemporizado:Envenenar()
    if self._veneno and self._veneno:IsActive() then
        return
    end
    -- Cada 0,5 s quita 5 de vida; a los 4 s se cura solo
    self._veneno = Timer.Every(0.5, function()
        self.vida -= 5
    end)
    self._cura = Timer(4, function()
        self._veneno:Cancel()
    end)
end

function VenenoTemporizado:Pausar(pausado: boolean)
    for _, t in { self._veneno, self._cura } do
        if t then
            if pausado then t:Pause() else t:Resume() end
        end
    end
end

function VenenoTemporizado:OnGUI()
    if self._cura and self._cura:IsActive() then
        GUI.Begin("Veneno", 20, 20)
        GUI.Text(string.format("Curación en %.1f s", self._cura:Remaining()))
        GUI.End()
    end
end

return VenenoTemporizado
Función Qué hace
Timer(segundos, fn, opciones?) Llama a fn(t) una vez (también Timer.After)
Timer.Every(segundos, fn, opciones?) Llama a fn(t) cada tantos segundos
t:Cancel() Lo cancela (true si seguía activo)
t:Pause() / t:Resume() Lo para guardando lo que le falta / sigue desde ahí
t:Remaining() Segundos que faltan para la próxima llamada
t:IsActive() / t:IsPaused() Si va a volver a llamar (en pausa también) / si está en pausa
t:SetTimeScale(x) / t:GetTimeScale() Escala propia: 2 el doble de rápido, 0 congelado

Opciones: { unscaled = true } sigue con el juego en pausa (Time.timeScale = 0; menús), { timeScale = 2 } es la escala propia y { owner = entidad } lo ata a otra entidad (se cancela si se destruye).

  • Se cancela solo al destruirse el script que lo crea (o al recargar el fichero, si se creó al cargarlo). A diferencia de Task.*, no se cancela al desactivar el script.
  • La función se llama directamente: dentro no se puede esperar (Task.Wait); para eso, Task.Spawn.
  • SetTimeout, CreateThread, Wait y Task.* no cambian: Timer va sobre el mismo planificador.

5. Pools de objetos#

Crear y destruir entidades cuesta (instanciar el prefab, Awake, cuerpos de físicas...). Un pool las reutiliza: al «destruir» una, se desactiva y se guarda para la siguiente.

Lua
-- En el prefab de la bala: se reinicia al salir del pool
local BalaReutilizable = Script()
BalaReutilizable.velocidad = 40

function BalaReutilizable:OnPoolGet()
    self._vida = 0
    Physics.SetVelocity(self.entity, self.transform.forward * self.velocidad)
end

function BalaReutilizable:OnPoolRelease()
    -- lo que haya que limpiar (sus tareas de Task.* y sus tweens se cancelan solos)
end

function BalaReutilizable:OnCollisionEnter(c)
    Pool.Release(self.entity) -- vuelve al pool en lugar de destruirse
end

return BalaReutilizable
Lua
local ArmaConPool = Script()
--[Tooltip("Prefab de la bala (con BalaReutilizable y, si quieres, el componente Devolver al pool)")]
ArmaConPool.bala = Asset("Prefab")

function ArmaConPool:Start()
    if self.bala then
        self._pool = Pool(self.bala, { initial = 20, max = 200 })
    end
end

function ArmaConPool:Update(dt: number)
    if self._pool and Input.WasActionPressed("Disparar") then
        local cannon = self.entity.position + self.transform.forward
        self._pool:Get(cannon, self.entity.rotation)
    end
end

return ArmaConPool
  • Pool(prefab, { initial = 20, max = 200 }) crea el pool con 20 ya creadas (desactivadas). max es cuántas libres guarda como mucho (las demás se destruyen al devolverlas). Es lo mismo que Pool.Create(prefab, 20, { maxSize = 200 }).
  • pool:Get(posicion, rotacion) saca una (o crea otra si no queda ninguna), con su cuerpo parado en el sitio nuevo, y llama a OnPoolGet() de sus scripts y de los de sus hijos.
  • pool:Release(e) o Pool.Release(e, segundos?) llama a OnPoolRelease(), cancela sus tareas y tweens, la desactiva y la guarda. Una devolución con espera solo vale para esa salida: si la bala se devolvió y se volvió a sacar antes, no la devuelve.
  • El componente Devolver al pool (PoolReturn, en «Scripts») devuelve la entidad sola pasados N segundos desde que sale: perfecto para impactos, casquillos y balas perdidas.
  • Más: pool:Prewarm(n), pool:CountActive(), pool:CountInactive(), pool:Clear(), Pool.IsPooled(e) (nativas-juego.md).

En red: pools de objetos de red#

Con un prefab con Identidad de red, el pool es de objetos de red y se crea en el servidor (en un cliente es un error que lo dice):

  • Las entidades se crean una vez con Spawn (en el servidor y en todos los clientes) y después solo se activan y desactivan: el estado activo se replica, así que los clientes las ven aparecer y desaparecer sin crear ni destruir entidades de red.
  • Al sacarla hay un teletransporte de red: los clientes no ven el salto interpolado desde donde se devolvió.
  • OnPoolGet y OnPoolRelease se llaman en el servidor. Si los clientes necesitan reiniciar algo, usa campos replicados.
  • Sin red (o jugando solo) funciona como un pool local.

Cuánto se gana#

Medido con 1000 balas (prefab con un script), en las pruebas del motor (release, nova_tests.exe utilidades):

1000 balas Crear y destruir Pool (sacar y devolver)
Local: Scene.Instantiate + Destroy frente a Get + Release ≈ 195 ms ≈ 6 ms (≈ 33 veces menos)
Red, pico del servidor en el frame de la orden: Spawn + Destroy frente a Get + Release ≈ 140–185 ms + 5 ms ≈ 8 ms + 2 ms
Red, altas y bajas de entidades de red en los clientes 2000 0

Lo que cuesta un pool de red: las libres siguen siendo entidades de red (desactivadas) que la red recorre en cada envío. Con 1000 libres, unos 1,7 ms por frame en el servidor y otro tanto en cada cliente. Por eso, dimensiona los pools de red a lo que de verdad se usa a la vez (con max), y para balas que solo se ven, usa un pool local en cada máquina (el servidor decide los impactos con rayos).
