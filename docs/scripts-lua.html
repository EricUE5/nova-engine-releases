La guía principal para programar juegos con Nova Engine en Lua (en concreto Luau, el Lua con tipos opcionales). Explica por qué Lua, cómo es un script, todos los atributos y la API por áreas, la recarga en caliente, el multijugador con el servidor al mando (un solo fichero para servidor y cliente), un tutorial completo de un juego en red («Rey de la arena»), VS Code con autocompletado, la publicación, el sandbox, los errores comunes, consejos de rendimiento y, al final, qué tiene Lua de lo que pueden hacer los scripts C++ y el motor (apéndice Paridad con C++).

Lua es el lenguaje de los scripts por defecto: las plantillas de Nova Hub, los ejemplos y todas las guías lo usan. Si nunca has abierto el motor, empieza por empezar.md y editor.md. La lógica en C++ sigue disponible, como opción avanzada, para lo que necesite código nativo: scripts-cpp.md.

1. Por qué Lua (y cuándo C++)#

  • Sin compilar. Guardas el fichero y el editor lo recarga al momento, también con el juego en marcha, sin perder el estado. No hace falta Visual Studio.
  • Fácil de leer y de aprender. Es un lenguaje pequeño y muy usado en juegos y mods.
  • Seguro. Cada partida ejecuta los scripts en una máquina virtual aislada: sin acceso a ficheros, al sistema ni a Internet, con límite de memoria y de tiempo. Un bucle infinito detiene ese script, no el editor.
  • El mismo motor. Un script Lua va en el mismo componente Scripts que los de C++: sus campos salen en el Inspector, se guardan con la escena, entran en los prefabs, el deshacer y la red, igual que los de C++.
  • La red con atributos. Un comentario --[Server] encima de una función la convierte en una llamada al servidor. Nada de registrar mensajes a mano.
Lua C++
Compilar No: se recarga al guardar Sí (Visual Studio o Build Tools; Ctrl+B en el editor)
Dónde scripts/*.luau del proyecto (subcarpetas valen) scripts/*.cpp → DLL del juego
Campos en el Inspector Clase.campo = valor y atributos en comentarios NOVA_FIELD(campo).Range(...)
Red --[Replicated], --[Server], --[Client], --[Multicast] .Replicated(), NOVA_RPC
Rendimiento Muy bueno para lógica de juego (1.000 scripts con Update ≈ 1,3 ms por frame); con --!native en la primera línea, los cálculos van de 2 a 5 veces más rápido (código máquina, rendimiento.md) El máximo
Aislamiento Total (sandbox) Ninguno: es código nativo
Para qué Reglas, personajes, IA sencilla, interfaz, rondas, objetos… Sistemas pesados, librerías externas, predicción propia

Los dos se mezclan: una entidad puede llevar scripts Lua y C++, y un script Lua puede leer los campos y llamar a los métodos NOVA_METHOD de uno de C++ (self:GetScript("Inventario")).

2. Tu primer script en cinco minutos#

  1. Crea un proyecto con la plantilla Vacío (Lua) en Nova Hub (la que sale elegida en Nuevo proyecto), o abre game/sample_lua.
  2. En el panel Contenido, entra en scripts/, clic derecho > Nuevo script... (o Crear > Nuevo script...) y llámalo PrimerScript. El editor crea scripts/PrimerScript.luau con una plantilla.
  3. Doble clic en el fichero para abrirlo y cámbialo por esto:
Lua
local PrimerScript = Script()

--[Range(-720, 720), Tooltip("Grados por segundo")]
PrimerScript.velocidad = 90

function PrimerScript:Start()
    Log.Info("Hola desde " .. self.name)
end

function PrimerScript:Update(dt: number)
    -- Gira sobre el eje vertical; con Espacio cambia de sentido
    self.transform:Rotate(Vec3.up, math.rad(self.velocidad) * dt)
    if Input.WasKeyPressed("Espacio") then
        self.velocidad = -self.velocidad
    end
end

return PrimerScript
  1. Arrastra el fichero desde Contenido hasta un cubo de la Jerarquía (o al Inspector del cubo).
  2. Pulsa Jugar. El cubo gira y la Consola dice Hola desde Cubo. Cambia Velocidad en el Inspector (arrastrando sobre el número): el cubo cambia al momento.
  3. Con el juego en marcha, cambia 90 por 300 o añade una línea y guarda: el editor recarga el script sin parar el juego y sin perder el estado.

Eso es todo: ni CMake, ni DLL, ni compilar.

4. Anatomía de un script#

Un script es un fichero .luau (también vale .lua) dentro de la carpeta scripts/ del proyecto:

Lua
-- 1. La clase: el local que se crea con Script(). Su nombre es el del fichero
local Puerta = Script()

-- 2. Campos: salen en el Inspector y se guardan con la escena. El tipo sale del valor
--[Range(0, 180)]
Puerta.anguloAbierta = 90
Puerta.abierta = false
Puerta.mensaje = "Pulsa E para abrir"
Puerta.jugador = Entity() -- referencia a otra entidad (se elige en el Inspector)

-- 3. Estado interno: lo que empieza por _ no es un campo (ni sale ni se guarda)
Puerta._angulo = 0

-- 4. Variables y funciones locales del fichero: privadas
local VELOCIDAD = 120 -- grados por segundo

local function Acercar(actual: number, objetivo: number, paso: number): number
    if actual < objetivo then
        return math.min(objetivo, actual + paso)
    end
    return math.max(objetivo, actual - paso)
end

-- 5. Funciones del ciclo de vida (las que no uses, no las escribas: no cuestan nada)
function Puerta:Start()
    self._cerrada = self.transform.rotation
end

function Puerta:Update(dt: number)
    local cerca = self.jugador and Vec3.Distance(self.jugador.position, self.entity.position) < 2
    if cerca and Input.WasActionPressed("Accion") then
        self:Alternar()
    end
    self._angulo = Acercar(self._angulo, if self.abierta then self.anguloAbierta else 0, VELOCIDAD * dt)
    self.transform.rotation = Quat.FromAxisAngle(Vec3.up, math.rad(self._angulo)) * self._cerrada
end

-- 6. Funciones propias: se llaman con dos puntos (self:Alternar())
function Puerta:Alternar()
    self.abierta = not self.abierta
    Log.Info(self.name .. (if self.abierta then " abierta" else " cerrada"))
end

-- 7. Devolver la clase
return Puerta

La clase y self#

  • local X = Script() crea la clase. El fichero la devuelve al final (return X). El nombre del script es la ruta del fichero dentro de scripts/: Puerta.luau, ia/Enemigo.luau. En el Inspector sale sin la extensión.
  • Cada entidad que lleva el script tiene su instancia; dentro de las funciones es self:
self... Qué es
self.entity La entidad (Entity)
self.transform Su Transform (posición, rotación y escala locales; más abajo, la API)
self.name El nombre de la entidad (se puede cambiar)
self.enabled Si el script está activo (false = no recibe Update)
self.campo Los campos de la clase (con su tipo: asignar otro tipo es un error)
self._loquesea Estado interno de esta instancia (cualquier valor Lua)
self:GetComponent("RigidBody") Un componente de su entidad (o nil); también AddComponent, HasComponent, RemoveComponent
self:GetScript("Otro") Otro script de su entidad (Lua o C++); AddScript("Otro") lo añade
self:Destroy(segundos?) Destruye su entidad (al final del frame, o dentro de esos segundos de juego)
self:IsServer(), self:IsClient(), self:HasAuthority(), self:IsOwner(), self:IsLocalPlayer(), self:To(jugador) Red (sección 9)
  • Las variables local del fichero las comparten todas las instancias de esa clase (en esa partida). Para datos de cada entidad usa campos o self._x.
  • Las funciones que no son del ciclo de vida (como Alternar) también se pueden llamar por su nombre desde la interfaz (eventos «Al hacer clic»), sin argumentos.

Ciclo de vida#

Llegan en el mismo orden que a los scripts de C++:

Función Cuándo
Awake() Al crearse la instancia (al empezar la partida, al aparecer la entidad, o dentro de Scene.Instantiate y Spawn, antes de que devuelvan la entidad)
Start() Justo antes de su primer Update
Update(dt) Cada frame (dt en segundos)
FixedUpdate(dt) Cada paso fijo de las físicas (60 por segundo)
LateUpdate(dt) Cada frame, después de todos los Update (cámaras)
OnDestroy() Al destruirse la entidad o el script, o al parar el juego
OnCollisionEnter(c), OnCollisionExit(c) Choques: c.other, c.point, c.normal, c.impulse, c.relativeSpeed
OnTriggerEnter(otra), OnTriggerExit(otra) Algo entra o sale de un sensor (Collider con isTrigger)
OnNetworkSpawn() La red ya creó la entidad (en el servidor: ya tiene dueño)
OnReplicated() En los clientes, una vez por cada actualización de la red que cambió algún campo o tabla replicada de este script (después de los onChange de cada uno)
OnAnimationEvent(nombre) Un evento de una animación
OnGUI() Cada frame, para dibujar con GUI.* (sección 7)
OnPoolGet(), OnPoolRelease() La entidad sale de un Pool o vuelve a él (utilidades-lua.md)
OnAnimationFinished(clip) Un clip «una vez» de la Animación llega al final (animacion-objetos.md)
OnInteract(jugador) Alguien usa este Interactuable (en el servidor): jugador es su número, no su entidad (lobby-y-escenas.md)
OnBreak(nivel, punto), OnFullyDestroyed() Se rompe algo de este Destructible / ya está roto del todo (destruccion.md)
OnSceneLoaded(), OnPlayerLoaded(jugador), OnAllPlayersLoaded() Cambios de escena en red (lobby-y-escenas.md)
OnValidate(motivo) (u OnEditorChange) En el editor, sin jugar (herramientas-lua.md)

Los parámetros tienen el tipo que les pasa el motor. Si anotas uno, que sea ese: OnTriggerEnter(otra: Entity), OnCollisionEnter(choque: Collision), OnInteract(jugador: number), OnBreak(nivel: number, punto: Vec3). Con otro tipo, el motor no puede llamar a las que llama por la reflexión: function Pickup:OnInteract(player: Entity) da en la Consola «OnInteract: Pickup.OnInteract no se puede llamar (recibe 1 parámetro(s))», porque le llega el número del jugador. El editor de scripts y la extensión de VS Code lo subrayan con el arreglo rápido (sección 13). Interaction.OnInteract(function(entidad, jugador) ... end) es otra forma, desde cualquier script: recibe la entidad usada y el jugador.

Lo que use la escena (Scene.Find, Global, componentes…) tiene que ir dentro de estas funciones: en el nivel principal del fichero da el error «no se puede usar al cargar el script (fuera de sus funciones): hazlo en Awake o Start».

Módulos (require)#

Un fichero que devuelve otra cosa que una clase (normalmente una tabla) es un módulo: no sale en «Añadir script» y se carga con require desde otros scripts. Cada partida tiene una sola copia, compartida por todos los scripts:

Lua
-- scripts/Util.luau: funciones que usan varios scripts
local Util = {}

function Util.Redondear(x: number, decimales: number?): number
    local m = 10 ^ (decimales or 0)
    return math.floor(x * m + 0.5) / m
end

function Util.FormatoTiempo(segundos: number): string
    return string.format("%d:%02d", segundos // 60, segundos % 60)
end

return Util
Lua
local Util = require("./Util") -- ruta relativa a este fichero (también "../comun/Util" o "@scripts/Util")

local Cronometro = Script()
Cronometro._segundos = 0

function Cronometro:Update(dt: number)
    self._segundos += dt
end

function Cronometro:OnGUI()
    GUI.Begin("Cronómetro", 20, 20)
    GUI.Text(Util.FormatoTiempo(self._segundos))
    GUI.End()
end

return Cronometro

require solo carga ficheros de scripts/. Para pasar datos entre scripts también sirven Global("X") (sección 9) y los eventos (sección 11).

5. Atributos#

Los atributos configuran campos y funciones. Van en un comentario que empieza por --[, encima de la línea o al final de ella; varios se separan con comas y varios comentarios seguidos se suman:

Lua
--[Header("Combate")]
--[Range(0, 100), Tooltip("Vida del jugador")]
Jugador.vida = 100 --[Int]
Atributo Sobre Qué hace
Global local X = Script() Script global: una instancia por partida, sin entidad del mapa (sección 9.7)
Header("Texto") campo Título de sección en el Inspector antes del campo
Space campo Un hueco antes del campo
Range(min, max) o Range(min = 0, max = 1) campo Límites al editarlo (y red más compacta si está replicado)
Slider o Slider(min, max) campo Deslizador (necesita un rango)
Step(x) campo Paso al arrastrar
Tooltip("Texto") campo Ayuda al pasar el ratón
Display("Nombre") campo Nombre en el Inspector (por defecto sale del nombre del campo: velocidadMaxima → «Velocidad Maxima»)
Hide campo No sale en el Inspector (sí se guarda)
ReadOnly campo Se ve pero no se edita
Multiline texto Caja de texto de varias líneas
NoSave campo No se guarda con la escena (vuelve a su valor por defecto)
Angle número El valor está en radianes y el Inspector lo enseña en grados
Color Vec3 Selector de color (un Color.new(...) ya lo es)
HDR color Color con intensidad mayor que 1
Int número Número entero (si no, es decimal)
Replicated campo Lo cambia el servidor y llega a los clientes. Opciones: onChange = "Funcion", condition = "All" / "OwnerOnly" / "SkipOwner"
Server función Llamada al servidor. Opciones: rate = N (por segundo y jugador), reliable = false
Client función Llamada del servidor al dueño de la entidad (o a un jugador con self:To). Opción reliable = false
Button("Texto") función Botón en el Inspector que ejecuta la función en el editor sin jugar, con deshacer (herramientas-lua.md)
Required campo Campo obligatorio (Entity(), Asset(...) o texto): vacío, sale como error en el panel Problemas (herramientas-lua.md)
Multicast función Llamada del servidor a todos (y a él mismo). Opción reliable = false
Server(validate = "Fn", kickAfter = N) función Opciones de Server: el servidor valida la llamada con self:Fn(<mismos argumentos>) antes de ejecutarla y, a los N rechazos, expulsa al jugador (seguridad-red.md)
ServerOnly función Solo se ejecuta en el servidor o el anfitrión (y sin red). En un cliente la llamada no hace nada y devuelve nil. Opciones: silent, warn (sección 9.14)
ClientOnly función Solo en las máquinas con pantalla: cliente, anfitrión y sin red (no en el servidor dedicado). Opciones: silent, warn
OwnerOnly función Solo en la máquina del dueño de la entidad (sin dueño, en el servidor). Junto a Server, otra cosa: solo la puede llamar el dueño
EditorOnly función o campo Solo dentro del editor (también jugando en él). En el juego publicado la función no hace nada (ni se compila su cuerpo) y el campo no va. Opción warn
Cooldown(segundos) función No se repite antes de esos segundos: por jugador en una Server, por instancia en las demás. Opción warn: Cooldown(1.5, warn)
Lua
local TodosLosAtributos = Script()

--[Header("Movimiento")]
--[Range(0, 20), Tooltip("Metros por segundo")]
TodosLosAtributos.velocidad = 5
--[Slider(0, 1)]
TodosLosAtributos.suavizado = 0.5
--[Step(0.25)]
TodosLosAtributos.paso = 1
--[Angle, Display("Giro inicial")]
TodosLosAtributos.giro = 0

--[Space, Header("Aspecto")]
--[Color]
TodosLosAtributos.tinte = Vec3.new(1, 0.5, 0)
--[HDR]
TodosLosAtributos.brillo = Color.new(4, 2, 1, 1)
--[Multiline]
TodosLosAtributos.descripcion = "Primera línea\nSegunda línea"

--[Header("Interno")]
TodosLosAtributos.vidas = 3 --[Int, ReadOnly]
TodosLosAtributos.depurar = false --[Hide]
TodosLosAtributos.contador = 0 --[Int, NoSave]

return TodosLosAtributos

Reglas:

  • -- [Range] (con espacio) y --[[ ... ]] son comentarios normales.
  • Un atributo con código en la misma línea va al final: --[Int] Jugador.x = 30 es todo comentario para Lua.
  • Un atributo desconocido, mal escrito o mal puesto es un aviso en la Consola con fichero y línea, con sugerencia: scripts/Jugador.luau:7: atributo desconocido [Rnage] (¿querías [Range]?). El script funciona igual, sin ese atributo. Con la extensión de Nova para VS Code el mismo aviso sale mientras escribes (sección 13).

--[Tooltip("A quién apunta (arrástralo desde la Jerarquía)")]

--[Tooltip("Prefab de la bala")]

end

function Torreta:Update(dt: number)
    if self.modo == "Quieta" or not self.objetivo then
        return
    end
    self.transform:LookAt(self.objetivo)
    self._espera -= dt
    if self.modo == "Disparar" and self._espera <= 0 and self.bala then

  • Entity() y Asset() son nil hasta que eliges algo en el Inspector: compruébalo antes de usarlos. Un campo Entity() vacío no es una entidad inválida, es nil: self.mano:IsValid() da «attempt to index nil». Usa if self.mano then ... end (o if self.mano and self.mano:IsValid() then si la entidad elegida puede haberse destruido).
  • Un Enum es un texto en Lua: self.modo == "Disparar". Asignar un texto que no está en la lista es un error que dice cuáles valen.
  • Una tabla o una función no pueden ser campos (aviso). Para listas internas usa self._lista = {}; para una tabla que el servidor reparte a los clientes, una tabla replicada (--[Replicated] X.casillas = {}, sección 9.3).
  • Nombres reservados que no pueden ser campos: entity, transform, name, enabled y los del ciclo de vida.
  • Si borras o renombras un campo, los valores guardados de los demás se conservan (por nombre).

local PruebaArrastre = Script()
PruebaArrastre.frame = 0 --[Int, NoSave]

function PruebaArrastre:Update(dt)
    if not Input.IsSimulationAllowed() then return end
    self.frame += 1
    local lienzo = UI("Inventario")
    if self.frame == 10 then
        Input.SimulateMouseMove(lienzo:CanvasToView(Vec2.new(300, 400))) -- encima del objeto
    elseif self.frame == 12 then
        Input.SimulateMouseButton("RatonIzq", true)                      -- lo coge
    elseif self.frame == 14 then
        Input.SimulateMouseMove(lienzo:CanvasToView(Vec2.new(700, 400))) -- lo arrastra
    elseif self.frame == 16 then
        Input.SimulateMouseButton("RatonIzq", false)                     -- lo suelta
    elseif self.frame == 18 then
        Input.SimulateKey("R")                                           -- y lo gira
    end
end

return PruebaArrastre

El cursor bloqueado en el editor y en el juego publicado#

SetCursorLocked(true) pide el cursor bloqueado; quien lo aplica es la ventana:

  • En el editor, el ratón se captura en la vista Juego mientras ese panel tiene el foco: el cursor no se ve, no sale de la vista y no hace clic en el editor, y MouseDelta() sigue llegando sin límites (lo mueva cuanto lo mueva). Esc lo libera (o Mayús+Esc, según Editar > Preferencias del editor > Jugar) y un clic en el juego lo vuelve a capturar; ese clic no le llega al juego. También se libera al cambiar de ventana, en pausa, con un diálogo del editor y al detener. Detalles en editor.md.
  • Mientras el editor lo tiene liberado, el juego no recibe el ratón (MouseDelta(), MouseWheel() y los botones dan cero), pero IsCursorLocked() sigue siendo true: es lo que pidió el juego, y el editor no lo cambia. No hace falta volver a llamar a SetCursorLocked(true) (llamarlo en cada frame tampoco molesta).
  • Con Esc (lo normal) el Esc también llega al juego: tu menú de pausa con WasKeyPressed("Esc") o la acción Pausa funciona igual. Si al abrirlo sueltas el cursor (SetCursorLocked(false)), el ratón vuelve a ser del jugador; cuando lo vuelvas a bloquear (botón Continuar) se captura otra vez sin clic.
  • En NovaGame.exe (el juego publicado), el cursor bloqueado se queda en la ventana mientras tiene el foco: con Alt+Tab se suelta y al volver se captura otra vez. Ahí Esc no hace nada especial: es de tu juego.
  • Con el cursor bloqueado, la interfaz OnGUI no recibe el ratón (no se puede apuntar a nada con el cursor oculto). Para un menú, suelta el cursor mientras se ve (las pantallas de UI con Mostrar cursor lo hacen solas).
Lua
function Jugador:Start()
    Input.SetCursorLocked(true) -- cámara en primera persona
end

function Jugador:Update(dt: number)
    if Input.WasActionPressed("Pausa") then -- Esc o Start: en el editor, ese Esc también libera el ratón
        self._pausa = not self._pausa
        Input.SetCursorLocked(not self._pausa) -- con el menú abierto, el ratón es del jugador
    end
end

Tiempo#

Time. Qué es
deltaTime Segundos del frame (el mismo dt que reciben Update y compañía)

Choques. OnCollisionEnter(c) y OnCollisionExit(c) reciben c.other (la otra entidad), c.point (punto de contacto), c.normal (de esta entidad hacia la otra), c.impulse (impulso del choque, en N·s: sirve para el volumen del golpe) y c.relativeSpeed (m/s con los que se acercaban); en Exit, el punto y la normal son cero. OnTriggerEnter(otra) y OnTriggerExit(otra) reciben la entidad que entra o sale del sensor.

Quién manda en red. Las físicas que importan las simula el servidor: en un cliente, los objetos de red siguen lo que dice el servidor (sus fuerzas y velocidades no hacen nada) y solo se simulan sus objetos locales (restos, efectos). Pide los cambios al servidor con una función [Server].

-- Apunta un foco hacia donde mira la camara y dice que hay delante
local Linterna = Script()
Linterna.alcance = 30 --[Range(1, 100)]

function Linterna:Update(dt: number)
    if not Input.WasMousePressed("RatonIzq") then
        return
    end
    local t = self.transform
    local golpe = Physics.Raycast(t.worldPosition, t.forward, self.alcance, { ignore = self.entity })
    if golpe and golpe.entity then
        Log.Info(string.format("Delante: %s a %.1f m", golpe.entity.name, golpe.distance))
        local cuerpo = golpe.entity:GetComponent("RigidBody")
        if cuerpo then
            cuerpo:AddImpulse(t.forward * 5)
        end
    end
end

return Linterna

Materiales y visibilidad#

renderer.visible = false deja de dibujar una malla (MeshRenderer o SkinnedMeshRenderer) sin desactivar la entidad: sus scripts, físicas y sonidos siguen. Para cambiar su aspecto, cada malla puede tener materiales propios: la primera vez que se cambia algo, el motor copia el material de esa submalla solo para esa entidad (el del proyecto y las demás entidades no cambian). Es visual y local: en red, cámbialo en cada máquina (en un [Multicast] o con onChange). Los materiales propios se liberan al terminar la partida.

renderer: Qué hace
SetColor(color, submalla?), GetColor(submalla?) Color base (con transparencia si el material es Blend)
SetEmissive(color, intensidad?, submalla?) Brillo propio (con bloom si pasa del umbral)
SetTexture(textura, submalla?) Textura de color (Asset o ruta; nil la quita)
SetMaterialValue(nombre, valor, submalla?), GetMaterialValue(nombre, submalla?) Cualquier valor del material: "metallic", "roughness", "emissiveIntensity", "uvScale", "alphaCutoff"...
SetMaterial(material, submalla?), GetMaterial(submalla?) Usar un material del proyecto (compartido); nil = el del modelo
GetSlotCount() Cuántas submallas (materiales) tiene
GetSlotName(submalla), FindSlot(nombre) El nombre del material de una ranura y el número de la primera con ese nombre (o nil)

Sin submalla, se cambian todas; la primera es la 1. En vez del número vale también el nombre del material de la ranura (el del modelo o el que usa ahora): malla:SetEmissive(Color.new(0, 1, 0, 1), 4, "M_tritio") o, sin intensidad, malla:SetEmissive(Color.black, "M_punto_rojo"). Las luces (PointLight.intensity, .color...) y el entorno (Environment.fogDensity, .exposure...) se cambian con sus campos. Las nubes tienen además el global Environment (Environment.SetClouds({ coverage = 0.8 }), Environment.TransitionClouds("Tormenta", 60)): ver nubes.md.

Lua
-- Parpadea en rojo al recibir dano y se oculta al morir
local Dano = Script()
Dano.vida = 3 --[Int]

function Dano:Start()
    self._malla = self:GetComponent("MeshRenderer")
    self._normal = self._malla and self._malla:GetColor()
end

function Dano:Herir()
    local malla = self._malla
    if not malla then
        return
    end
    self.vida -= 1
    malla:SetColor(Color.red)
    SetTimeout(150, function()
        malla:SetColor(self._normal)
    end)
    if self.vida <= 0 then
        malla.visible = false
        self:Destroy(2) -- deja tiempo al sonido de la explosion
    end
end

return Dano

Datos guardados#

Los scripts no pueden tocar ficheros, salvo en una carpeta de guardado propia del juego, con límites de tamaño: %LOCALAPPDATA%\<juego>\guardado en NovaGame.exe, guardado-editor jugando en el editor (así las pruebas no estropean las partidas de verdad) y guardado-servidor en NovaServer.exe. Con la variable de entorno NOVA_DATOS_USUARIO (la ponen las pruebas del motor), esa carpeta sustituye a %LOCALAPPDATA%, como para las opciones y el registro.

PlayerPrefs. Qué hace
Set(clave, valor) Guarda un booleano, número o texto (hasta 4 KB); nil la borra
Get(clave, porDefecto?) Su valor, o porDefecto (o nil) si no está

SaveGame. Qué hace
Save(nombre, datos) Guarda una partida: una tabla (o cualquier valor) con números, textos, booleanos, Vec2, Vec3, Vec4, Quat, Color, Asset y tablas anidadas (listas y claves de texto o número). Devuelve true o da un error claro
Load(nombre) Los datos, o nil y el motivo ("no existe", "el fichero está dañado...")
Exists(nombre), Delete(nombre), List() Comprobar, borrar y listar las partidas
  • El nombre de una partida solo admite letras sin tildes, números, _ y - (hasta 64): "partida1", "ranura-2". Así nada puede salir de la carpeta. No valen los nombres que Windows reserva para dispositivos (CON, PRN, AUX, NUL, COM1 a COM9, LPT1 a LPT9). Mayúsculas y minúsculas son la misma partida: "Partida1" carga y sobrescribe "partida1", y List() la devuelve con el nombre con el que se creó.
  • No se pueden guardar entidades (guarda su id, su posición o lo que necesites), funciones, NaN ni tablas que se contengan a sí mismas: es un error que dice dónde está el valor (datos.inventario[3]).
  • Límites: 1 MB por partida y 256 partidas. Se cambian en project.nova: "lua": { "guardadoMaxKB": 4096, "guardadoMaxFicheros": 1000 }.
  • Cada máquina guarda en su disco. En red, lo que tiene que ser fiable (dinero, inventario, progreso) lo guarda el servidor (if IsServer() then ... end); los clientes, sus opciones (volumen, teclas, nombre).
Lua
-- Guarda y carga la partida (F5 / F9) y recuerda el volumen
local Partida = Script()
Partida.ranura = "partida1"

function Partida:Start()
    Audio.SetBusVolume("Master", PlayerPrefs.Get("volumen", 1))
    self._monedas = 0
end

function Partida:Update(dt: number)
    if Input.WasKeyPressed("F5") then
        SaveGame.Save(self.ranura, {
            nivel = Scene.GetName(),
            posicion = self.entity.position,
            monedas = self._monedas,
            inventario = { "espada", "llave" },
        })
        Log.Info("Partida guardada")
    elseif Input.WasKeyPressed("F9") then
        local datos, motivo = SaveGame.Load(self.ranura)
        if datos then
            self.entity.position = datos.posicion
            self._monedas = datos.monedas
        else
            Log.Warn("No se pudo cargar:", motivo)
        end
    end
end

function Partida:CambiarVolumen(volumen: number)
    PlayerPrefs.Set("volumen", volumen)
    Audio.SetBusVolume("Master", volumen)
end

return Partida

Registro#

Log.Info(...), Log.Warn(...), Log.Error(...), Log.Debug(...), Log.Trace(...) y print(...) Con red, cada mensaje lleva delante de qué lado sale (también print y los errores de Lua):

[  12.455] INFO  Client: vida 80

8. Errores y recarga en caliente#

Recarga. Con el editor abierto (y en NovaGame.exe cuando juega desde el código fuente), el motor se entera al momento de lo que guardas en scripts/ (también en subcarpetas y también jugando). Al guardar uno:

  1. Lo vuelve a compilar y lo dice: abajo a la derecha sale «Recargado Jugador.luau» unos segundos (y en la barra de estado). Si es un módulo (require), también se recargan los scripts que lo usan, aunque sea a través de otro módulo: «Recargado Util.luau (y 3 scripts que lo usan)».
  2. Si tiene un error, el aviso sale en rojo con el fichero y la línea: «Error en scripts/Jugador.luau:12: … (se sigue usando la versión anterior)». El error queda también en la Consola y el juego no se para. Pulsa el aviso (o el error en la Consola) para abrir el script en esa línea en el editor de scripts. Con la extensión de Nova para VS Code, el error sale también en el panel Problemas de VS Code y se quita al arreglarlo (sección 13).
  3. Si los campos cambian, el Inspector se actualiza y los valores de las entidades se conservan por nombre.
  4. Las instancias que ya existen pasan a usar las funciones nuevas conservando su estado (campos y self._x); no se vuelven a llamar Awake ni Start.
  5. Los manejadores de eventos y tareas que registró el fichero al cargarse se quitan antes de volver a ejecutarlo: no se duplican.

Recargar scripts (Ctrl+R). Menú Scripts > Recargar scripts: vuelve a leer y compilar todos los scripts del disco, como al abrir el proyecto, sin reiniciar el editor ni parar el juego. En el día a día no hace falta (se recargan solos), pero si alguna vez parece que un cambio no ha entrado, pulsa Ctrl+R en lugar de reiniciar el editor. Si el proyecto tiene scripts C++, también vuelve a cargar su DLL.

Cómo se entera el editor (por si trabajas en OneDrive, en una carpeta de red o en una sesión de equipo):

  • Un vigilante de la carpeta scripts/ avisa de cada guardado. De red de seguridad, el editor mira la fecha y el tamaño de todos los scripts cada 2 segundos y compara el contenido de unos pocos en cada vuelta: así entran también los cambios que dejan la misma fecha (copias que la conservan, sincronizaciones) aunque se pierda algún aviso.
  • Lo recién guardado se lee cuando lleva una décima de segundo sin cambiar, y entero: si otro programa lo tiene bloqueado (OneDrive subiéndolo, el antivirus mirándolo) o lo sigue escribiendo, se vuelve a intentar en los frames siguientes sin dar error. Si sigue bloqueado más de 2 segundos, lo avisa y lo carga en cuanto se pueda.
  • Funciona igual con el guardado atómico de VS Code (fichero temporal y renombrar), con muchos guardados seguidos (se queda con el último) y en la carpeta de trabajo de una sesión de equipo (%LOCALAPPDATA%\NovaEngine\equipo\espejos\…): lo que guardas tú y lo que llega de los demás. En una sesión, abre los scripts desde el editor (doble clic o «Abrir script») para editar los de esa carpeta y no los de tu copia del proyecto: los de tu copia no se usan hasta que salgas de la sesión.
  • Un fichero de OneDrive que está solo en la nube no se descarga para compararlo; si OneDrive lo cambia, se recarga al cambiar su fecha.
  • Guardar sin cambiar nada (o que otro programa toque el fichero) no recompila nada.

En project.nova se puede desactivar ("lua": {"recargar": false}).

Errores. Un error dentro de una función sale en la Consola así:

ERROR Lua: scripts/Puerta.luau:24: attempt to index nil with 'position' (Update de Puerta.luau en 'Puerta 2')
  scripts/Puerta.luau:24 function Update

Primero el fichero y la línea, después el mensaje, qué función y en qué entidad, y la pila. El mismo error no se repite cada frame: sale una vez y después un resumen cada 5 segundos. Ese script sigue recibiendo llamadas (el error puede ser de un solo frame), salvo que agote el tiempo o la memoria: entonces se detiene hasta la próxima partida (sección 15). Un error nunca cierra el editor ni el juego.

Un script con errores al cargarse aparece en el Inspector como «Script Lua con errores o borrado (mira la Consola)»; sus datos se conservan y vuelve a funcionar en cuanto lo arreglas.

9. Multijugador#

En Nova, el multijugador se escribe en un solo fichero por script, que se ejecuta en el servidor y en cada cliente. Unos atributos dicen qué viaja por la red. Antes de seguir conviene leer los conceptos de multijugador.md (servidor autoritativo, replicación, dueño) y cómo se juega en red desde el editor (multijugador.md).

9.1 El servidor manda#

  • El servidor tiene la versión buena de la partida: decide la vida, los puntos, quién gana, dónde está cada objeto. Los clientes piden cosas y muestran lo que el servidor les cuenta.
  • Un cliente no puede cambiar nada que importe por su cuenta: si cambia un campo replicado en su máquina, solo lo ve él y el servidor lo pisa en la siguiente actualización.
  • Por eso la regla de oro: nunca te fíes del cliente. Comprueba en el servidor cada petición (sección 9.8).

Las piezas:

Qué Cómo
Que todos vean un valor Campo --[Replicated] (lo cambia el servidor)
Pedir algo al servidor Función --[Server] (desde el dueño de la entidad, o cualquiera en un [Global])
Que el servidor avise a un jugador Función --[Client] (al dueño, o a quien digas con self:To(id))
Que el servidor avise a todos Función --[Multicast]
Reglas de toda la partida (rondas, marcador) Script --[Global]
Que una función solo se ejecute en el servidor, donde hay pantalla, en el dueño o en el editor --[ServerOnly], --[ClientOnly], --[OwnerOnly], --[EditorOnly] (sección 9.14)

9.2 Un fichero, los dos lados#

Sin red Un jugador o anfitrión Cliente Servidor dedicado
IsServer(), self:IsServer(), self:HasAuthority() sí sí no sí
IsClient(), self:IsClient() sí sí sí no
self:IsOwner() nunca si es del jugador local si es de este jugador nunca
self:IsLocalPlayer() nunca si es el personaje del jugador local si es su personaje nunca

Sin red (el editor sin sesión) se es servidor y cliente a la vez y las funciones de red se ejecutan aquí mismo, así que el mismo script sirve para probar solo. Reglas prácticas:

Lua
function Ejemplo:Update(dt: number)
    if self:IsLocalPlayer() then
        -- leer el teclado y pedirle cosas al servidor
    end
    if IsServer() then
        -- reglas: vida, puntos, quien se cae...
    end
    if IsClient() then
        -- sonidos, efectos, interfaz
    end
end

Network. da más detalles: Mode() ("None", "Offline", "Host", "Client", "DedicatedServer"), IsRunning(), IsConnected(), IsHost(), IsDedicatedServer(), LocalClientId() y PlayerName(). GetPlayers() da los ids de los jugadores y GetPlayerName(id) su nombre; con su ping y más, Network.Players() (sección 9.12).

9.3 Campos replicados#

Lua
local Barril = Script()

--[Replicated(onChange = "AlCambiarVida"), Range(0, 100)]
Barril.vida = 100 --[Int]
--[Replicated(condition = "OwnerOnly")]
Barril.secreto = "" -- solo lo recibe el dueño

-- En el servidor: lo llama otro script cuando le disparan
function Barril:Danar(cantidad: number)
    if not IsServer() then
        return
    end
    self.vida = math.max(0, self.vida - cantidad)
    if self.vida == 0 then
        self:Destroy() -- con Identidad de red, se destruye en todas las máquinas
    end
end

-- En los clientes, cada vez que llega un valor nuevo de 'vida'
function Barril:AlCambiarVida()
    Log.Info(self.name .. " tiene " .. self.vida .. " de vida")
end

return Barril
  • La entidad necesita Identidad de red (NetworkIdentity); los personajes que crea PlayerSpawner ya la tienen.
  • El servidor escribe; los clientes reciben. onChange llama a esa función en los clientes al llegar un valor nuevo (en el servidor, y en el anfitrión, no: si hace falta, llámala tú después de cambiarlo).
  • condition: "All" (por defecto), "OwnerOnly" (solo el dueño) o "SkipOwner" (todos menos el dueño).
  • Se replican números, enteros, booleanos, textos (hasta 256 bytes), Vec3, Vec2, Quat, Enum, Entity y Asset. Con Range los números viajan más comprimidos. Para textos más largos o listas, usa una tabla replicada (abajo).
  • OnReplicated() se llama una vez por cada actualización de la red que cambió algo de este script, después de todos los onChange: sirve para redibujar algo que depende de varios campos a la vez. Si en la misma actualización llegan campos y tablas replicadas (abajo), sigue siendo una sola vez. Los campos y las tablas viajan por separado: un cambio de los dos en el mismo frame del servidor puede llegar en dos actualizaciones.

Tablas replicadas. Con --[Replicated] encima, un campo que vale {} es una tabla que el servidor reparte a los clientes. Solo viajan las claves que cambian (en mensajes fiables, aparte de las posiciones):

Lua
local Tablero = Script()

--[Replicated(onChange = "AlCambiarCasillas")]
Tablero.casillas = {}
--[Replicated(condition = "Observers")]
Tablero.cartas = {} -- solo lo reciben los jugadores de self:SetObservers

-- En el servidor
function Tablero:Marcar(casilla: number, jugador: string)
    if not IsServer() then
        return
    end
    self.casillas[casilla] = jugador -- solo viaja esta clave
    self.cartas.mano = { "as", "rey" }
    self:SetObservers({ Network.GetOwner(self.entity) })
end

-- En los clientes
function Tablero:AlCambiarCasillas()
    for casilla, jugador in self.casillas do
        Log.Info(tostring(casilla) .. " = " .. tostring(jugador))
    end
end

function Tablero:OnReplicated()
    Log.Info("Casillas: " .. #self.casillas)
end

return Tablero
  • Claves: textos (de 1 a 128 bytes) o números. Valores: números, booleanos, textos (hasta 4 KB), Vec2, Vec3, Quat, Color, Entity, Asset y tablas de esos tipos (hasta 64 elementos y dos niveles).
  • Límites por tabla: 1024 claves y 64 KB. Pasarse da un error en la línea que lo intenta, y la tabla se queda como estaba. Una sola clave puede ocupar tanto como la tabla (por ejemplo, un valor de 20 KB): lo grande viaja en varios trozos y el cliente lo aplica de golpe con el último, así que nunca ve la tabla a medias y su onChange (y OnReplicated) se llama una vez por cada cambio que llega, no una por trozo.
  • Se guarda una copia del valor: si el valor es una tabla, se lee de solo lectura (self.cartas.mano[1] = "x" da error); para cambiarla, asígnala otra vez (self.cartas.mano = { "x", "rey" }; table.clone da una copia que se puede cambiar). self.casillas = { ... } cambia la tabla entera (y se envía entera); self.casillas = nil la vacía.
  • Se lee con self.casillas[k], se recorre con for k, v in self.casillas do y se mide con #. No es una tabla de Lua: pairs, ipairs, table.insert y table.sort no la admiten (añade con t[#t + 1] = valor).
  • Solo el servidor la cambia para todos: lo que escribe un cliente solo cambia su copia, hasta que el servidor envíe esa clave o la tabla entera. En cuanto la entidad existe en un cliente (al aparecer, al acercarse si la partida usa relevancia por distancia, o al entrar tarde), el servidor le envía sus tablas completas, un momento después que los campos sueltos. Si son muchas, van poco a poco, al ritmo de bajada de la red (128 KB/s por jugador y como mucho 16 KB de tablas enteras por frame, o una sola tabla si ocupa más): quien entra tarde en una partida con megas en tablas las recibe todas sin que la red lo expulse. Una entidad que un jugador no tiene (lejos, con relevancia) no le gasta ancho de banda.
  • condition: además de "All", "OwnerOnly" y "SkipOwner", las tablas admiten "Observers": solo la reciben los jugadores de self:SetObservers({ ids }) (solo en el servidor; la lista es de la entidad y vale para todas sus tablas "Observers"; self:GetObservers() la devuelve). A quien sale de la lista se le vacía la tabla. Desde otro script: Network.SetObservers(entidad, ids) y Network.GetObservers(entidad).
  • El inventario tipo Rust reparte sus casillas de otra forma: un campo de texto replicado por casilla (declarados en un bucle con :Field) y un [Client] con el contenido.

9.4 Funciones de red: [Server], [Client] y [Multicast]#

Se declaran con un atributo y se llaman como cualquier función (self:Abrir()): en el lado correcto se ejecutan aquí; si no, viajan por la red.

Atributo Quién la puede llamar Dónde se ejecuta
--[Server] El dueño de la entidad (en un [Global], cualquier jugador). En el servidor, el propio servidor En el servidor; source = quien la llamó
--[Client] El servidor En el dueño de la entidad, o en el jugador de self:To(id)
--[Multicast] El servidor En el servidor y en todos los clientes

Opciones: rate = N (llamadas por segundo y jugador que acepta el servidor; las demás se descartan) y reliable = false (más rápida pero se puede perder: para cosas que se repiten, como la entrada o un efecto).

Los parámetros llevan tipo (las anotaciones de Luau) y se comprueban siempre, también sin red:

Anotación Viaja como
number número decimal (64 bits)
integer o int entero de 32 bits
boolean, string booleano, texto
Vector3 (o Vec3), Vector2, Vector4, Quat, Color vectores, rotación, color
Entity, Asset referencia (por UUID)
"a" | "b" texto
sin anotación valor cualquiera con límites: nil, booleanos, números, textos de hasta 4 KB, vectores, entidades y tablas de hasta 64 pares y 2 niveles

Como mucho 8 KB de argumentos por llamada. El número de argumentos también se comprueba. Las firmas forman parte de la «huella» de la red: un cliente con otros scripts no puede conectarse (y cambiar las funciones de red durante una partida en red pide reiniciarla).

Lua
-- El cofre del tesoro de la partida, como script [Global]: cualquier jugador puede pedir abrirlo (tecla F) y solo
-- el primero se lleva el premio. El servidor decide; los demas reciben el resultado.
--[Global]
local Cofre = Script()

--[Replicated]
Cofre.abierto = false
--[Replicated]
Cofre.quien = ""

-- Cliente -> servidor (en un [Global] la puede llamar cualquier jugador; 'source' dice quien)
--[Server(rate = 2)]
function Cofre:Abrir()
    if self.abierto then
        self:To(source):Aviso("Llegas tarde: ya está abierto")
        return
    end
    self.abierto = true
    self.quien = GetPlayerName(source) or "?"
    self:Efecto(Vec3.new(0, 1, 0))
    self:To(source):Aviso("¡Has encontrado 100 monedas!")
end

-- Servidor -> todos: sonido y particulas en cada maquina
--[Multicast(reliable = false)]
function Cofre:Efecto(donde: Vector3)
    Log.Info("¡Clac! El cofre se abre en", donde)
end

-- Servidor -> un jugador: self:To(id):Aviso(...)
--[Client]
function Cofre:Aviso(texto: string)
    Log.Info("Aviso:", texto)
end

function Cofre:Update(dt: number)
    if IsClient() and Input.WasKeyPressed("F") then
        self:Abrir()
    end
end

return Cofre

Llamar a una función desde donde no se puede es un error en quien llama (con fichero y línea), nunca un cierre:

  • [Server] Abrir solo la puede llamar el dueño de 'Puerta' (este jugador no lo es)
  • [Multicast] Efecto solo la puede llamar el servidor
  • [Client] Aviso solo la puede llamar el servidor (o el dueño de 'X' en su propia máquina)

Las funciones de red no devuelven valores: si el cliente necesita una respuesta, el servidor se la envía con un [Client].

9.5 self:To(jugador)#

self:To(id) devuelve un objeto cuyas funciones [Client] van a ese jugador en lugar de al dueño: self:To(source):Aviso("No tienes munición").

  • En el servidor vale para cualquier jugador (si es el jugador del anfitrión, se ejecuta aquí).
  • En un cliente, solo para sí mismo.
  • self:To(-1) no existe: para todos se usa [Multicast].
  • Un [Client] sin To en algo sin dueño (un [Global], un objeto del servidor) es un error que lo explica.

9.6 source#

Dentro de una función [Server] (y de un manejador de un evento que llega de un jugador), source es el id del jugador que la llamó (0 = el propio servidor). En lo demás es nil. Es una variable global de solo lectura que cambia en cada llamada: si la necesitas después (en un SetTimeout), cópiala a un local.

9.7 Scripts [Global]#

--[Global] encima de local X = Script() crea un script de la partida: no se pone en ninguna escena; el motor crea una instancia en el servidor y en cada cliente al empezar, con la misma identidad de red en todas. Sus [Replicated] y sus funciones de red funcionan como en cualquier entidad.

  • Desde cualquier script: Global("Rondas") (o la ruta: Global("reglas/Rondas.luau")) devuelve su instancia.
  • Como no tiene dueño, cualquier jugador puede llamar a sus [Server] (valida con source) y sus [Client] necesitan self:To(jugador).
  • No tiene Inspector (no está en ninguna escena): sus campos valen lo que dice el código.
  • Uno nuevo (o que pasa a serlo) mientras se juega empieza en la siguiente partida.
Lua
--[Global]
local Puntuaciones = Script()

--[Replicated]
Puntuaciones.mejor = "" -- texto replicado: "Ana (12)"

function Puntuaciones:Awake()
    self._puntos = {} -- servidor: id del jugador -> puntos
    if IsServer() then
        AddEventHandler("playerDropped", function(id)
            self._puntos[id] = nil
        end)
    end
end

-- Servidor: lo llaman otros scripts, por ejemplo Global("Puntuaciones"):Sumar(id, 1)
function Puntuaciones:Sumar(jugador: number, cantidad: number)
    if not IsServer() then
        return
    end
    self._puntos[jugador] = (self._puntos[jugador] or 0) + cantidad
    local mejorId, mejores = nil, -1
    for id, puntos in self._puntos do
        if puntos > mejores then
            mejorId, mejores = id, puntos
        end
    end
    self.mejor = string.format("%s (%d)", GetPlayerName(mejorId) or "?", mejores)
end

return Puntuaciones

9.8 Límites y validación#

  • rate: --[Server(rate = 4)] acepta como mucho 4 por segundo de cada jugador (con una pequeña ráfaga); las demás se descartan. Si alguien insiste mucho, la red lo expulsa. Sin rate vale el límite general.
  • El motor comprueba solo: el dueño ([Server] de entidades), los tipos y el número de argumentos, el tamaño y que los números no sean NaN ni infinitos en los parámetros con tipo number (también con tipo Vector3 conviene comprobarlo: ver el ejemplo).
  • Tú compruebas el resto: rangos, distancias («¿está cerca del cofre?»), esperas («¿ya puede volver a disparar?»), que esté vivo, la longitud de los textos…
  • Con atributos, el motor lo comprueba por ti antes de llamar a la función: RateLimit(n) (como rate), ArgRange("param", min, max), MaxLength("param", n), Validate("Funcion") (o [Server(validate = "Funcion", kickAfter = N)], que además cuenta los rechazos de cada jugador y lo expulsa al N-ésimo), AnyCaller (cualquier jugador puede llamar a la [Server] de una entidad: puertas, botones), OwnerOnly y Cooldown(segundos) (por jugador; sección 9.14). Lo rechazado no se ejecuta y queda en el registro de seguridad. Ver seguridad-red.md, con la API Security (expulsar, banear, reportar sospechas, OnCheatSuspected, AllowRate y ValidateMove).
Lua
--[Server(rate = 4)]
function Jugador:Disparar(direccion: Vector3)
    local largo = Vec3.Length(direccion)
    if not (largo > 0.01 and largo < 1e6) then
        return -- direccion vacia, NaN o infinita: un cliente roto o tramposo
    end
    if self._reloj - self._ultimoDisparo < self.cadencia then
        return -- demasiado pronto
    end
    self._ultimoDisparo = self._reloj
    -- ...
end

9.9 Objetos de red: crear, dueño, teletransporte y empujones#

Todo esto lo hace el servidor (un cliente se lo pide con una función [Server]; si lo llama él, es un error claro). Sin red funciona igual, en local.

Función Qué hace

Orden al crear. Cuando Spawn (o Scene.Instantiate) devuelve la entidad, el Awake de sus scripts ya ha pasado: entidad:GetScript("Bala") da la instancia con sus valores iniciales y se le puede escribir en la línea siguiente. En los clientes, Awake se ejecuta al aparecer allí la entidad; si solo debe hacer algo el servidor, compruébalo con IsServer().

9.10 Llamadas al servidor con respuesta#

Una función [Server] no devuelve nada a quien la llama. Para preguntar algo al servidor y recibir la respuesta: el servidor registra la respuesta con RegisterServerCallback y el cliente pregunta con TriggerServerCallback, que llama a su función cuando llega:

Lua
--[Global]
local Precios = Script()

function Precios:Awake()
    if IsServer() then
        -- 'source' es quien pregunta; lo que devuelve la funcion es la respuesta (hasta 16 valores)
        RegisterServerCallback("tienda:precio", function(articulo: string)
            return if articulo == "espada" then 100 else 10, source
        end)
    end
end

function Precios:Preguntar(articulo: string)
    TriggerServerCallback("tienda:precio", function(precio: number, quien: number)
        Log.Info(string.format("%s cuesta %d (para el jugador %d)", articulo, precio, quien))
    end, articulo)
end

return Precios
  • En el servidor (o un anfitrión, o sin red) se responde en el acto. Los argumentos y la respuesta usan la serialización de los eventos (valores sencillos y tablas pequeñas, 8 KB). Sin respuesta en 10 s se olvida con un aviso; si el servidor no tiene ese callback, también hay un aviso y la función no se llama.
  • Para esperar la respuesta dentro de un hilo: CreateThread con una variable y while not listo do Wait(0) end.

9.13 Lo que no se puede hacer (todavía)#

  • Predicción propia desde Lua: el CharacterController de los jugadores se predice solo (escribe su entrada con Move, Face y Jump en self:IsLocalPlayer(); los empujones y teletransportes del servidor llegan con la reconciliación); otros movimientos los simula el servidor.
  • Valores de vuelta directos en las funciones de red (usa 9.10), y Vec4/Color en campos replicados sueltos (dentro de una tabla replicada, sí).
  • La condición "Observers" en campos sueltos: es solo para tablas replicadas.
  • Scene.Load en una partida en red: en red se cambia de escena con Network.LoadScene desde el servidor (todos a la vez o unos jugadores, con pantalla de carga): lobby-y-escenas.md.

9.14 Dónde se ejecuta una función#

Un script se ejecuta en todas las máquinas (sección 9.2). En vez de empezar cada función con if not IsServer() then return end, un atributo dice dónde se ejecuta. A diferencia de [Server], [Client] y [Multicast], no viajan por la red: si se llama en una máquina donde no toca, la llamada no hace nada y devuelve nil.

Atributo Sin red Anfitrión Cliente Servidor dedicado (NovaServer) Juego publicado
--[ServerOnly] sí sí no sí igual
--[ClientOnly] sí sí sí no igual
--[OwnerOnly] sí si la entidad es suya (o no tiene dueño) si la entidad es suya si no tiene dueño igual
--[EditorOnly] en el editor, sí (también jugando en él) ídem ídem ídem no (ni se compila)
Lua
local InventarioRed = Script()

InventarioRed.monedas = 0 --[Int, NoSave]
--[EditorOnly]
InventarioRed.verCasillas = true -- no va en el juego publicado

-- Solo el servidor cambia el inventario de verdad. En un cliente no hace nada, devuelve nil y avisa una vez en la
-- Consola: «InventarioRed:AddItemInHand es ServerOnly: se ha ignorado en un cliente»
--[ServerOnly]
function InventarioRed:AddItemInHand(objeto: string)
    self.monedas += 1
    return self.monedas
end

-- Un cliente lo pide; el servidor lo valida antes y lo acepta como mucho una vez cada 0,5 s de cada jugador
--[Server(validate = "PuedeTirar", kickAfter = 5), Cooldown(0.5)]
function InventarioRed:Tirar(casilla: integer)
    self:AddItemInHand("nada")
end

function InventarioRed:PuedeTirar(casilla)
    if casilla < 1 or casilla > 30 then
        return false, "casilla fuera de la mochila"
    end
    return true
end

function InventarioRed:SonarMonedas()
    Log.Info("¡clinc!")
end

-- La interfaz de la mochila: solo en la máquina de su dueño
--[OwnerOnly]
function InventarioRed:AbrirMochila()
    Log.Info("Mochila de " .. self.name)
end

-- Herramienta del editor: en el juego publicado la función está vacía

        Debug.DrawSphere(self.transform.position, 0.5, Color.new(1, 1, 0))

    self:AddItemInHand("moneda")

  • ServerOnly: servidor, anfitrión y sin red (jugar solo es ser servidor). Para pedírselo al servidor desde un cliente hace falta [Server]: ServerOnly solo impide que se ejecute en un cliente.
  • ClientOnly: todo lo que tiene pantalla (cliente, anfitrión y sin red). En NovaServer no hace nada: sonidos, partículas, interfaz.
  • OwnerOnly: solo en la máquina del dueño de la entidad (Network.GetOwner(self.entity) es el jugador local). Sin dueño (una entidad sin Identidad de red, una del servidor —dueño 0— o un script [Global]), la autoridad hace de dueña: se ejecuta en el servidor (y en el anfitrión) y no en los clientes. Junto a [Server] significa otra cosa, la de siempre: solo la puede llamar el dueño (seguridad-red.md). Con [Client] (--[OwnerOnly, Client]), solo la ejecuta el dueño aunque el servidor la mande con self:To(otro).
  • EditorOnly: dentro del editor (sin jugar y jugando, también en una partida en red desde el editor). En el juego publicado (NovaGame y NovaServer) la llamada no hace nada; además, al publicar, el cuerpo de la función no se compila (queda vacía: su código no va en el .luauc) y los campos EditorOnly no van (con sus atributos; leerlos en el juego da nil: úsalos solo desde funciones EditorOnly). Las líneas no cambian: un error en el juego publicado dice la misma línea que en el editor.
  • El aviso: la primera llamada ignorada de cada función escribe en la Consola «Clase:Funcion es ServerOnly: se ha ignorado en un cliente» (o «en el servidor dedicado», «en una máquina que no es la dueña de 'X'»). Una vez por función y máquina. --[ServerOnly(silent)] (o silent = true) lo quita. Las funciones que llama el motor (Update, OnInteract...) y EditorOnly no avisan si no se les pone warn.
  • Cooldown(segundos): la función no se repite antes de ese tiempo; la llamada de dentro se ignora y devuelve nil (con --[Cooldown(1.5, warn)], avisa cada vez). En una [Server] cuenta por jugador que llama, en el servidor (dos jugadores pueden usarla a la vez); en las demás, por instancia (cada puerta tiene el suyo). Usa el tiempo de la partida sin timeScale.
  • Las funciones del ciclo de vida funcionan igual: un Update con --[ServerOnly] solo se llama en el servidor y un OnInteract con --[ServerOnly], solo en el servidor.
  • Lo que devuelve: donde se ejecuta, lo de la función; donde no (o en el Cooldown), nil.

Orden de evaluación de una llamada:

  1. EditorOnly (fuera del editor, se acaba aquí);
  2. ServerOnly / ClientOnly / OwnerOnly en la máquina que la ejecuta;
  3. si es [Server] y llega de un cliente: el límite (rate/RateLimit), el dueño (OwnerOnly/AnyCaller), los argumentos (tipos, ArgRange, MaxLength), validate/Validate y ValidateArgs;
  4. Cooldown (una llamada rechazada antes no lo gasta);
  5. el cuerpo de la función.

En un cliente, una [Server] no pasa por 2-4: se envía y todo eso lo hace el servidor al recibirla. Una [Client] o [Multicast] hace 1-4 en cada máquina que la recibe.

Combinaciones. Se pueden juntar en un comentario o en varios (--[Server(validate = "X"), Cooldown(0.5)]). Las que no tienen sentido son un error de compilación del script, con su línea:

Combinación Resultado
ServerOnly + Cooldown, ClientOnly + Cooldown vale
Server(validate) + Cooldown vale (Cooldown por jugador, después de validate)
OwnerOnly + Client, ClientOnly + Multicast (efectos que el servidor dedicado se salta) vale
Server + OwnerOnly vale (OwnerOnly: quién la puede llamar)
ServerOnly + EditorOnly vale (el servidor o el anfitrión dentro del editor)
ServerOnly + ClientOnly error: «Clase:F: [ServerOnly] y [ClientOnly] no se pueden combinar: ...»
ServerOnly + Client, ServerOnly + Multicast, ClientOnly + Server, ServerOnly + OwnerOnly error
EditorOnly + Server/Client/Multicast error (las funciones de red forman parte de la huella de la partida)

Avisos (en la Consola al cargar, en el editor de scripts y en VS Code mientras escribes): llamar a una ServerOnly desde una ClientOnly u OwnerOnly (en un cliente nunca hará nada), validate = "X" si X no existe o tiene otro número de parámetros, Cooldown sin segundos, una opción desconocida y ServerOnly (o Cooldown) encima de un campo. Y si una función empieza por if not IsServer() then return end, la bombilla ofrece cambiarlo por --[ServerOnly]. Al pasar el ratón por una función, la ayuda dice dónde se ejecuta.

Coste. ServerOnly, ClientOnly y EditorOnly (sin OwnerOnly ni Cooldown) no cuestan nada donde se ejecutan: al cargar la clase (y si cambia el modo de la red) la VM pone en la clase la función tal cual donde toca y un envoltorio donde no. Medido con un millón de llamadas: 25 ns la función normal y 25 ns la ServerOnly (llamadas directas), 24 ns la llamada ignorada. OwnerOnly y Cooldown pasan siempre por el envoltorio (unos 90 ns más por llamada: miran el dueño de la entidad o la hora).

10. Tutorial: «Rey de la arena»#

Un juego en red completo, solo con Lua, en game/multiplayer_lua: varios jugadores en una plataforma flotante se empujan con E. Cada empujón quita vida, y cuanta menos vida tienes, más lejos sales volando. Quien cae (por debajo de y = −10) queda eliminado y mira desde la grada. El último en pie gana la ronda y es el rey de la arena; a los pocos segundos empieza otra. Con Intro se escribe en el chat (y con 1 a 4, mensajes rápidos). El HUD (marcador, vida, anuncios, avisos y chat) está hecho con el creador de interfaces y los scripts lo rellenan con UI("HUD/...").

El dueño pide moverse. Mover es [Server(reliable = false)]: se envía 10 veces por segundo (y enseguida si cambia la dirección), así un paquete perdido se corrige solo.     local d = DireccionValida(direccion)

        return
    end
    self._entrada = d
    self._correr = correr
    self._ultimaEntrada = self._reloj
end

En FixedUpdate, solo en el servidor, el cuerpo acelera hacia esa velocidad (con poco control en el aire o justo después de recibir un empujón) y gira hacia donde anda.

Empujar. El dueño llama a self:Empujar(direccion) al pulsar E. El motor ya ha comprobado que es el dueño de este personaje; el servidor comprueba lo demás: que la ronda lo permite, que está vivo, la espera entre empujones (aunque un cliente modificado se salte la suya) y lanza un rayo grueso hacia delante:

Lua

11. Eventos#

Para comunicar scripts entre sí sin conocerse. Disponibles en cualquier script:

Función Qué hace
AddEventHandler(nombre, fn) Escucha un evento en esta máquina; devuelve un identificador
RemoveEventHandler(identificador) Deja de escuchar
TriggerEvent(nombre, ...) Lanza un evento en esta máquina
RegisterNetEvent(nombre, fn?) Acepta ese evento desde la red (y opcionalmente lo escucha)

Lua
-- Una tienda con eventos con nombre (en un [Global], para que exista en todas las maquinas)
--[Global]
local TiendaEventos = Script()

local PRECIOS = { pan = 2, agua = 1 }

function TiendaEventos:Awake()
    -- Servidor: compra pedida por un cliente
    RegisterNetEvent("tienda:comprar", function(articulo)
        local precio = PRECIOS[articulo]
        if type(articulo) ~= "string" or not precio then
            return -- nunca te fies del cliente
        end
        Log.Info(GetPlayerName(source), "compra", articulo)
        TriggerClientEvent("tienda:comprado", source, articulo, precio)
    end)
    -- Cliente: respuesta del servidor
    RegisterNetEvent("tienda:comprado", function(articulo, precio)
        Log.Info("Has comprado", articulo, "por", precio)
    end)
end

function TiendaEventos:Update(dt: number)
    if IsClient() and Input.WasKeyPressed("B") then
        TriggerServerEvent("tienda:comprar", "pan")
    end
end

return TiendaEventos

Límites: hasta 16 argumentos y 8 KB por evento, nombres de 1 a 128 caracteres, valores como los parámetros sin tipo (sección 9.4) pero con tablas anidadas de hasta 8 niveles y 256 elementos por tabla (un inventario con sus contenedores cabe tal cual, sin Json.Encode; desde la 0.9.13: las versiones anteriores solo aceptan 2 niveles, así que el que envía y el que recibe tienen que ser 0.9.13 o posteriores), y 30 eventos por segundo de cada cliente. De un cliente, el servidor aplica además los límites de la seguridad de la red (elementos por tabla, textos). Lo que pase de 8 KB, divídelo en varios eventos. Las funciones de red (9.4) y las tablas replicadas siguen con 2 niveles. Los eventos no registrados que llegan al servidor se descartan con un aviso. Un manejador añadido en una función de una instancia se quita solo al destruirse; uno añadido al cargar el fichero, al recargarlo.

12. SetTimeout, CreateThread y Wait#

  • SetTimeout(ms, fn): llama a fn dentro de ms milisegundos.
  • CreateThread(fn): ejecuta fn como una tarea que puede esperar con Wait(ms) sin parar el juego.
  • Wait(ms): solo dentro de CreateThread o SetTimeout (fuera es un error que lo explica).

Usan el reloj de la escena: en pausa no avanzan. Las tareas de una instancia terminan cuando se destruye, y las del fichero al recargarlo. Cada vez que una tarea se reanuda tiene el mismo límite de tiempo que cualquier llamada.

Lua
local Semaforo = Script()
Semaforo.color = Enum({ "Rojo", "Ambar", "Verde" }, "Rojo")

function Semaforo:Start()
    CreateThread(function()
        while true do
            self.color = "Verde"
            Wait(5000)
            self.color = "Ambar"
            Wait(1500)
            self.color = "Rojo"
            Wait(5000)
        end
    end)
    SetTimeout(500, function()
        Log.Info(self.name .. " funciona")
    end)
end

return Semaforo

Un while true sin Wait dentro de una tarea es un bucle infinito: el motor lo corta al pasar el tiempo máximo.

Desde la 0.9.2 está también Task (sobre el mismo planificador): Task.Wait(segundos), Task.Delay, Task.Spawn, Task.Defer, Task.Every y Task.Cancel, en segundos, con el tiempo de juego o el real y que se cancelan al desactivar su script o su entidad (nativas-juego.md).

Dentro de la clase#

luau-lsp no sabe qué es self dentro de function MiScript:Metodo() (para él es any, como cualquier parámetro sin tipo), así que por sí solo no completaría nada de self. La extensión lee el script y lo completa ella:

Lua
local Jugador = Script()
Jugador.velocidad = 5                 -- campo de la clase (Inspector)

function Jugador:Awake()
    self._controlador = self:GetComponent("CharacterController")
    self._camara = Scene.Find("Camara")
    self._giro = 0
end

function Jugador:IniciarLocal()
    self.                             -- velocidad (number), _controlador (CharacterController?), _camara (Entity?),
                                      -- _giro (number), entity, transform, name, enabled
    self:                             -- IniciarLocal, Awake, GetComponent, Destroy, IsLocalPlayer...
    self._controlador.                -- grounded, velocity, speed... (los de CharacterController)
    self._controlador:                -- Move, Jump, Face, Push
end

function Jugador:                     -- Start, Update(dt: number), FixedUpdate(dt: number), OnDestroy... (no Awake: ya está)
  • function MiScript: sugiere las funciones que llama el motor y que la clase aún no tiene, con sus parámetros y su ayuda: Awake, Start, Update(dt), FixedUpdate(dt), LateUpdate(dt), OnDestroy, OnCollisionEnter(choque: Collision), OnCollisionExit(choque), OnTriggerEnter(otra: Entity), OnTriggerExit(otra), OnNetworkSpawn, OnReplicated, OnAnimationEvent(nombre), OnAnimationFinished(clip), OnGUI, OnPoolGet, OnPoolRelease, OnInteract(jugador: number), OnBreak(nivel, punto), OnFullyDestroyed, OnSceneLoaded, OnPlayerLoaded(jugador), OnAllPlayersLoaded, OnValidate(motivo) y OnEditorChange(motivo), con los tipos que les pasa el motor. Al elegir una en una línea vacía se escribe también el cuerpo y su end. Si declaras una con otros tipos o con más parámetros, se subraya (ver Textos entre comillas y funciones del motor).
  • self.: los campos de la clase (MiScript.x = ...) y los que se asignan en cualquiera de sus funciones (self._x = ...), con el tipo que se deduce de lo asignado: números, textos, true/false, tablas ({ vida = 100 } → vida), GetComponent("X") → X?, Vec3.new(...) → Vec3, Scene.Find(...) → Entity?, Entity() → Entity?, lo que devuelve cualquier función de la API, x :: Tipo... Al lado, en qué función y línea se asigna. Y los de todo script: entity, transform, name, enabled.
  • self:: tus funciones y las de todo script (GetComponent, AddComponent, Destroy, IsServer, IsLocalPlayer, To...).
  • Lo que sale de self: self._controlador., self.entity:, self:GetComponent("Animator")., self._camara.transform. y una variable local que lo guarda (local c = self._controlador y luego c.) completan los miembros de su tipo con su ayuda.

Lo demás (Physics., Vec3., Scene.Find("x")., local c: CharacterController = ...) lo completa luau-lsp como siempre; la extensión no repite nada suyo. Un campo cuyo tipo no se puede deducir (por ejemplo, el resultado de una función tuya sin anotar lo que devuelve) sale como any: si quieres sus miembros, anota la función (function Jugador:BuscarObjetivo(): Entity?) o el valor con :: y un tipo de nova.d.luau (self._objetivo = self:BuscarObjetivo() :: Entity?). Se puede apagar con el ajuste nova.autocompletarClase.

  • El tipo de cada script: sus campos de la clase (Inventario.capacidad = 10 → number; Entity() → Entity?; Asset("Prefab") → Asset?; Enum({...}) → sus valores entre comillas; List(Objeto) → {Objeto} (datos.md); {} → una tabla; Vec3.new(...) → Vec3; GetComponent("X") → X?), los que se asignan en sus funciones (self._objetos = ... en Awake; los que empiezan por _ salen al final y su ayuda dice que son internos) y sus funciones con sus parámetros y lo que devuelven, tal y como los anotas (id: string). El comentario de encima de cada cosa es su ayuda al pasar el ratón. Un tipo local de tu script (type Objeto = {...}) no existe fuera de él: ese parámetro sale como any. Una función sin anotar lo que devuelve, devuelve any.
  • Lo que devuelve su tipo: entidad:GetScript("Inventario") y self:GetScript("Inventario") (también por su ruta: GetScript("ia/Enemigo")), entidad:AddScript("Inventario") y Global("Rondas") (los scripts --[Global]). Si dos scripts de carpetas distintas se llaman igual, solo vale la ruta. Dentro de function X: luau-lsp no sabe qué es self: lo que sale de self:GetScript("Inventario") lo completa la extensión, con lo mismo.
  • Los nombres entre comillas: GetComponent(", AddComponent(", HasComponent(", RemoveComponent(", Scene.FindWithComponent(" y Scene.FindAllWithComponent(" sugieren los componentes (los del motor y los de tu DLL de C++); GetScript(", AddScript(" y Global(", tus scripts, con su ruta, sus funciones y su comentario.
  • Los avisos (amarillos, con arreglo rápido en la bombilla o Ctrl+.): GetComponent("Inventario") con un script, GetScript("RigidBody") con un componente, un componente o un script que no existe (con el parecido: «¿querías decir RigidBody?»), Global("X") de un script que no es [Global] y una función o un campo que no tiene un script o un componente. Se apagan con el ajuste nova.avisos.nombresYMiembros. Con --!strict en el script, luau-lsp da además sus propios errores de tipos (no hace falta: los scripts del proyecto siguen en nonstrict, sin errores falsos).

GetComponent o GetScript: un componente es una pieza del motor o de tu DLL de C++ (RigidBody, CharacterController, Animator, AudioSource...) y se pide con GetComponent("RigidBody"). Un script es un fichero tuyo de scripts/ (Inventario.luau) y se pide con GetScript("Inventario"). GetComponent("Inventario") no lo encuentra y da el error «'Inventario' es un script: usa GetScript('Inventario')»; la extensión lo subraya antes de jugar y la bombilla lo cambia por GetScript.

Se rehacen solos. Al guardar, crear, renombrar o borrar un script, el editor de Nova (si está abierto con el proyecto) rehace nova.d.luau y nova.docs.json, y al abrir el proyecto también; solo si el proyecto ya los tiene (lo usa VS Code) y solo si algo ha cambiado (con 200 scripts, una décima de segundo, y se vuelve a leer solo el script que cambió). Si el editor no está abierto, la extensión se da cuenta de que a nova.d.luau le falta algo (un script, una función o un campo nuevo o quitado) y ejecuta ella NovaEditor.exe --generar-tipos-lua, sin ventana (ajuste nova.tiposDeScripts). Cuando nova.d.luau cambia, la extensión le dice a luau-lsp que lo vuelva a leer (luau-lsp solo lo lee al arrancar: tarda un segundo y los subrayados de luau-lsp parpadean); no hace falta reiniciar VS Code. Mientras tanto, lo nuevo de un script ya sale en lo que completa la extensión.

require: un módulo (local Util = require("./Util"), también "../comun/Util" o "@scripts/Util") lo lee luau-lsp con sus tipos: Util. completa sus funciones con sus parámetros.

14. Publicar: solo el bytecode#

Publicar juego (en el editor o con NovaEditor.exe --project <proyecto> --publish <carpeta>) compila cada script a data/scripts/<ruta>.luauc: el bytecode de Luau más la declaración de la clase (campos, funciones y atributos). No se copia ningún .luau. NovaGame.exe y NovaServer.exe cargan el bytecode sin compilar nada, y los errores siguen diciendo fichero y línea. Si un script no compila, la publicación falla con su error. Más en publicar-juego.md.

15. El sandbox y los límites#

Cada partida (cada escena que se juega) tiene su propia máquina virtual, que empieza limpia y se cierra al parar. En el editor, con el modo Anfitrión + clientes, cada ventana de juego tiene la suya.

  • Librerías: math, string, table, utf8, bit32, buffer, vector, coroutine y de debug solo info y traceback. No hay os, io, loadstring ni acceso a ficheros, procesos o red: el código de un compañero (edición en equipo) o de un mod no puede tocar el PC de nadie.
  • Ficheros: solo PlayerPrefs y SaveGame, siempre dentro de la carpeta de guardado del juego, con nombres que no pueden salir de ella y límites de tamaño (sección Datos guardados).
  • require solo carga ficheros de scripts/.
  • Globales: la API es de solo lectura. Cada fichero tiene sus propias globales (si creas una, solo existe en ese fichero); para compartir, usa módulos, Global("X") o eventos.
  • Memoria: 256 MB por máquina virtual. Al pasarse, el script que la pidió se detiene hasta la próxima partida.
  • Tiempo: cada llamada del motor a un script (un Update, una función de red, un manejador) tiene 2 segundos. Un bucle infinito se corta con el script tardó más de 2000 ms y se ha detenido (¿un bucle infinito?), con fichero y línea, también aunque esté dentro de un pcall. Ese script se detiene hasta la próxima partida.

Los límites se cambian en project.nova:

JSON
"lua": { "memoriaMB": 512, "tiempoMaximoMs": 5000, "recargar": true, "guardadoMaxKB": 1024, "guardadoMaxFicheros": 256 }

17. Consejos de rendimiento#

  • Guarda los componentes en Start: self._cuerpo = self:GetComponent("RigidBody") y úsalo en Update, en vez de buscarlo cada frame. Lo mismo con Scene.Find.
  • No crees tablas en Update si no hace falta ({...} reserva memoria y luego hay que recogerla). Los Vec3 no cuestan nada (son valores nativos de Luau); Vec2, Quat, Color y Mat4 sí reservan.
  • No escribas Update si no lo necesitas: una clase sin Update no recibe ninguna llamada. Para algo cada cierto tiempo, usa SetTimeout o una tarea con Wait.
  • Funciones y constantes local del fichero en lugar de campos o globales para lo que no tiene que salir en el Inspector.
  • Red: replica lo mínimo (un Range en los números los comprime), usa reliable = false para lo que se repite muchas veces por segundo y onChange en lugar de comparar cada frame. En una tabla replicada cambia claves sueltas (self.t[k] = v): asignar la tabla entera la vuelve a enviar completa.
  • Log cada frame llena la Consola y cuesta: úsalo para eventos, no para cada frame.
  • Busca por etiqueta o guarda la lista: Scene.FindAllByTag y FindAllWithComponent recorren la escena; en Update, mejor una lista que se rellena en Start.
  • SaveGame.Save escribe en el disco en el momento: guarda al terminar un nivel o cada cierto tiempo, no cada frame.
  • Referencia: 1.000 entidades con un Update que lee y escribe su Transform cuestan unos 1,3 ms por frame en release.
  • Deja el trabajo pesado al motor (nativas-juego.md): Spatial para buscar lo que hay cerca (x55 frente a recorrer una lista), Physics.RaycastBatch y LineOfSightBatch para muchos rayos, Pool en lugar de instanciar y destruir (x9), Tween para animar (x2), Scene.SetPositions para mover muchas entidades (x4) y Json (x4).
